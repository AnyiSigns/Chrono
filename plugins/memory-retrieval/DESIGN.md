## 检索流水线

```
1 查询构造   双入口：`args.query`（#17 `memory.search` / #27 工具路径）或 `bag.query`（recall 节点路径）；拼上 L1 goal / 摘要（2026-09-20 修订）
2 多查询     （开关）eff 12 生成 2-3 个子查询 / HyDE 假设文档
3 向量化     每查询 eff 20 embed（384 维归一）
4 索引检索   每查询 eff 21 search(vector, top_k_per_query)
5 归并       按 chunk 取跨查询最高分；chunk -> entry 回溯（调 #21 `read(entry_hash)` 取条目正文）
6 过滤       工作区范围 + 标签 / 来源
7 时间衰减   score × decay(at, now)，新条目优先
8 阈值       衰减后低于余弦阈值者丢弃（**先衰减再卡阈值**，否则衰减会把命中压到地板下却已过闸）
9 去重       同 entry 取最高分；**与在上下文内容去重**：调用方把「在上下文条目的 dedup_key 列表」放 `bag.dedup_set` 传入（规范化规则与 #13 同口径；仅覆盖历史 / L1 / L2）（2026-09-20 修订）
10 重排       MMR（多样性）；（开关）eff 12 语义重排（listwise）
11 预算截断  按分配预算定最终条数，写入 `bag.recall`（2026-09-20 定名）
```

## 逐项口径

| 项 | 口径 |
| --- | --- |
| **查询构造** | 默认 = 当前轮用户文本 + `#3` 本会话 L1 的 `goal`；不含历史全文（避免查询漂移）。**双入口**：`args.query`（#17 `memory.search` / #27 工具路径）与 `bag.query`（recall 节点路径）（2026-09-20 修订）。**argsSchema**（白名单子集）：`query` / `workspace` / `tags` / `limit`。 |
| **多查询** | 开关；eff `#12` 生成 2–3 个子查询（或 HyDE）。模型调用**不参与重放**（同 #12 口径）。**跨插件登记 #12**：多查询默认关、模型调用不参与重放（双侧互记，2026-09-20 修订）。 |
| **工作区范围（默认开，写死）** | 默认只召回 `meta.workspace == 当前工作区` **+ 全局条目**（`meta.workspace` 缺键）；跨工作区召回需**显式开关**。**默认必须是开启过滤**——多项目场景下关闭即串味（见下「多项目」）。 |
| **标签 / 来源过滤** | 按 `meta.tags` / `meta.source`（session / skill / manual）过滤，规则住 schema。 |
| **余弦阈值** | 低于阈值直接丢；阈值住 schema、可热改。 |
| **时间衰减** | `score × exp(-λ · age)`，`age` 由 bag 时间 − `meta.at` 算（服务不取时间）；λ 住 schema。 |
| **上下文去重** | 与 #13 组装去重**同口径**（规范化字符串）；调用方把「在上下文条目的 dedup_key 列表」放 `bag.dedup_set` 传入，本插件据此去重，只能对**已知来源**（历史 / L1 / L2）去重——最终组装视图由 #13 在召回之后形成，故 #13 仍会做最后一道去重；本插件为**尽力预去重**。**形状定义单一来源，两个实现各自持有、以对拍测试防漂移——已知重复，登记**（2026-09-20 修订）。 |
| **预算感知 top_k** | 召回预算 = `bag.recall_budget`（#33 按 `thresholds` 写入；#13 配额分配为最终截断兜底——两段式，2026-09-20 定案）；本插件据此定 `top_k` 与每查询条数，而非固定值。 |
| **语义重排** | MMR 之上可选 eff `#12` 做 listwise 重排（取相关度最高 + 去冗余）；关闭时只用 MMR（确定）。**跨插件登记 #12**：语义重排默认关、模型调用不参与重放（双侧互记，2026-09-20 修订）。 |
| **查询向量缓存** | 查询向量可缓存宿主侧 ③（`state/plugins/memory-retrieval/`），可重算、可 GC；不命中则重算。 |
| **空结果** | 返回空集，不报错、不阻塞组装。 |
| **索引构建中** | #21 冷索引首查回 `{status:'index_building', hits:[]}`：本插件**不静默当空集**，回结构化 `{status:'index_building', reason:'index_building', recall:[], count:0}` 供调用方稍后重试（2026-09-22 修订）。 |
| **分数归一** | 跨查询归并取最高分；重排分数仅用于排序，不回写世界。 |
| **检索分工** | agent 面「检索记忆」工具 = 本插件 `retrieval.search`；#21 `memory.search` 只是其内部低层向量检索，不直接暴露（避免同名职责重叠）。 |

## 与 #13 / #33 的关系

- **调用链**：`#33` 管道 eff 本插件 `search`（bag 带当前轮文本 / 工作区 / 预算）→ 流水线内调 #21 `search` 得 chunk 命中、再调 #21 `read(entry_hash)` 取条目正文 → 命中写入 `bag.recall`（2026-09-20 定名） → `#13` 组装时读取（#13 不 eff 本插件）。
- **模型项开关**：多查询 / 语义重排默认关（保确定可回放）；打开后该次召回的模型输出不参与重放（已知限制，同 #12）。**跨插件登记 #12**：多查询 / 语义重排默认关、模型调用不参与重放（双侧互记，2026-09-20 修订）。
- **在 #33 图里的位置**：本插件对应 #33 的 `recall` 种子契约（`touches_effects:true`），
  排在 `context.assemble` 之前——**召回先于组装**。**v1 种子图无 recall 节点**（`plugins/loop-policy/DESIGN.md` 契约表已声明、随图版本插入）；**v1 唯一活路径 = #27 记忆工具**（`memory.search` 绑定）；recall 节点插入后主链生效（2026-09-20 修订）。
  到位后由一次图变更（fork + 有限 diff）插入，走 #33 门禁。

## 多项目下的工作区过滤（本轮登记）

**场景**：用户让 agent 同时推进两个代码项目（如 Rust 后端 + 前端）。两项目是两个会话、两个工作区
（`#11` 的 `workspace_id` 创建即钉死）。

**风险**：若关闭工作区过滤，前端项目的召回会命中 Rust 项目的 L3 条目 ⇒ **串味**：
注入的"惯例 / 决策"来自另一个技术栈，模型据此产出错误结论，而这类错误**很难被发现**
（它看起来像是合理的上下文，不像是 bug）。

**口径**：

- **默认过滤开启**（当前工作区 + 全局条目），这是**默认值不是建议值**；
- 跨工作区召回只能由**显式开关**打开，且该开关住 `schema/retrieval.json`（世界数据、可回放、可审计）；
- 全局条目（`meta.workspace` 缺键）**仍然召回**——跨项目通用的约定（如"提交信息用中文"）应写成全局条目，
  这是跨项目共享知识的**正确通道**，而不是关闭过滤。

**与 #3 L2 的对照**：`#3` 的 L2 工作区累积是**每工作区一条**，天然分开、无需额外过滤。
L3（#21）是扁平条目集合、无工作区分区，所以过滤责任落在本插件的召回侧。两者形状不同、处置不同，不要类推。
