## 三个方法

| 方法 | 做什么 | 写哪 | 触发 |
| --- | --- | --- | --- |
| `consolidate` | 收 bag 的 `11` 会话 + `3` L1/L2 片段（周期路径 = periodic reads 注入、agent 路径 = 入口 term 装配，D8）→ #20 `chunk + embed` → 按 entry 聚合去重（余弦阈值）→ 需要摘要时 eff `19`；**L1 合并进 L2**（L1 保留至 TTL 过期、sweep 清；L2 合并 `sources[]` 追加来源会话 id、最新在前）；**L2 高价值项固化进 L3**（agent 判定 + 定期兜底） | 计划【batch：写 `3` L2 + 写 `21` L3】 | **宿主周期触发**（周期住 schema，D6；2026-09-20 与 draft §1.7/§1.12/loop-policy 三方统一：宿主周期唯一自动触发）；agent 记忆工具 |
| `sweep` | 收 bag 的 `3` / `21` 片段（同上两路注入）→ 按策略选待删：**L1 过期（24h）**、L2 / L3 超容量、低权重（按条目 `weight`，跳过 `pinned`） | 计划【batch：写 `3`（删 L1/L2 项）+ 写 `21`（**删除 L3 = #21 body 加 `deleted` 条目**）】 | **宿主周期触发**（周期住 schema，D6；2026-09-20 与 draft §1.7/§1.12/loop-policy 三方统一：宿主周期唯一自动触发） |
| `candidates` | 只读：回「过期 / 低价值」候选列表，**不删** | 无（返回值） | **经 #27 具名工具 `memory.candidates` 暴露**（绑定见 `plugins/tools/DESIGN.md`）；agent 同一回合顺带调用（§1.12 统一口径，2026-09-20 修订） |
| `view` | 只读：回 L1（`#3`）/ L2（`#3`）/ L3（`#21` 元数据）三档，含 `at` / 剩余 TTL / tags / source（**L3 视图字段与 #21 条目字段一致：`at`/tags/source/`weight`/`pinned`；#22 命中数据同形**，2026-09-20 修订） | 无（返回值） | #17 S12 记忆 tab |
| `edit` | UI / agent 的改 / 删 / 置顶：收入口 term 传入的槽体与 `3` / `21` 片段（D8）→ 出计划（**删除 = #21 body 加 `deleted` 条目；置顶 = body.pinned；文本编辑 = put 新条目 def + 新 body**，2026-09-20 修订） | 计划【batch：写 `3` L1/L2 + 写 `21` L3】 | #17 S12 记忆 tab / agent 记忆工具 |

- **触发归宿主周期（D6），不归 #33 回合尾**：`#33` 现为**服务自驱解释器、无回合尾维护节点**；`consolidate` / `sweep` 的周期住 `schema/memory-maintenance.json`，由**宿主按周期构造 run** 触发（D6）——本插件不自触发、不依赖 #33 节点。删除无节点背书的「#33 回合尾」口径。（2026-09-20 与 draft §1.7/§1.12/loop-policy 三方统一：宿主周期唯一自动触发。）
- **`view` / `edit` 的投影读由调用方入口 term 完成（D8）**：本插件是 execute-only，**服务自身不做 `+` 投影读**；#17 S12 的入口 term 读 #3 / #21 投影后经 args/bag 传入，本插件只据传入数据出视图 / 计划。
- **`view` / `edit` 是记忆 UI（#17 S12）的读写面**：写一律经计划、可回放；**置顶 = `body.pinned`（淘汰时跳过；不改 `at`）**（2026-09-20 修订）。
- **冲突消解（机械）**：L2 合并 / L3 固化的**同键多版本取 `at` 最新**（同 `at` 取来源可信度高者：历史 > L1 > L2 > L3）；**语义矛盾机械不判**，交 agent 按 #33 准则在压缩 / 固化时修正（去重只解决「相同」，不解决「矛盾」）。

- **时间由 bag 传入**（服务不取时间，保可回放）；`expires_at` 比对在 `sweep` 内完成。
- **sweep 增量**：以「上次 sweep 水位」（住宿主 ③，可重算）为游标，只扫描水位之后新增 / 变更的条目；L1 到期集合按 `expires_at` 索引（③）取，不线性扫全层，避免随库增长的全量扫描。**periodic.reads 全量注入为接受代价**（水位只省本插件扫描）；**H1 全量闭包与 refCap 兜底**（2026-09-20 修订）。
- **水位只在无待落账删除时推进**：有删除计划时服务不写本地水位，只回 `cursor_next`，由调用方在计划落账后持久化；保证「计划未落账时同输入重跑仍出同一删除集」。显式 `args.cursor` 优先且不改本地水位（调用方完全控制游标）。（2026-09-22 修订）
- **agent 顺带清理（已定，2026-09-20 口径统一）**：记忆工具目录暴露**具名工具 `memory.candidates`**（绑本插件 `candidates` 方法，见 `plugins/tools/DESIGN.md` 绑定表）；agent 在查看 / 保存记忆的**同一回合**顺带调用它获取候选、当场决定删 / 合并（原「返回结果一并附 candidates」的复合工具口径作废——§1.12 已统一）；真正的删除仍由 `sweep` 出计划（可回放）。
- **两条 L3 来源**（已定，与 #21 `meta.source` 枚举 `session|skill|manual|consolidate` 对齐）：① agent 经记忆工具**显式保存**（`21` 写计划，`meta.source = "manual"`）；② `consolidate` 定期把 L2 高价值项**固化**进 L3（去重，`meta.source = "consolidate"`）。
- **L2 `sources[]` 维护与 L1 处置（2026-09-20 补）**：L1 合并进 L2 后 L1 保留至 TTL 过期（sweep 清）；L2 合并 `sources[]` 追加来源会话 id（最新在前）；与 #19 `extract` 的去重分工：extract 只写新条目、去重归本插件。
- **不永久存**：L1 硬 TTL 24h；L2 / L3 容量上限 + agent 主动清理双保险。

> **为什么能合并**：`forget` 与 `consolidate` 的差异只是**策略参数**（写入 vs 删除），而策略本来就该住数据、由宿主按周期触发（D6）；拆两个插件会各自实现一遍「读 3/21 → 出计划」。
