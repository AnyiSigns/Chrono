## 原生 tokenizer 子组件（TS 主体 + Rust 热点，2026-09-19 定）

- **为什么只下推 token 计数**：它是本插件唯一的纯 CPU 热点（每轮对候选消息反复计数），而**组装策略（去重 / 配额 / 裁剪 / 前缀排序 / 格式化）是迭代最频繁的部分**，必须留 TS 才能快速改。全服务 Rust 会把最常改的算法锁进编译期，故只把热点下推。
- **形态**：`native/tokenizer/`（Rust crate + `Cargo.toml`）编译成原生扩展（`*.node`，napi-rs 一类），TS 服务**进程内**加载调用——不是第二个进程、不走 `port.call`、无 hop。
- **物化（H15）**：源码 + `package.json` + `Cargo.toml` 入世；`node_modules` / `target/` / `*.node` 走宿主侧 ③；宿主物化时 `npm ci` + 构建原生扩展。
- **单一实现（写死）**：tokenizer 只有 Rust 一份；**native 缺失 / 构建失败 ⇒ H15 `deps_failed` → #13 隔离（与 H15 失败码对齐，2026-09-20 修订），不回落 JS 实现**——两份 tokenizer 必然漂移，会让「预算 / 75% 阈值 / 同输入同输出」全部失真。
- **可逆**：能力类 / 方法 / `pins` 与实现无关；若将来热点消失，去掉 `native/` 即可（换实现不改调用方）。

## 调配流水线（2026-09-20 修订）

```
0 候选汇集   本轮用户消息(#1 槽，含附件 text / 资产引用) / 系统提示(bag) / 工具 schema(bag) / L2 / 上一会话 L1 / 本会话 L1 / 技能 / L3 召回(bag) / 历史 / 风格
0b TTL 过滤  L1 注入前校验 expires_at <= 帧 env.now（H16）⇒ 过期 L1 不注入（见下「读时 TTL 过滤」）
1 结构化     每片段 -> 规范消息；工具调用与结果成对、标记 atomic
2 去重       规范化后完全一致 -> 只留位置最新一条；跨来源也去重（记忆 vs 历史 -> 丢记忆副本）
3 预算建模   总预算 = context_window - max_output - 余量；逐片段 token 计数
4 配额分配   按优先级给各类配额；未用额度下滚给历史
5 裁剪       历史新 -> 旧；保持 atomic 组完整；仍超 -> 触发压缩协调
6 来源调度   决定技能 / 召回 / 历史窗口的纳入量（对 bag 里已有的召回集按配额截断；召回调用与 top_k 由上层管道按预算传 #22）
7 冲突消解   同键多版本取最新；语义矛盾交 agent（准则）
8 排序       稳定前缀置前、易变置尾（前缀缓存）
9 格式化     按模型方言编 content parts（含多模态）
10 组装清单  产 `context.assembled` 事件（不进世界）
11 触发协调  组装后 used >= budget × 75% -> 追加一条压缩提示 system 消息
12 交错引导  本轮含工具结果 -> 追加一条「说意图、禁标识符」system 引导（见下）
```

- **工具循环边界**：一次 run 内**每次模型调用前**都走一遍调配（工具结果回灌后重组装）；配额 / 去重 / 清单按当轮 bag 重算，不在多轮间缓存拼接结果。
- **系统提示 / 工具 schema 都来自 bag**：由上层（#33 `context.assemble` 节点）写入 `bag.system_prompt` / `bag.tools`；本插件**不 pin #27 / #33、不读它们的投影**（否则就认识了工具集与图）。系统提示词本体住 #33 `prompts.system`（行为准则 + 产品事实、只谈意图、禁工具标识符）。

## 规范消息模型

```jsonc
{ "role": "system|user|assistant|tool",
  "parts": [ { "type": "text", "text": "…" },
             { "type": "image", "asset": { "sha256": "…", "mime": "image/png" } },
             { "type": "audio", "asset": { … } } ],
  "source": "prompt|tools|l2|l1|skill|recall|history|style",
  "priority": 0,
  "tokens": 0,
  "atomic": false,                    // 工具调用 + 结果 = true，不可拆
  "dedup_key": "<role>|<规范化 parts 文本>" }
```

- `dedup_key` 是**规范化字符串**（去首尾空白、统一换行、压缩连续空白），**不是哈希**（插件不算世界哈希）。
- `atomic` 组：一个 `assistant.tool_calls` 与其后的 `tool` 结果同生共死；裁剪以组为单位。

## 去重（已定：规范化后完全一致、留最新）

- 同一 `dedup_key` 多次出现 → **只保留位置最新的一条**，其余丢弃。
- **跨来源**：若 L3 召回 / 记忆摘要与历史消息规范化后一致 → **丢记忆副本**（历史是事实源，记忆只是提示）。
- 语义近似（改写版）**不在此去重**：交给 L2/L3 的向量去重（#20 / #23）。
- 去重**本身**不改变保留项的相对次序；**最终顺序由第 8 步按来源分段决定**（稳定前缀置前），两者不矛盾。
- **规范化缓存**：`dedup_key` 的规范化结果按消息 def 哈希缓存（同 def 只规范化一次），避免每轮对全量历史重复规范化。
- **只作用于本轮发给模型的视图**：去重 / 裁剪**不改 #11 的展示历史**（见下「展示历史与组装视图分离」）。

## 预算与配额

- **总预算** = `context_window - max_output - 余量`（余量默认 5%，住 policy）。`context_window` / `max_output` 取自 `#2 config` 的模型档案；缺档案 → 保守默认 + 组装清单标 `profile_missing`。
- **token 计数**：v1 估算器（确定，规格写死：ASCII 词 ≈ 1 token、CJK 每码点 ≈ 1 token、其余按码点分桶；同实现同输入同值）；按模型的精确 tokenizer 后续可换（**远期可选 / 非当前待办**：可拆小插件 `token-counter`，接口 `count(text, model)`；当前已收口在 #13）。
  - **计数缓存（关键优化）**：消息是内容寻址 def ⇒ **按 def 哈希缓存 `tokens`**，并维护各来源的**前缀和**；工具循环里每次重组装只对新增片段计数、对未变前缀直接取缓存，避免每轮全量重算 O(历史长度)。
- **优先级**（高 -> 低，配额不足时按此降级）：

| 优先级 | 类 | 处理 |
| --- | --- | --- |
| P0 | 系统提示 + 工具 schema | 保底，不裁；超预算即报 `budget_impossible` |
| P1 | L2 / L1 记忆摘要 | 保底一份；**若 P0+P1 已超预算** → `budget_impossible`（先于裁剪，见下） |
| P2 | 技能片段 | 按配额截断片段数 |
| P3 | L3 召回 | 按分数截断条数 |
| P4 | 历史 | 新 -> 旧，保持 atomic 组 |
| P5 | 风格 | 超预算首先丢 |

- **未用额度下滚**：高优先级用不完的额度给下一级（尤其给历史）。
- **P0+P1 出口（写死）**：`budget_impossible` 判据 = `P0 + P1` 的 token 和 > `budget`（P1 中无 TTL 的 L2 可能持续增长）。此时不静默截断：返回结构化 `budget_impossible`，由上层决定强压（调 #19 `compact`）或失败；L2 软上限与容量淘汰归 #23 `sweep`。**消费方（2026-09-20 修订）**：#14 `wiring.on_budget:'fail'`（入口 term 据结构化错误以 extern 失败收口）；#33 按 `thresholds` 分支。
- **来源调度**：纳入量由配额决定；对 bag 里已有的召回集做截断（#22 的 `top_k` 由上层管道按预算传，见 #22「预算感知」）。

## 冲突消解

- **机械**：同键（如记忆条目的 `subject` / 规范化 `dedup_key` 前缀）多版本 → 取 `at` 最新；`at` 相同取来源可信度高者（历史 > L1 > L2 > L3）。
- **语义矛盾**（不同表述、事实相反）：机械不判，交 **agent 按 #33 准则** 处理（可在压缩 / 固化时修正）；本插件只保证不把明显同键旧版并列注入。

## 前缀缓存排序

- **稳定前缀**（顺序固定、内容不逐轮变）：`系统提示 -> 工具 schema`；其后才是逐轮变的 `L2 -> L1 -> 技能 -> 召回 -> 历史 -> 风格`。
- 目的：命中 provider 的 prompt 前缀缓存（缓存键 = 前缀逐字节一致）。**L2 不放前缀**：它随记忆更新而变化，放前缀会反复击穿缓存（原「系统提示 -> 工具 schema -> L2」口径修正）。
- 缓存标记（provider 特有）由 #12 按方言加，本插件只保证顺序。

## 格式化（按方言，含多模态）

- vendor `sdk` / `quirks` **由 `bag.config` 携带**（调用方入口 term 装配，§1.14）；自定义厂商的 `protocol` 同路；据此把 `parts` 编成该方言的 content parts：`openai-chat` / `openai-responses` / `anthropic-messages` 各自的 text / image / audio 形态。（2026-09-20 修订）
- **多模态内容装配**（原候选缺口）归此处：**可解析附件 `text` 内联进组装；二进制附件只传资产引用、不进组装**（无需取字节 / 无需 pin `host`；2026-09-20 修订）；按模型 `modalities.input` 编 content parts，模型不支持该模态 → 降级为文本引用 + 组装清单标 `modality_dropped`。
- 方言映射表可随 `vendor-*` 换代；本插件不硬编码厂商怪癖。

## 组装清单（插件事件，经宿主透传，不进世界）（2026-09-20 修订）

- 每次组装产一条 `context.assembled` 事件：`{ run, thread, model, budget, used, sources:{prompt,tools,l2,l1,skill,recall,history,style:{tokens,count}}, deduped, trimmed:[{source,reason}], recall:[{entry,score}], flags:[] }`；**`run` / `thread` 自协议帧 `env`（H16）读取**。（2026-09-20 修订）
- **`run` / `thread` 必填**（2026-09-19 补）：UI（#40 上下文用量行 / #18 调试）按 `thread` 过滤取当前线程最近一次——真并发下不按线程过滤会把别的线程的用量串进当前视图。
- 经宿主 `event` 透传（**不落账、不推进、不参与哈希**）；UI / 日志消费，供调试「为什么这轮上下文长这样」。

## 75% 触发协调（已定：不设专门图节点）

- 组装完成后若 `used >= budget × 75%`（`budget = context_window - max_output - 余量`，**不是裸 `context_window`**）→ **追加一条 system 消息提示 agent 压缩**（文案住 policy）；不删消息、不动 #33 图 / 策略数据。
- agent 经记忆工具调 #19 `compact` / `extract` 落计划，`covered_upto` 前进后，下次组装才排除旧轮次；**压缩只写 `#3`、不删 #11 消息**。
- 若裁剪后仍 > 100% → 不静默截断：返回结构化 `budget_exceeded`。**消费方（2026-09-20 修订）**：#14 `wiring.on_budget:'fail'`（入口 term 据结构化错误以 extern 失败收口）；#33 按 `thresholds` 分支。

## 交错引导语（工具结果回灌后注入，本轮定）

- **触发**：本轮组装时若上下文里含**工具结果**（上一轮有 `tool_calls` 且已回灌）→ 在消息列尾部追加**一条 system 引导**（只追加一条，幂等）。
- **文案**（住 `schema/policy.json`，可热改）：约「用**自然语言**描述下一步要做什么；**不要引用工具标识符**（工具名 / 插件名 / 能力类名 / 端口名），不要复述参数」。
- **修什么（放大器）**：回合内「推理 ↔ 工具」交错时，模型爱在可见文本里写 `read(...)` / `tool-fs.read(...)` 这类标识符；这些文本被落进 `#11` 展示历史后，下一轮组装又把它当上下文 ⇒ **越写越多**（正反馈），并污染展示层。引导语把「说意图、不说标识符」钉在工具结果之后，正好卡在交错点。
- **与 75% 压缩提示同一机制**：都是组装期追加的 system 消息，**不进世界、只影响本次模型输入**；两条可同时出现（压缩提示在前、引导语在后）。
- **文案口径与系统提示词一致**：**只谈意图、禁标识符**。系统提示词本体住 #33 `prompts.system`（每回合稳定前缀），本节的引导语是**每轮短引导**（住本插件 policy、随组装追加）。

## 展示历史与组装视图分离（红线）

- **展示真源 = #11 会话**：全量、追加、独立留存；对话面板（#18）按 `chat.history` 渲染，**与组装无关**。
- **本插件的输出只是发给模型的派生视图**：去重 / 配额 / 裁剪 / 冲突消解 / 压缩边界**全部只影响这一次模型调用的输入**，**永不回写 #11、永不删消息**。
- 换模型 / 换压缩策略 / 回滚 `covered_upto`，展示历史都不变；用户永远看得到完整对话。

## 与 #3 的关系

- #3 的读取**由调用方入口 term 完成**（#14 / #33 装配 `bag.memories`，§1.14；本插件服务不读投影）；#23 维护所需的 #3 片段同路由（periodic reads / 入口 term）——两处读取互不依赖；写回一律由 19 / 23 的计划落账。
- L3 召回不经本插件发 eff：上层（#33 管道）调 #22 后写入 **`bag.recall`**（记忆引用字段，双侧定名），本插件只读 bag。（2026-09-20 修订）

## 线程（按 `kind` 调组装输入，2026-09-19）

- **`bag.thread_kind`** 由 #33 的 `context.assemble` 节点写；本插件据此调输入（相关 bag 字段：`bag.thread_kind` / `bag.parent_summaries` / `bag.task_prompt` / `bag.inbox_unread`）：
  - `main`：全切片（现口径不变）。
  - `subagent`：**去掉「上一会话 L1」**，加 `bag.parent_summaries`（父会话 L1 最新 N 条）+ `bag.task_prompt`（父 agent 任务提示词）+ `bag.inbox_unread`（本线程 inbox 未读消息：父 instruction / decision）；**不继承父会话消息历史**。
  - `group`：用**群聊 transcript**（带发言者名）替换「历史」切片，并加**本轮发言者人格 + 圆桌议题**；参与者各自独立组装。
  - `workflow`：不组装消息历史（图 `shared` / slots 归 #33）。
- **子代理 ≠ 协作者**：子代理隔离（父摘要 + 任务提示词）；协作者共享群聊 transcript。完整口径见 `docs/plans/threads-design.md` §三（子代理五条 + 分野表）。
