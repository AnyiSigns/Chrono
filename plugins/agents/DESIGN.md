| 职责 | 智能体数据身份：**模板 / 实例（人格）/ 通道** 的索引（各自成 def + **链式 tail**） |

| 机制 | body = `{ templates:{tail,count}, instances:{tail,count}, channels:{tail,count} }`（tail 为 `{"def":hash}` 标记）；**条目各自成 def**（内容寻址、带 `prev` 成链），**不列全部哈希**（避免 O(N²) 重写，同 #11）；写一次 = `put(条目) + put(新 body) + add_gen`；条目 body 由**宿主投影引用闭包解析**放进 `ids.agents.refs` |
| 边界 | 不做：特权（框架无特权插件）/ 消息传输实现（**通道 = 纯世界数据，写入后下一回合经投影读到；不经宿主 `event` 投递给插件**）/ 实例自带执行权（权限档在 #2 / #26）/ 调度（归宿主 `caps` / `limits`）/ **能力边界与端口声明**（归 #33 契约） |

## 实例 = 人格（版本提升，2026-09-19）

**口径（与 #33 分工，写死）**：`#33` 的 Scope 统一了「节点 = agent = 作用域」，一个 Scope 由四样组成——
**契约**（能力边界）住 #33 `contracts`、**实现**（atomic / composite）住 #33 `nodes`、
**人格**（是谁）住**本身份 instance 条目**、**边界**由契约声明 + #33 解释器强制。

```jsonc
// instance 条目（人格）
{ "id": "ag-…", "name": "Rust 评审员",
  "system_prompt": { "def": "<提示词 def 哈希>" },   // pin，不内联
  "model":         { "def": "<模型绑定 def 哈希>" },  // 可选；缺省由 #33 / #34 定
  "decoding":      { "def": "<解码参数 def 哈希>" },  // 可选
  "prefer_tools":  ["…"],                            // 可选：偏好工具名（提示层，非权限）；消费方 = #33 `context.assemble`（#14 入口 term 读 #35 投影随 bag 传入，D8）
  "scope": { "kind": "global" | "workspace" | "session", "workspace_id": "w1", "session_id": "c1" },
  "prev": { "def": "<上一条实例哈希>" } | null }
```

**字段消费（D8 补，避免静默死字段）**：

- `prefer_tools`：消费方 = #33 `context.assemble`（偏好工具排序 / 提示层；#14 入口 term 读 #35 投影后随 bag 传入，服务不读投影）。
- `channels`：消费方 = #33 `context.assemble`（跨回合留言板注入；同经 #14 入口 term 读投影随 bag 传入）。
- `templates`：**v1 未接线**（预留：供 #17 S13 新建子代理 / #45 提案预填，v1 无消费方；不作静默死字段）。

**为什么人格与 `NodeDecl` 分居两处（不是冗余）**：人格是"**是谁**"（人可见、可命名、UI 可选、跨图复用）；
`#33` 的 Scope 是"**在哪跑、能干什么**"（端口、权限、重试策略）。合成一处必然出现两个坏结果之一——
改一句提示词就换 `H(Scope)` ⇒ 池里多出"一个新节点" ⇒ **提示词 A/B 与漂移归因当场做不了**；
或者改接线等于改人格 ⇒ UI 里看不懂。

**关键安全结论：加子代理不会扩权。** 节点可调端口由 **#33 契约的 `effects`** 声明（契约没声明的端口运行时不注入），
本身份实例只提供 prompt / model / decoding。⇒ 用户加一个"运维子代理"最多换提示词和模型，**拿不到 shell 权限**；
要给新权限必须改 #33 契约（append-only、走门禁、且受"审批段不可绕过"约束）。**这条是结构性的，不靠纪律。**

**`scope` 字段（新增，专门化的机械边界）**：

| `scope.kind` | 可见范围 | 典型 |
| --- | --- | --- |
| `global` | 所有工作区 | 通用子代理 |
| `workspace` | 仅 `workspace_id` 匹配 | 该项目专属人格（"本仓库的 Rust 评审员"） |
| `session` | 仅该会话 | 一次性实验性人格 |

- **强制点在 #33 的实例选择，不在本身份**：#33 按 `contract_id` 选实例时候选集先按 `scope` 过滤，
  `workspace` 实例在其它工作区**不进候选集**。本身份只**存**这个字段，不做判定（纯数据身份）。
- ⇒ **专门化落实例层、不落结构层**：#33 的图保持通用（样本量不被除），人格按工作区专属（材料不串味）。

**加一个子代理不需要改图**：#33 池中始终保留 `subagent` 契约（其池不变量），
故"写一条本身份人格 + 一条 #33 `NodeDecl`"即可被既有图调用，**不动顶层图**。
代价明写：`bindings.agent` 由上游 slot 解析 ⇒ **跑了哪个人格看图看不出来**，只能看轨迹
⇒ #33 必须在 `trace` 记 `chosen_agent` **轨迹字段**（与 `chosen_instance` 同理，不记就分不开"换了人格"和"换了模型"）。

**子代理没有私有持久记忆**：#33 的 Scope 不持有跨调用状态（L0/L1 一律），
要记就显式落 **#21**（带 tag + scope），走同一条记忆通道。本身份不存运行态。

## 协作 = 共享大脑、私有工作台（无新机制）

多个子代理 Scope 读**同一份** #33 `shared`（任务 spec / 工作区快照 / 讨论摘要），各写**自己**的 slot，
末端由聚合契约（`vote` / `judge` / `merge`）收敛。

- **辩论 / 评审 / 多方案择一必须显式建模为扇出 + 聚合**（`cardinality:'n'` 的 `all` 端口，**N 路全计费**），
  不能指望 `any` 顶替（`any` = 恰一条触发）。
- **v1 顺序执行**（单 pending + 单写者锁）：扇出是依次跑完 N 路，不是并发。
- **多层子代理靠 composite 嵌套表达**（#33），不靠 L2 递归委派（L2 不开）。

## 通道 = 跨回合留言板，不是实时总线（定位明确）

两条既定口径卡死了通道的能力上限：

1. 宿主的 `event` **只透传给入站面已连接的客户端**，**不投递给其它插件**（`host.md` §世代）；
2. 插件间**不得直连**（`plugins.md` §三 红线 3）。

⇒ 通道**不可能**是 agent 间的实时消息总线。它能做的是：**写进世界 → 下一回合的 Scope 经投影读到**。
跨会话 / 跨回合的异步协作只能是这个形状；"实时对话式协作"必须先解决并行与投递，**属后置档**。

**通道没有隔离（明写，别误以为有）**：通道是世界数据，任何能读本身份投影的 term 都能读全部通道。
要分隔离只能在 term 判定里做，或拆身份。v1 不做。

## 跨插件登记

- **#33 loop-policy**（提出方）：要求本身份升一代 —— instance 补人格字段（`system_prompt` / `model` / `decoding` 的 pin）
  与 `scope` 字段；`#33` 的 Scope 以 `bindings.agent` pin 本身份条目；`chosen_agent` **轨迹字段**由 #33 记录（非事件）。
- **#45 orchestration-admin**：加子代理 / 协作者提案 = 本身份一条 instance 人格条目 + `#33` 一条 Scope；采纳 = **跨身份批量写**
  （`#33` 图世代 + 本身份 instance 世代），由采纳者（#33）在图外一次性提交，审批闸对整批生效（口径见 #45「跨身份采纳」）。本插件只存数据、不执行写。
- **#17 ui-settings**：S13 编排 tab 渲染 Scope 名录（含人格名与 `scope`），**只读**；人格的增删改经 #33 提案或客户端直写。
- **#21 memory-store**：子代理要记东西落 #21（带 tag + scope），本身份不存运行态。
- **宿主能力（H1 已落地）**：投影引用闭包解析（`{"def":hash}` → `ids.<id>.refs`）；与 #11 / #21 共用同一条。
- **线程设计（2026-09-19）**：**子代理 = 子线程**（隔离上下文 + **双向通信**：父可发 `instruction`、可 `status` / `resume` / `terminate`，子可发 `decision_request` / `report`；默认只回最终 `report`，实测口径见 `docs/plans/threads-design.md` §三）；**协作者 = 圆桌群聊**（共享 transcript、开放讨论，与子代理分野写死）。子代理线程上下文 = 人格 `system_prompt` + 父线程几条摘要 + 父 agent 任务提示词 + **inbox 未读消息**，**不含父会话历史**；本插件实例提供人格与 `scope`，仍不存运行态。
- **`channels` 与 `inbox` 分工**：`channels`（本插件）= 跨回合留言板（写进世界、下一回合读，通用）；**`inbox` 住 #11 会话 body**（线程收件箱，父子消息专用、带 `kind` 与未读游标）。两者都是"落世界 + 下轮读"，不重复：留言板是广播式，收件箱是点对点 + 有 `kind`。
