# 内核设计与架构

> 本文只回答**是什么、为什么、边界在哪**。不含伪代码、类型定义、形状表、错误码、行数预算与阶段计划——那些住在 `kernel.md`（可编码规格）。
>
> **两份文档的分工（唯一裁决）**：本文讲 What / Why；`kernel.md` 讲 How / 怎么判对错。同一条约定两说即为漂移，发现时当场定一侧：可观察契约、边界表、验收判据一侧以规格为准（它可测）；"内核不认识什么、不做什么"一侧以本文为准（它是规格的判据来源）。
>
> 文中 `§n` 指 `kernel.md` 的节号。**不变量的权威编号清单在 §14，本文不复制**，只给分组与意图（§11）。

## 1. 内核是什么

一个**内容寻址的世界**加一条**只追加的日志**，包在一个**纯函数**里。

`run(input) → KernelOutput`。没有别的入口，没有别的出口。

它只兑现三个承诺：

| 承诺 | 靠什么兑现 |
|---|---|
| **改坏了能退** | 日志只追加、无删除；回滚是一次追加，不是一次抹除 |
| **非法进不来** | 唯一写口前的机械校验：形态 → 引用 → 位置 → 不变量，四步任一不过则整次调用作废 |
| **历史改不掉** | 链式哈希覆盖每条记录的位置与内容摘要；改任何一处，其后全断 |

它**明确不兑现**一个：不判断"这次改动是不是更好"。

> **判决 ≠ 正当性。** 内核的 `ok` 只回答"这次写入是不是合法的记账动作"。"该不该做"由上层回答，而上层的判据本身只能以**数据**身份进世界——判据、阈值、评分规则爱怎么叫怎么叫，永不以代码身份进内核。这条单向性是整个分层的地基：内核不知道什么叫好，所以它可以诚实地记住一切。

由此得到内核的四词自我（§3）：**身份 · 世代 · 依附 · 判决**。除这四个词和四条机制，内核不认识任何东西。

## 2. 分层与位置

| 层 | 职责 | 不认识 |
|---|---|---|
| **内核** | 一致性：改了什么、能不能退、非法进不来 | 语义、性能策略、审核、存储、调度 |
| **宿主** | 存储、效果执行、装载执行件、审计策略、上下文投影 | 判定逻辑（那是数据） |
| **执行件（插件）** | 干活。独立进程，按协议挂载 | 世界状态的所有权 |
| **上层（产品 / 审核 / 研究）** | 用内核给的一致性做自己的判定 | — |

三条单向：

1. **判定单向**：上层的判据只能作为数据进世界，不能作为代码进内核。
2. **依赖单向**：`run` 是唯一编排者；`machine` 与 `journal`/`commit` 之间**没有任何边**——求值不认识写入，写入不认识求值，两边都只认识值模型。这条 DAG 是承诺不是习惯（§14-4）。
3. **信任单向**：内核不信任宿主，也不质问它。它把宿主能碰的东西全部收敛为"输入里的数据 + 落盘的字节"，剩下的一律自己重算。

**多宿主不是一个世界被多个宿主共享**——每个宿主各有一个内核实例，各自一条链，零共享状态（纯函数使这免费）。跨世界的内容相同性由内容哈希保证，不是由同步保证。

**执行件是进程，不是库**：内核永不加载任何东西。宿主读声明 → spawn → 按协议通信。二进制本体不住在世界里，只有"声明 + 哈希 + 平台"进 `defs`。

**内核不要求任何分类字段**：`Identity` 只有 `id / schema / gens / active / born`，没有 `class`，也没有标签位。想区分"这是插件、那是判据、那只是数据"，就写一份声明它自己的 `schema`——那是数据，不是特权。

### 2.1 一件事该谁做：四向路由判据

"保持内核轻量"是对的方向，但它不是"能推就推给插件"。真正的判据只有一条：

> **少了它，坏数据就能进世界** → 内核做。（没有第二条路：任何外包都会让"非法进不来"变成靠自觉）
> **少了它，某个宿主自己算错自己的账** → 宿主做。（保护对象是它自己的读，不是世界的合法性）
> **需要特定语言生态、进程隔离，或可丢弃可重算** → 执行件做。（前提：`协议往返 ≪ 单次任务成本`）
> **是判定标准本身** → 都不是，写成**数据**进世界（M2 存在的唯一理由）。

三条推论，都是反直觉的：

1. **执行件不能承担校验**。它是宿主可换、可不在、可崩的东西。把"基础对不对""链断没断"交给插件 = 破 M4。**所以"闭包遍历""投影压缩"可以是执行件，"引用存在性"永远不行。**
2. **内核轻的是名词数，不是行数**。放开 `note` 载荷是 1 行，不违反轻量；给内核加一个 `truncate` / `compact` / `index` 才违反——那是加动词。**"只加概念才算重"这条比"少改代码才算轻"更准确。**
3. **推给插件常常是把自己系统的不变量换成一次 RPC**。典型反例：为了"原生级哈希"把 `H` 做成执行件——哈希是 0.14ms 的纯 CPU 活，RPC 搬运要 0.6–1.4ms（JSON 序列化本身就是哈希的 3–6 倍），既没吃到原生收益，又把内核从"零依赖纯 JS"变成"需要外部实现件"，还引入"两份实现两份口径"的谱系分裂风险。**哈希的内核侧最优实现已经存在（就是那份手写 sha256），宿主侧最优实现也已经存在（`node:crypto`，进程内原生）。**



## 3. 世界的形状

世界 = 两张表：`defs`（内容寻址的 def 表，键 `= H(Def)`）+ `ids`（身份与世代）。

**两份"身份"必须分开**（D1 的核心）：

| 身份 | 是什么 | 成本 | 用途 |
|---|---|---|---|
| **位置** `pos` | 链头哈希 | **O(1)** | 乐观并发（`expect_pos`）、链完整性 |
| **内容** `worldRev` | 世界键集 + 身份内容摘要 | O(def 数) | 快照锚点、跨世界比较、数据 pin——**按需算，绝不挂在每条 entry 上** |

三个设计后果值得单独记住：

- 内容摘要吃 **`defs` 的键**而不吃序列化 body：键本身就是 `H(Def)`，键集 ⟺ 内容集，代价从"序列化整个世界"降到"排序键"。
- 摘要**不吃履历**（`born` / `adopted`）：否则同内容、同 `active` 而采纳历史不同的两个世界摘要不同，pin 它们的内容会无端漂移。"何时、谁、哪条 entry 采纳"是履历，归链管。
- 两者都**不做可达闭包**：闭包要求认识 body 里的引用标记 = 认识语义。（但见 §10 规矩 A——它让**上层**能算闭包。）

**`retire` 与 `set_active(null)` 世界效果相同，却是两条不同的 entry**：历史绝不折叠。幂等（`dup`）只属于"同内容重复 `put`"这一种情形。

## 4. 四条机制

缺了哪一条，承诺就漏哪一块。

| 机制 | 内容 | 缺了会怎样 |
|---|---|---|
| **M1 值层** | 一种 JSON 值模型 + 唯一规范序列化 + 结构相等 | 哈希口径不唯一 ⇒ 同一内容有两个键 ⇒ 身份系统当场失效 |
| **M2 归约机** | 8 原语、可执行的 def、显式效果挂起 | 判定逻辑只能编进宿主 ⇒ 改判据要重启、不可回滚、不留痕 |
| **M3 日志** | 只追加、链式哈希、位置 CAS | 无法回滚、无法审计、无法重放 ⇒ 内核剩下的唯一理由消失 |
| **M4 唯一写口** | 所有世界改动穿过同一个门，四步机械校验 | "非法进不来"变成一句靠自觉的话 |

M2 与 M3 的关系容易被低估：**判据必须是数据，所以必须有一种"能被数据表达的执行方式"**。把归约机冻成宿主代码，等于把 M2 的第一个用途（让判据可热改、可追溯、可回滚）取消——那不是简化，是换掉系统的一个承诺。

## 5. 求值与续跑契约

四态：`idle` / `waiting` / `done` / `refused`。设计语义只有三条要紧：

1. **整次调用原子**：`refused` / `waiting` / `idle` 返回的是**输入的那个世界**，日志为空。克隆体只服务于"整次成功"的 `done` 路径。这条是"失败不留半成品"的落地形式。
2. **`waiting` 从不返回部分世界**，也从不返回可续跑的中间态（D2：不捕获续体）。效果结果由输入回灌，**从入口重跑**，走到同一 `eff` 时直接取 `results[id]`。
3. **推荐一条 `write` 一个调用**；要原子地写多份内容，用**一条 `batch` entry**——这是 `batch` 的主要用途，不是性能技巧。

**`eff_id = H({run, i, n})`**（D3）：`i` 是 directive 序号，`n` 是该次求值内的效果序号。只带 `n` 会在一次调用内多次求值时碰撞——效果身份必须能对上号，否则回灌会喂错。

**D2 的代价必须明说，别让它变成意外**：

- 单 pending 是严格求值下的**下界**（`if` 不预求另一支、`cmp` 严格左→右），所以"同时挂起多个效果"语义上不可能；推测性发射只会浪费宿主的副作用。
- 一个 directive 内 k 个效果 ⇒ 总成本 **O(k²)**（每次续跑重放前缀）。每次调用由 `limits.gas` 封顶，不会失控，但**这笔账要按期付**。
- 纪律：**效果放叶子**；长循环拆成多个 directive（`i` 不同 ⇒ 各自前缀更短）。
- **门外的逃生舱**（宿主侧，不破 D2）：O(k²) 里真正贵的是重复触碰真实端口，不是重放纯计算。效果身份确定 ⇒ 宿主可按 `(port, method, canonicalJson(args))` 缓存幂等端口的结果。**做不了的事也写死**：宿主不能"从第 k 个效果续跑内核"——那需要捕获续体，撞回 D2。重放的 CPU 是纯函数侧的确定成本，宿主只能把它的**外效应**摊平到 O(k)。

**观测流是派生视图，不是状态**（§21 的架构含义）：不落盘、不入世界、一个 directive 至多一条、挂起时**不产出**观测（挂起不是结果）。但 `refused` / `waiting` 时它**照常返回**，尽管世界与日志都回到了输入——

> 设计后果：内核能在"整次调用作废"的同时仍然诚实地告诉你为什么作废。因为 `observations` 是拒因的**唯一载体**（输出里不另设 `reasons` 字段），而它不承载状态，所以同输入重跑得到同一条流。少一个字段、少一个可能的不一致面。

## 6. 日志即真源

**补丁链就是日志本身**（§10.6）。这四行不是需要辩护的替代方案，而是 `journal` 的同构描述：

| 你的说法 | 内核里的实体 | 代码与测试状态 |
|---|---|---|
| 变化 = 补丁（append-only） | 一条 `Entry`，由 `WriteRequest` 经唯一写口产生 | ✅ 实现 + 全量测试 |
| 状态 = 基础 + 补丁链 | `replay(entries, from?)`——**`from` 就是那个"基础"**，缺省 `EMPTY_WORLD`（`journal.ts:60`） | ✅ 实现 + 测到（`journal.b:324`） |
| 取用 = 组装（full / base_only / partial） | 三种起点 × 是否校验，见下 | ⚠️ 三种模式都**有通路但没有命名**；其中"校基础"这一步是整条链唯一没有正式入口的环节（`partial` 的现有测试甚至跳过了它） |
| 压缩 = 压扁（rebase，非破坏性） | 追加一条 `op:'snapshot'` = 新基础；**旧段不折叠、哈希不改** | ✅ 实现 + 正反例测到（`journal.a:441-456`） |

> **基础的真源在宿主，不在内核。** `snapshot` 只记 `args = { world_rev }`（内容身份，`commit.form.ts:71`）与自身位置，**不携带世界本体**；基础世界是宿主从某次 `done` 输出里存下来的一份数据。内核能在其位置**自校**它（`journal.apply.ts:50-56`：`args.world_rev !== worldRev(w)` 即拒），但"取用基础"这个动作本身不是内核动词。

**"取用 = 组装"这一行是新的，值得写进规格**——它精确对上已有的 API，只是从没被这样命名：

| 模式 | 怎么做 | 校验方式 | 能提 `write` 吗 | 状态 |
|---|---|---|---|---|
| `full` | `replay(全部 entry)` | `verify(全部)`——起点是冻结常量 `EMPTY_WORLD`，无需校基础 | ✅ | 测到 |
| `partial` | `replay(尾段, 快照世界)` | **必须两步**：先 `verify([], anchorAfter(基础, 快照), {worldRev: 快照 args.world_rev})` 校基础，再 `verify(尾段, anchorAfter(基础, 快照))` 校接驳；并断言 `worldRev` 与 `full` 相同（`journal.b:325-326` 正是此条，**但它跳过了第一步**） | ✅ | 组合未测 |
| `base_only` | 直接取宿主存的基础世界，不组装 | 就是上面那一步①本身：`verify([], anchorAfter(基础, 快照), { worldRev: 快照 args.world_rev })`——空段跳过循环、只剩 `journal.ts:95` 的内容身份比对。**这是内核里唯一能校验"基础"的入口** | ❌ **不可** | **该被命名；无"空段"测试** |

> **成对使用是硬规则（读代码读出的一条，此前没有任何文档写过）**：`replay` **只重建、不校验链**——`journal.ts:62-66` 里没有任何 `seq` / `prev` 检查，只查 `applyEntry` 成功与 `argsHash` 一致。于是 `replay(尾段, 错的基础)` **不会报错**：最锋利的例子是尾段里一条 `add_identity`，在真实历史上本该撞 `id_taken` 而被拒，接在一个缺前缀的基础上却**成功**了——于是你算出一个**链上从未被授权的世界**。幂等的 `put` 只是让这类错位变得安静。**防"接错位"的责任全在 `verify`**（`journal.ts:86` 才查 `seq !== expectSeq ‖ prev !== anchor`）。
>
> 所以取用的正确姿势是**三步成对**：① 校基础（`verify([], anchor)`——见下，它是唯一的入口）→ ② 校接驳（`verify(段, anchor)`）→ ③ 才 `replay(段, anchor.world)` 出状态。**单用 `replay` 会把接错的尾巴当合法历史。**现有测试覆盖了"凭证拿错 → `verify` 拒挂"（`journal.b:327`），但**没覆盖"`replay` 单独面对错位会怎样"**——这是一块未测面，该把"不保证"写死成断言。
>
> **更深的一层：`anchor.world` 不被校验，而 `base_only` 恰好是唯一的补法。** 读 `verify` 的实现（`journal.ts:81-93`）：它校验 `seq` 衔接、`prev` 衔接、每条 op 应用成功、`argsHash` 一致，**但对起点那个世界本身一个字都不查**——它是被 `cloneWorld` 之后直接当真理用的。`expected.worldRev` 校验的是**段应用完之后**的结果，不是**基础**；而"组装完的结果应当等于什么"除了再重放一遍历史之外无处可查。
>
> 于是"状态 = 基础 + 补丁链"这条语义里，**"基础"是整条链上唯一没有校验入口的一环**。现有 API 里唯一能校它的组合正是空段：`verify([], anchorAfter(基础, 快照), { worldRev: 快照 args.world_rev })`（`journal.ts:95`——空段跳过循环，只剩这条比对）。所以 `base_only` 不是"少起个名字"，**它是把基础纳入校验的那一次调用**；`partial` 想安全，必须先付它，再接尾巴。
>
> 这条不是理论担忧：`host.ts:61,182` 已经在手工做这件事——它把 `worldRev` 另存一个 `rev` 文件，重启时比对。宿主自己发明了"基础校验"，规格与接口里没有它的位置。而 `run(input)` 是同一个洞的更一般形式：**`expect_pos` 只证明"你接在这条链后面"，不证明"你手里的世界与那条链一致"**（要证明就得重放全部历史，不可负担）。所以基础一致性是**宿主的义务 + 内核提供可按需计算的凭证**，不可能是内核的自动检查——这一句决定了下面这条契约。
>
> `base_only` 的禁则是结构性的：写要 `expect_pos`，而 `pos` 是**链头**哈希，基础里根本没有。所以三模式里只有"组装到链头"的那两种可以提写；`base_only` 只能当**只读投影**（上下文、检索索引、UI）。这一格恰好也是它的正当用途——**"上下文 = 对日志的投影"在此闭环**：投影就是按需选一种取用模式，不需要任何新机制。

### 6.1 事件流语义的映射（会话 / 断线续流 / 编辑重放）

目标语义四行，逐行落到内核实体上——**其中一行的落点必须挪一格，挪不动的那一行是承诺的边界**：

| 事件流语义 | 内核里的实体 | 状态 |
|---|---|---|
| 事件流 = append-only 执行日志 | `journal`：一条 `Entry` 一个事件，`prev` 串起 | ✅ 齐 |
| checkpoint = 快照 | `op:'snapshot'`（记 `world_rev` = 内容凭证；世界本体在宿主） | ✅ 齐，但**基础不被校验**（§6 三步成对的①） |
| 恢复 / 断线续流 = 快照 + 增量日志重放 | `verify(尾段, anchorAfter(基础, 快照))` + `replay(尾段, 基础)`；效果侧未回灌部分靠 `waiting` + `results` 台账 | ✅ 齐（等价性实测为**逐字段（worldRev 相等）**） |
| **编辑重放 = 日志截断 + 新分支** | **截断 ❌ 内核不给；新分支 ✅ 但它住在身份层，不是链上的一段** | ⚠️ **落点要挪** |

**"编辑重放"的正确落法**：一条"线"是一个**身份**（`add_identity` / `fork`），线的一次状态是一个**世代**（`add_gen`，payload 指向那一刻的全量内容），"哪条线为真"是 **`set_active`**。于是"截断 + 新分支"表达成：从被编辑的那个世代 `add_gen` 一个新 payload（编辑后的内容），`set_active` 指过去——**旧线仍在链上，只是不再被取用**。

- **为什么不能是真的截断**：删尾部 = 改历史 = 放弃"历史改不掉"这条承诺（三承诺之一）。这条**不能既要又要**，不是没做。
- **为什么挪一格反而更强**：旧线留着 ⇒ ①"我把它改成了什么、原来是什么"本身可审计；② **旧线上已经真实执行过的效果有据可查** ⇒ 编辑重放不会把已经花掉的钱、已经发出去的 HTTP 再干一遍（配合 §5 的幂等端口缓存）。一个会编辑重放的 agent 产品，**最怕的正是"重放把副作用重放了一遍"**，而这恰恰是截断模型给不了、追加模型白送的东西。
- **行级归属怎么办**（链是全局线性的，"哪些事件属于这条线"内核不解释）：`Entry.ref` 是 entry 的字段、被 `entryHash` 覆盖 ⇒ 宿主用它指向"这条线 / 这条审计记录"，内核不看内容，但**过滤与分组可以按它做**。这是 `ref` 的设计用途，零改动，只需要一条约定。

**这个模型落在内核上的唯一实质税（必须记账，别让它意外发生）**：世界只增不减，而**编辑重放系统的历史增长速度远大于它的最终状态**——每次重做都往世界追加内容，被丢弃的那次不会消失。于是 `defs` 的字节数 ∝ **总尝试次数**，不是 ∝ 会话数。所以 §10 的四档分层在这个用法下**不是性能优化，是前置条件**：会话正文与工具结果属于 ②③，只有"线 / 世代 / 依赖声明"属于 ①。否则几个月后 §13 那两条墙会自己长出来。

1. **不需要 base 精确匹配才"不坏"**：`applyEntry` 从不读某个 def 的旧内容（同键 `put` 就是 `dup`），所以补丁重复应用、错序放置都**不会破坏已有内容**。但**别把这条读成"起点无所谓"**：它只保证"不弄坏"，不保证"不算出错态"——见下面的成对规则。状态差则是**必须**base 精确匹配，错位就坏，而且坏得像成功。
2. **崩溃后宿主可以随便重试**（幂等）。差量链重放两次直接把状态弄坏。
3. **补丁自带理由**：`{op, args, by, at, ref}` 说得出"谁、何时、提了什么"；一条 diff 说不出为什么。
4. **代价如实记**：盘上体积 ≈ 语料 1×（实测），不自动压缩。想小，就在**存储层**压（gzip / zstd 字典 / 块级差量，§9 宿主契约：能逐字节还原即合法），不改世界语义。**git 就是这个形状**：object 全量内容寻址，packfile 的 delta 住在对象模型之外。

**"非破坏性"的准确含义 = 压扁不改任何哈希。** `snapshot` 只是一条普通 entry（有自己的 `seq` / `prev` / `entryHash`，`args = {world_rev}`，应用时自校不符即 `world_rev_mismatch`）。它给重放提供**新起点**，不给历史动一刀——所以叫 rebase 是词汇借用，实质是**追加一个新基础**。内核里唯一的真差量是批内 `undo[]`：只活在内存、只在一批的范围内、失败即弃、**从不进历史**。

**与合并无关**（更正我此前的一句话）：这套"基础 + 补丁"的表述不需要分叉归并来证成，它本身就是单链的形态。多世界合并仍然是另一件事，仍然 off-scope（§9 边界 5）。

**链是 Merkle 的**（D5）。每条 entry 带 `argsHash`，而链哈希 `entryHash` **只吃 `argsHash`，不吃 `args`**：

- 于是链头推进、位置计算、锚点、期望值比较全部 **O(1)**，不碰载荷字节。
- 一份 `args` 只规范化一次；`batch` 的 entry 哈希从 O(总字节) 降成 **O(子操作数)**。
- **防篡改不降级，反而更强**：重放时把 `applyEntry` **重算**的 `argsHash` 与 entry 里**存着的**值比对，所以"改了 `args` 但没改 `argsHash`"也会被抓出来——这是**加出来**的一查，不是省掉的一查。
- 代价：`Entry` 多一个字段，且 **`argsHash` 的口径是链格式的一部分——改口径 = 改链**。

**`batch` 为什么要两段**：`Gen.adopted.write` 的语义是"完成采纳的那条 entry 的位置"。批内只可能是外层 entry，而外层链哈希依赖外层 `argsHash`，后者依赖全部子哈希——**单趟式里这个先后无解**。段一不碰世界，只做替换、哈希、聚合、外层定位；段二才应用。顺带收益：哈希性失败在**世界分文未动之前**就抛出。

**自引用只在批内、只指向更早的 `put`**（只有它有产物），替换发生在算哈希**之前**，而日志永远存**替换前**的 `args`——于是重放必然算出同一个 `argsHash` 与同一个外层位置。

**回滚 = 追加**。`snapshot` 只是锚点（世界不变，`worldRev` 因此不变），它的价值是把"重放全部历史"变成"从某点起重放尾巴"。归档与回收的**算法内核不欠**（§10.7 给了协议），宿主侧要做的只有节拍与冷存储策略。

**内核没有 `compact` 这个 op，也不欠一个**：上下文是**对日志的投影**，不是世界的副本。压缩、遗忘、摘要都发生在投影层，或作为数据进世界，或作为归档协议的一部分——三种都不需要新机制。

## 7. 表达力的边界（为什么只有 8 个原语）

机器侧有两个"造不出"（§12.1a 引理 0）：

- **(a)** 运行期造不出新 def——`eval` 的值域是 `Json`，写世界只经 directive（机器外）。
- **(b)** 运行期连新哈希都算不出——哈希不是求值原语。

由此**终止性是结构保证，不是纪律**：引用被引用定义一律经哈希（字面量或从数据里取出的 64-hex 串），两者都只能指向**已存在**的 `defs`；机器运行期构造不出新 def ⇒ 调用图恒为 defs DAG 的子图。`fold` 受集合长度限制，`gas` 只管资源上界。

三条裁决在写机器之前定死，并且对自己完成了第一例裁决：

| 构造 | 结论 | 理由 |
|---|---|---|
| `let` | **可派生 ⇒ 永远是写期宏，不是第 9 原语** | 展开产物是数据，重放走同一条路；用哈希引用而非朴素代入，使重复出现只付一份 def，且效果恰好发射一次 |
| `lambda`（运行期构造函数） | **不可派生，且证明不可派生后仍拒绝升级** | 构造出的函数**没有身份**——不在 `defs`、无 `seq`、无 `pins`、无 `sig`、进不了依附与判决。一个演化系统里"改动了却看不见、坏不了也退不回"的能力 = 内核的负资产，宁缺。真要生成性，正确出口是**多次续跑的写期生成**：产物拿到身份·世代·依附，演化要的是被记账的生成，不是黑盒里的生成 |
| 高阶 | **需要且已给**：函数作为一等**值** | 函数可入列表、可入 ctx、可运行时选择（策略注入、插件表、dispatch），但**永远只能选中已存在 defs 里的函数** |

原语只增、不改语义：老日志不含新原语，在任何实现上仍可重放；新日志在旧实现上报错——**拒绝执行，而不是算错**。这是不必给世界加版本字段也能保住"历史可重放"的原因。

**高阶的代价（写明）**：字面引用不再是 body 里穷举可得的静态依赖图——"扫引用算影响面"从语法层沉到运行时。内核从不承诺静态可分析性，引用完整性只吃**内核认识的字段**。

> **闭包其实是可算的**：机器无环境捕获（每次调用的环境 = 显式 `args`），所以"部分应用"= 把已绑参数做成数据，与函数哈希一起走。这条常被误当成缺失的能力，它是同一件事的另一种写法。

## 8. 五条设计决定（ADR）

| # | 决定 | 理由 / 代价 |
|---|---|---|
| **D1** | **位置与内容两份身份分开**：`pos` 用于并发与链完整性，`worldRev` 按需算，且摘要不吃履历 | 内容哈希必须覆盖语义，但挂在每次写入上会退化成 O(世界)/条。代价：跨实现的键排序必须写死（数组元素序不由规范序列化负责） |
| **D2** | **不捕获续体**：结果回灌后从入口重跑 | 确定性重跑本身就是复现。代价：O(k²)，见 §5 |
| **D3** | **效果身份 = `H({run, i, n})`** | 只带 `n` 会在一次调用内多次求值时碰撞 |
| **D4** | **错误一律抛同一类型带码，只在 `run` 边界转成 `refused`** | 内层返回类型保持干净（值就是值），不必层层解包。代价：错误码表成为契约的一部分 |
| **D5** | **链哈希是 Merkle 的**（`argsHash` 进 entry、链只吃它） | 见 §6。代价：`Entry` 多一字段，且口径不可改 |

## 9. 边界、信任与硬约束

**内核承认的输入边界**（§4.5 式清单，v1 不扩）：

1. 世界是一份完整输入，不是一句"你自己去读"。内核不认识文件、数据库、网络。
2. 时钟与随机来自输入（`now`），内核不取。
3. 能力表来自输入（`caps`），且**恒等于输入**——内核不扩权、不改权（§14-6）。
4. 效果只被**请求**，从不被执行。谁执行、执行几次、失败怎么办，全是宿主的事。
5. **单链 CAS**：`expect_pos` 只有一个链头。多世界合并不在射程内，v1 的答案是"再开一段账"。这不是缺陷，是**故意的边界**：合并语义要求内核认识冲突，而"认识冲突"要求认识语义。

**宿主契约（内核管不了、但破了内核就白干）**：

- 落盘**字节保真**：不得重新序列化 `Entry.args`。数字精度、键序、代理码元的任何漂移都会让 `argsHash` 对不上——损失的不是某条记录，是**整条链在那个位置断**。判据只有一条：**能否逐字节还原**。所以**编解码器合法**（gzip / zstd 字典 / 块级差量——解压后字节相同即可），**语义往返非法**（`JSON.parse` 之后再 `stringify`、按字段重建对象、丢弃未知字段）。前者是压缩，后者是改写。这也正是"差量与压缩属于存储层"（§6）的落点。
- **基础一致性内核不校验，也不校验不了**：`run` 收到的 `input.world` 是不是"这条链当前的结果"，验证它等于重放全部历史——不可负担，所以内核只在**可按需算的凭证**层面给工具（`worldRev` O(defs) + `snapshot.args.world_rev` + `verify` 的 `expected.worldRev`）。义务在宿主：**从任何非空基础起组装之前，必须先校基础**（§6 三步成对的①）。
  - **候选强化（未采纳，属实现选择）**：把 `Anchor` 改成 `{ world, head, world_rev }`，`verify` 首行无条件核对 `worldRev(anchor.world)`——"忘了校基础"就结构上不可能。代价：从快照起的那次 `verify` 必付 O(defs)。这是**冷路径**，与 D1"不挂在热路径"不冲突；且 `Anchor` 不落盘、不进链、不是 `KernelInput` 的成员，**改它不动任何哈希口径、不冻结历史**。
- 效果侧的审计（真实世界做了几次、失败重试）归宿主：内核只记"请求过什么、回灌了什么"。
- 装载、调度、保留策略、投影与压缩，都是宿主动词。内核提供这些词所依赖的**一致性**，不提供这些词本身。

## 10. 四档：什么住在哪（本轮决定）

热路径的成本几乎全部来自一个混淆：**把"只是发生过的事"当成"决定世界现在是什么的事"**。按**是不是声明** × **能不能重算**两个轴分四档（大小只是结果，不是判据）：

| 档 | 判据 | 住在哪 | 内核为它付什么 | 丢了的后果 |
|---|---|---|---|---|
| **① 声明** | 影响"世界现在是什么"，需要被引用 / pin：**含源码文本** | `defs` + `ids` | 哈希它（写一次、全量重放一次）、克隆、进摘要、进闭包 | **不可丢** |
| **② 留痕** | 只需"发生过、不可抵赖"，不需被引用 | `Entry.args`，被链覆盖 | 一次 `H(args)` 进链；**不**克隆、**不**摘要、**不**进闭包 | 可归档，**不可删** |
| **③ 可重算的本体** | 大，但能由 ① 重新算出来 | 宿主**缓存** | **零** | 丢了重建即可：构建产物、索引、解析结果 |
| **④ 不可重算的本体** | 大，且算不回来 | 宿主**持久存储** | **零**（世界只存"哈希 + 平台"声明） | 丢了就真没了：训练权重、外部抓取的数据、用户上传原始件 |

③ 与 ④ 在**协议上同形**（世界里都是一条"哈希 + 平台"声明），区别只在宿主的保留策略。

**源码为什么必须在 ①**（不因大而外迁）：

1. **回滚承诺**：回滚一个插件 = `set_active` 指回旧 payload，一个记账动作。这要求旧世代的源码必然还在；若它住在"可丢弃缓存"里，回滚承诺即为假。
2. **依附判定**：换掉源码必须判得出旧内容失效，而 `pins` 必须能指向它——源码不是 def，就没有东西可 pin。
3. **无特权**：给"代码"开一个"其实住在外面"的例外，就是内建特权。

**两条规矩**：

- **规矩 A：结构性依赖只走 `pins`，`pins` 是唯一记录处。** 判据一句话——"**被引用的那份 def 不在世界里，这份 def 还成立吗？**"不成立 ⇒ 它是依赖 ⇒ 必须是 `pins` 的一项；body 里的哈希只能是业务数据值。这样：闭包 = 宿主沿 `pins` 做一次**只读遍历**（内核仍不提供该算法、仍不解释 pin 名）；归档裁剪、跨世界搬运、`stale()` 依附判定全部随之可执行。**残留洞**：内核无法强制这点（它不读 body），漏写 pins 不会被拒，只会让 `stale()` 静默失效——**不报错的错**。
- **规矩 B：留痕走链，声明走世界。** 带内容的记录不该为了"能被记住"而挤进热世界。`note` 必须能承载载荷，否则 ② 无处可去。**代价**：② 换到的是 RAM / 克隆 / 摘要，**不省哈希时间**；把大字节塞进 `note` 只是把 RAM 墙换成时间墙。所以 ② 放摘要级、③④ 放本体，且载荷大小由**宿主门禁**限制（不是内核常量——内核定大小就是认识语义）。

**R1 的补法（与规矩 A 同批）**：把"pin 完整性"写成一条**可执行 term**——`schema` 声明"该类型身份必须有名为 `src` 的 pin"，宿主在采纳前求值它。门禁因此落在**数据**上（能热改、能追溯、能回滚），而不是落在宿主代码里（要重启）。这也是 M2 的第一个真实用户。

## 11. 不变量守住了什么（编号权威在 §14）

本文不复制规范清单，只交代方向与分组——**每条不变量都是某条承诺的可执行形式**：

| 组 | 守住的承诺 | 关联 |
|---|---|---|
| 重放一致 | `replay` 与 `run` 逐字段相同——真源只有链 | M3、D5、§6 |
| 失败不留痕 | 校验/应用失败后调用方的世界与日志分文未动 | M4、§5-1 |
| 纯与无外部 | 不取时间、不碰 IO、不依赖宿主环境；静态扫描可查 | §1、§9 边界 2–3 |
| 依赖形状 | 求值与写入之间没有边；公共面就是导出面 | §2 依赖单向 |
| 不扩权 | 能力表恒等于输入；效果只被请求 | M4、§9 边界 3–4 |
| 链格式 | `argsHash` 口径、唯一回填点、`Entry` 不被就地改写 | D5、§6 |
| **留痕不进世界**（待落，见下） | 规矩 B 的可执行定义 | §10 |

> 本文档写作时，`kernel.md` §14 是 15 条。"留痕不进世界"是规矩 B 带来的**第 16 条**，随 S1/S2 一并落入 §14，权威文本以那里为准。

## 12. 明确不做什么

这一节和上面所有节同等重要——**内核的价值大部分来自它拒绝成为的东西**。

**七项"最容易被顺手加"的东西**（§22 的架构表述；权威理由表在 §22，想加之前先**证伪**理由，而不是先写代码）：

| 不做 | 为什么不做 |
|---|---|
| 可达闭包遍历 | 要求内核认识 body 里的引用标记 = 认识语义。（§10 规矩 A 消掉的是"上层必须解析 body"，不是"内核提供算法"） |
| 内容回收 / 删除 | 内核没有删除；缩小世界由上层重建 |
| 效果执行 / 重试 / 超时 | 内核只发射，执行是宿主的事 |
| 审核判定 / 排程 | 都是动词，在上层 |
| 求值记忆化 / 捕获续体 | 撞 D2。且**记忆化只改常数、改不了 O(k²) 的阶**（阶来自重放前缀，靠 §5 的纪律解决），却要引入一份可变缓存与它的失效面——含 `eff` 的子树根本不可缓存（值来自 `results`），缓存还得先判定"是否含 eff" |
| 换哈希算法 | `H` 的口径**是链格式的一部分**（D5），换哈希 = 旧链不可重算，并破坏自证向量与跨实现可复现。真要换只有一处要动。（唯一例外：P0 开工前 sha1 截短 → sha256 全长不是"换哈希"而是格式定稿前的最后修正——**以内容哈希为身份与依附的系统不能建在已被实用碰撞攻破的哈希上**。此后任何再换（blake3 / xxhash）都按"换链"裁决） |
| `worldRev` 增量维护 | D1 已把它挪出热路径；增量维护要可变缓存 = 引入状态，破纯函数承诺，并新增"缓存与世界不一致"这个失效面 |

**三条更高层的不做**（不在 §22，因为它们是这次讨论才钉下来的）：

- **不把哈希实现做成注入 / 端口 / 执行件**：内核的 `H` 必须唯一且不可协商——可注入实现会让不同宿主产生"同内容不同键"的谱系分裂，动摇身份地基。性能靠"别让内核碰大字节"解决（§10 四档），不靠换实现者。
- **不把索引做进内核**："按内容查留痕"是宿主的派生物（可从日志重建、丢了不损真源）。内核加索引就是加动词。
- **不提供任何"便捷"的第二个写口**：M4 的全部价值在于"只有一个门"。
- **不做多链合并**：§9 边界 5。
- **不要求分类字段**：没有 `class`，没有标签位，没有内建特权（§2）。
- **不判断合理性与正当性**：内核只判机械合法性。

## 13. 已知规模边界（实验来源，只写比率与量级）

以下来自仓库内规模实验（`experiment/`），**绝对值一律随机器而变，不得写进任何规范性文本**；能长期引用的是**比率与量级**。测机：Node v24.x，双核 i3 @1.2GHz，原生哈希单元可用。

| 事实 | 量级 |
|---|---|
| 内核纯 JS 哈希 vs 宿主进程内原生哈希 | **40–58×**（同热口径两轮；`≈70×` 是早期冷均值口径的工件，与 K1 从 4.7× 修正到 1.4× 同源——JIT 预热差，单点比率不可长期引用） |
| 世界必须**整份在内存里**（`defs` 只增不减） | **RAM 墙**，随机器内存线性移动 |
| 日志自带全量载荷 | 盘上体积 ≈ 语料 1×；**不可比语料更小** |
| 重复提交同内容（`dup`）的成本 | 约为一次真写的 **7–9 成**（纯内核口径 ~9 成，含盘写口径 ~7 成）——判决发生在完整应用之后；dup 短路的省幅上限是一半（预哈希那一趟不可免） |
| 链哈希与 `worldRev` | 前者 O(1)、后者 O(def 数)，均符合 §6/D1 的设计意图（实测确认） |

**由此得到的两条墙**：

- **时间墙**：只要大字节继续走 `put`，全量审计的成本就 ∝ 语料字节 ÷ 内核哈希速率。`snapshot` 分界能把**日常重启**变成只付尾账（且与全量重放**逐字节等价**，已实测），所以时间墙实际落在"完整审计"这一次。
- **RAM 墙**：`①` 档的字节数没有可调上限。约束形式：**`defs` 的字节 ≪ 进程可用内存**；任何"单条很大"的东西都不该是声明。

**四条对策（都不破不变量，且都已各自有等价性证据）**：

1. **`dup` 短路**：全幂等批在预哈希后即可定论，跳过完整应用——重试是演化系统的常态路径，不该重付。
2. **大字节不走 `put`**（§10 的 ③④ 档）：链只承诺哈希值，不承诺谁算的——宿主用原生哈希重建并比对即可验证。
3. **`note` 承载载荷**（规矩 B）：切断"历史增长率 = 热路径增长率"。
4. **快照分界 + 归档协议**（§10.7）：把全量重放降为可选择的审计动作。

**字块化哈希**（把内核哈希速率再抬高）是**止血，连都不是良止血**：实测上限只有 **1.4–1.6×**（逐字节等价已验；此前"数倍"为冷口径工件）。这个数字反过来加固本节结论——纯 JS 实现层近乎无路，性能只能靠上面的 1–4 活路；四档分层落地后就不必再回头看它。

**源码这笔账**：源码留在 `①`，接受"每次全量审计重哈希一遍"的保险费。按真实尺度（平均几十 KB 一份）这笔费用很低，且被对策 4 移出日常路径；它在**大型仓库**下的真正约束是内存，不是 CPU。把源码搬出世界省下的那点钱，代价是放弃"代码回滚 = 一个记账动作"——不值。
