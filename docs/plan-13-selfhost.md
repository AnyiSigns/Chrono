# 计划 13 · 自改宿主（非插件）

> 前置：`plan-03`–`plan-12`。
> 口径来源：`docs/agent.md` §1 / §5 / §6 / §7.1 / §10；`docs/plugins.md`。
> 本计划**不是加插件**：让 agent 改 `host` 源码并安全重启 / 回退。这是唯一需要动框架源码的计划。

---

## 目标

agent 改 `host` 源码 → 构建 → 重启 → 失败自动回退 `last-known-good`。

## 前置

`plan-03`–`plan-12` 验收全绿（尤其 `plan-10` 的 `approval` 与 `plan-11` 的异常面）。

## 本阶段交付

- `host` 源码入世（对 `host` 身份一条 `add_gen`）；源码树以 `blob` / `tree` / `commit` def 入世。
- 构建 → 重启路径：装配层按新 active 世代构建并 spawn。
- 失败回退：引导器读"最后已知良好"检查点，指回旧世代 + 重启。
- 回退动作本身走三档卡（`approval` term 分级）。
- 边界定义：破坏 = 构建失败 / 握手失败 / 启动崩溃 / 采纳后回归（G7 判负）。

## 本阶段口径

- 引导器是唯一不可自改常量，自改必须先有"不在被改对象里"的执行体。
- 回退由 `approval` term 分级：`auto` = 自动回退立即执行 / `review` = 挂起等批 / `deny` = 停在当前；
  但分级表本身对 agent 恒 `deny`（`plan-10` / `agent.md` §7.1）。
- 回滚 = 一条 `set_active` + 重启，不改历史。
- `host` 源码入世后，世界是真源，磁盘是工作副本。

## 出口验收

**破坏性门禁**：注入坏宿主源码 → 必须自动回退 `last-known-good` 并在时限内恢复。

## 本阶段不做

- 多设备 / 多用户同步；多链合并。
- 自改内核（内核是常量，永不可自改）。

## 范围红线

- 内核与引导器不改；回退动作不得放宽 `approval` 分级表。
- 不改装配层的装配算法（只换 active 世代）。

## 单次会话可完成

按 host 入世 → 构建 / 重启 → 失败回退 → 破坏性门禁 提交；超尺度即再切。
