## 0. 命题与主目标

**一句话命题**：在**固定预算**（LLM 调用数 + token + 工具调用 + walltime，见 §0.1）下，一个运行时现场生成
拓扑的 agent 图，能否比人工设计的固定编排图拿到更高的隐藏测试通过率，且增益可归因到
**编排 / 自治 / 进化**，而不是模型或参数量。

**唯一主目标（同构于 DataGraphLab 计划附录 A.1，可测量）**

```
S(holdout, 主档) = 隐藏测试通过的任务比例，同预算 B 下测量
达标：配对差值单侧 CI 下限 ≥ Δ（同任务同 seed 配对，BH-FDR 校正）
      且  S_new(holdout) ≥ S_incumbent(holdout) − ε
```

`Δ / ε / δ / floor` 第一版写常量，但**以数据 def 形式住账本**（可版本化、可回滚、可人工改）；
**阈值由机器从指标重算，禁手写 `passed`**（承 DataGraphLab 纪律）。

**口径分工（两处不可混用同一阈值）**：**目标命题**（`S_ag` vs `S_fixedgraph`）用 `Δ`，判据 = **配对差值
单侧 CI 下限 ≥ Δ**（同任务同 seed 配对，BH-FDR 校正；点估计并列报告）——主结论不能只用点估计，否则真 LLM
方差会把噪声读成增益；
**采纳闸**（`new` vs `incumbent`）用**配对非劣检验**（单侧 CI 下限 ≥ −δ **且实测半宽 ≤ δ**，`n` 由预注册功效分析
定、`n ≥ 200` 为下限；§8 硬闸、§10 GA7）。前者是"比人工图强多少"，
后者是"本世代有没有退步"，不是同一件事。

### 0.1 预算 `B` 的可操作定义（否则主判据不可测量）

- `B` 是**向量 cap**：`{ calls, tokens, tool_calls, walltime }`，四项上限**同时生效**，任一触顶即停。
  **`walltime` = 有效挂钟预算**（含 IO 与 LLM 网络等待，不区分 CPU/IO）；**限速退避的等待时长从 cap
  中扣除并单列 `ratelimit_wait`**（否则"配额枯竭"会被读成"能力不足"，§12-4）。§6 默认**串行拓扑执行**，
  并行化列为 §13 阶梯一档（否则并行度成为隐藏自变量、改变 walltime）。改并行化前须先登记，且须先
  解决 §4.3 的 publish 偏序问题（并行下"两两可比"不可满足）。
- **控制层推理与搜索都要计费，但分两层记账**：**运行时**控制层（编排/分解/路由）的 decode token
  进本任务 `B`；**离线搜索**（MCTS/EA 展开）不是单任务的属性，记在 `ROUND_B`（§8、§12-11）并单列
  `search_cost`，**不得**摊进 `cost_exec(G)`。不记它 ⇒ `fit` 系统性低估自适应臂的成本，主判据当场偏袒本方案。
- 主判据读 `S_at_cap(B)`：**在 cap 下**的成绩。同时**必须报两个方向**——① 等预算比成绩（`S@B`）
  ② 等成绩比成本（`cost_to_solve`）：报四维 `{calls,tokens,tool_calls,walltime}` 的**帕累托前沿**
  （哪些臂不被任何臂在所有维度同时支配）+ 各维中位数。**四维 `used` 必须含编码器成本**（§5 `encoder_cost`，
  与 `cap` 同口径；另单列报告）——否则帕累托低估自适应臂的真实成本；标量 `cost_exec(G)`（§4.3，只含图执行）
  仅作 fit 内部用、**不进对外结论**——否则两臂省不同维度时排序依赖 `w_d` 主观选择。某臂只用 30% B 就达到同成绩，
  这是它的优势，**必须让它可见**；只看 `S@B` 会把它埋掉。
- **任务级成功 = 隐藏测试全过**（`pass@1`）；另有 **`test_pass_fraction`**（用例通过比例）作
  dense 信号（§5）。两者都报，**适应度只用前者**。

### 0.2 两条硬约束（破了结论不可信）

1. **holdout 只准"冻结模型前向 + 真测试判分"**。搜索器、llm teacher、任何"为提升而跑"的循环
   **一律只在 dev 上运行**；蒸馏集里不允许出现任何由 holdout 任务驱动的拓扑。一旦在 holdout 上
   搜过，holdout 即刻作废。
2. **同预算的第一性是 cap 而不是等量**：所有臂共用同一 cap、允许提前停止；**不允许**给自适应臂
   更大的 cap 再用"同预算"话术掩盖。

**五个自变量必须分开记账**（否则永远分不清收益来自哪边）：

| 自变量 | 对照 | 测量 |
|---|---|---|
| 编排 | 图固定 vs 现场生成 | 同池、同权重、同预算下的 pass@1 差 |
| 分解 | 固定分解（teacher 单次产出） vs 蒸馏分解（含再分解） | 固定分解下只搜拓扑的增益差（GA8⑧）；分解本身**不进搜索**（§7） |
| 路由 | 同图随机路由 vs 学到的路由 | GA8⑦ 的 pass@1 差 |
| 自治 | L0 vs L1 vs L2 | 同图骨架、只改节点自治档位（GA8⑩） |
| 进化 | 池冻结 vs 可结晶生长 | 跨世代曲线 + holdout 非降（GA8⑪，跨世代 lineage 对照） |

> 分解、路由在 §5 是独立模型，但其增益**默认并入"编排"列**汇报；要单独归因时必须挂 GA8⑦/⑧
> 消融臂（见 §10），不许用"并入"话术掩盖其贡献。编码器（§5）同理：冻结编码器 + 随机编排臂
> （GA8⑨）隔离编码器对泛化的贡献。

## 2. 任务域：真实编码任务

**任务规格（task spec）**：`{ id, repo 模板, 起始提交, 任务描述, 隐藏测试, 预算上限, 难度向量 }`。

- **判分 = 真跑隐藏测试**（不是模型自评）：`exec` 端口在临时工作区执行；产物路径回写校验。
- **测试完整性（GA4）**：评测用测试文件哈希 == 钉死哈希；改/删/新增测试文件 ⇒ 任务分 0。
- **holdout 隔离（GA5）**：holdout 用**不同 repo 模板族**，不是同模板换参数——否则测的是记忆不是能力。
- **难度向量参数化**（课程模型的自变量）：文件数 / 接口数 / 约束数 / 不可逆步骤数 /
  隐含依赖数。**"复杂"必须是向量，不是标签**。
- **dev / holdout 无交集**：任务哈希集合与 `expected` 不得出现在提案上下文、提示词、记忆召回里（含 JSON 内嵌）。

**沙箱最小版（P2）**：临时工作区目录 + 路径白名单 + 超时 + 默认无网（网络只在 `model` 端口）。
先用 Node 子进程 + 目录隔离；Rust 沙箱/容器列为后置（对齐 `docs/agent.md` §7 的"第一版不做"）。

## 3. 节点池与能力契约

**声明式节点池**：池子是一份**数据**（清单式 def），不是代码。

```
NodeDecl = {
  node_id,                    // 实例 id（开集）
  contract_ref: Hash,         // 它实现的 Contract（= 能力类，闭集 append-only）；见 §3.1
  implementation,             // llm | tool | trainable
  bindings: {                 // 每项都是 pin(hash)，内容不内联（规矩 A）
    prompt?,                  //   提示词 def（LLM 节点必填）
    model?,                   //   模型 id / provider / 版本
    decoding?,                //   temperature / max_tokens / stop / tool_choice
    tools?,                   //   工具绑定与版本
    context_policy?,          //   装什么进上下文 + 预算与权重
    retry_policy?,            //   L1 的迭代上限 K 与退出条件
    weights?,                 //   trainable 节点的控制层权重世代
  },
  cost_model: { tokens?, calls?, walltime? },          // 成本估计，进预算账
  autonomy: L0 | L1 | L2,     // 自治档位（§6）
  canary_set,                 // 金丝雀集 ref（按契约定义，§3 末；统计按实例滚动）
  health: { success, calibration, latency, n },        // 滚动统计（宿主算，不入能力契约）
}
```

### 3.1 节点契约（`Contract`）——可寻址面的唯一单位

```
Contract = {                        // 规范形哈希 = contract_id = 编排模型看到的能力类
  contract_id,
  kind: 'pure' | 'effect' | 'agent',
  inputs:  [ { name, type, required, cardinality: 1|n, binding_mode: all|any } ],  // 走边读；all=汇聚(AND)，any=候选(OR)
  outputs: [ { name, type, cardinality: 1|n } ],            // 写自己的 slot（单写者）
  reads:     [ SharedRef ],         // 可读的共享上下文键（只读，§4.3）
  publishes: [ SharedRef ],         // 可发布到共享上下文的键（受控动作，§4.3）
  pre:   Term,                      // 前置条件：不满足则节点可合法拒绝
  post:  Term,                      // 后置条件 = 节点级验收器（dense 信号的唯一来源）
  refuses: [ RefusalCode ],         // 合法拒绝码表（typed、可路由）
  effects: { ports, methods, caps },// 声明需要的能力；越权即拒（不扩权）
  idempotent: bool,                 // L1 重试与宿主幂等缓存依据
  cost: { tokens?, calls?, walltime? },
  determinism: 'exact' | 'audited'  // exact 可逐字节重放；audited 必须 EffectAudit 回灌
}
```

**两级成本与两套分类（不许混用）**

- **成本两级**：`Contract.cost` = 该**能力类**的成本先验（解码期预算 mask 的估计量）；`NodeDecl.cost_model`
  = **实例**的实测/覆盖值。**预算记账以实例 `cost_model` 为准**，实例缺省时回退契约 `cost`；两者都进
  manifest。`§8`/`§12` 的 cap 一律指实例侧记账。
- **分类两套、正交**：`Contract.kind`（`pure|effect|agent`）= **效果语义**，属能力类；
  `NodeDecl.implementation`（`llm|tool|trainable`）= **执行载体**，属实例。约束（缺一即拒，GA1）：
  `trainable` ⇒ `kind:'pure'` 且 `determinism:'exact'`（可逐字节重放）；`tool` ⇒ 触达端口时
  `kind:'effect'`、否则可为 `pure`；`llm` ⇒ `kind:'agent'`（可 L2 委派）或 `'effect'`（触达 `net`），
  且 `determinism:'audited'`（temperature=0 且审计回灌齐备时方可声明 `exact`）。

**五条铁律**

1. **能力类 ≡ 契约**。"新节点只注册能力"的精确含义 = 新实例声明它实现哪个**既有** `contract_id`；
   契约集 append-only ⇒ 可寻址面永不变化。
2. **契约不可变**。改 `inputs`/`outputs`、改 `pre`/`post` 的**判定式结构** = **新 `contract_id`**
   （不是改旧类）；否则等于偷改可寻址面。`post` 两层拆分，不可混：
   - **(a) 判定式结构**（`post_term` 的算子、比较关系、字段引用）属契约、不可变；改它 = 新
     `contract_id` ⇒ 触发 MoE 专家追加 + arch bump + 重训 + 门禁重跑（§3 结晶同档）。
   - **(b) 阈值参数 θ**（如"通过率 ≥ θ""延迟 ≤ θ"）走 §9 `put_threshold`、**回合锚冻结**、
     可版本化热改（`set_active` 切版本），**不**触发新契约、不重训。调阈值只影响下一轮。
3. **`pre`/`post` 是可执行 term**（对齐 `docs/agent.md` 判定单向）：判定式结构以数据身份进库、
   **不可热改**（改即新契约，见铁律 2(a)）；阈值参数以 `put_threshold` 入库、回合锚下可热改可回滚可审计。
   `post` 就是前文一直说的"节点级验收器"——**dense 训练信号、漂移判定、路由反馈全部出自它**；
   没有它，dense 信号无来源。账本无 `put_pre`/`put_post` op：判定式走 `declare_capability`，
   阈值走 `put_threshold`。
4. **拒绝是一等输出**：`refuses` 码表 typed 且可路由。节点不许用异常表达"我不该做/做不了"，
   否则路由学不到东西、L1 的"拒绝并给原因"没有落点。
5. **效果声明 = 权限上限**：契约里没声明的端口/方法，运行时就不注入，调用即拒。这是 GA0「不扩权」
   的落点，也是"自治只能花预算、不能拿权限"（§6）在契约层的实现。

**校准（`calibration`）语义钉死（`health.calibration` / GA11）**：`calibration` = 节点**预测置信 vs
实际通过率**的误差（ECE）。来源是契约可选的 `confidence` 输出位——`outputs` 可声明一项
`{ name:'confidence', type:'prob', cardinality:1 }`（值域 [0,1]，节点自报对该次产物 post 通过的概率）；
`ECE = Σ_b (n_b/n)·|avg_conf_b − emp_pass_b|`（`n` = 该节点累计预测数，`n_b` = 落入 bin `b` 的样本数，
**按 bin 样本数加权**；bin 划分与 `n` 一起入 `health`）。**无 `confidence` 输出的节点 ⇒ `health.calibration` 恒为
`null`**——不得用 post 的 0/1 verdict 凑 ECE（那是"节点-任务一致性"，不是校准）；GA11 对此类节点只判
成功率/延迟漂移、不判 ECE。`type:'prob'` 进 §4 类型系统。

**幂等 ↔ 确定性对齐（堵 memo 误用）**：`idempotent:true` ⇒ 必须 `determinism:'exact'`（产物逐字节
可复现，§4.3 memo 才能合法短路复用）；`determinism:'audited'` 的节点一律 `idempotent:false`、
调用必须带 `variant_index`。**校验点不在契约层，而在 `(contract, 解析后的 bindings, decoding)` 三元组
解析之后**——同一 `pure/exact` 契约的实例若绑定 `temperature>0` 的模型或非确定工具，即判
`idempotent:false`（契约层单独通过不算数，否则 memo 会非法短路）；违反即拒（GA1）。因此契约的
`determinism` 是**能力类允许的最强档**，**生效档位** = 按 `(contract, bindings, decoding)` 解析后的
`min`；**结晶合成（下文）与 GA10 一律用生效档位，不用契约声明档**。

**端口绑定谁决定（已定）**：绑定属于拓扑，**不交给运行时猜**。

- 每个契约的端口在生成期按 `0..k-1` 规范化编号，token 空间小且稳定（契约不可变 ⇒ 编号不漂移）。
- **唯一匹配自动补齐**：`LINK u→v` 编译成唯一合法端口对，只花一个 token。
- **歧义时要求显式端口对**：`LINK u:2→v:0`。
- "歧义即拒"不可取：浪费预算，而歧义在实践中稀少；"运行时确定性优先序"更不可取：它把一部分
  数据流交给运行时排序规则 ⇒ **拓扑不再是唯一控制面**，而且模型本意被悄悄替换成别的端口，
  只表现为成功率下降、归因不出。
- 端口对进 `sig(topology)`：选错端口就成为可去重、可对照、可回滚的**结构差异**。

**三条闭/开集铁律**：

1. **能力类 = 闭集 append-only；节点实例 = 开集**。编排模型寻址**能力类（= 契约）**，池子把契约绑到实例实现。
2. **新节点只注册能力**：不得改变路由表、不得改变其它模型的结构、不得改变可寻址面。
3. **契约数有上限**：`|Contract| ≤ 32`（= §12-6 的专家数上限）。append-only 不等于无限增长——
   触顶后要么走 §13「控制层容量」档扩容（arch bump + 重训），要么把新能力并入既有契约的 `role`/子类型，
   不允许静默突破（否则 MoE gate 维度与专家预算失去上界）。

**为什么 `bindings` 必须 pin 而不是内联**（三条都是硬理由）：

1. **规矩 A**：结构性依赖只走 `pins`。提示词 def 是独立 def，节点声明只持哈希 ⇒ 同内容只存一份、
   闭包 = 沿 `pins` 只读遍历、`stale()` 判失效（改提示词 ⇒ 旧绑定失效）。
2. **归因**：若把提示词内联进 `NodeDecl`，改一个词就换 `H(NodeDecl)` = 池子里多出"一个新节点"，
   于是**提示词消融（prompt A/B）与漂移归因都做不了**。pin 住之后节点身份不变、绑定换代，
   可以问"同一节点、同一拓扑、只换 `prompt_pin`，S 变多少"。
3. **回退**：换 pin = 换版本；回退是 `set_active` 一条追加，不是重写正文。

**三级内容必须分开**（否则轨迹既不可重放也不可蒸馏）：

| 级 | 内容 | 住在哪 | 谁记录 |
|---|---|---|---|
| 节点身份 | 角色提示词、few-shot 模板、解码参数 | `bindings` 里 pin 住的 def | 池版本 |
| 每次调用装配 | 上下文策略现场拼进提示词的片段 | 运行时 | **逐次入轨迹**（连同 `prompt_pin`） |
| 外部输入 | 检索片段、记忆召回、文件内容 | 节点外部 | `EffectAudit` + 轨迹 |

**变异通道三分（对应"什么可训、什么可长"）**：

| 通道 | 对象 | 占生长额度？ | 触发 |
|---|---|---|---|
| 权重变异 | 控制层三模型（可训） | ❌ | 蒸馏 / 微调 |
| **绑定变异** | **llm 节点的提示词·模型·解码·工具绑定** | ❌ | 搜索 / 提案（这就是"不可训节点"的进化面） |
| 生长变异 | 新能力类 / 新节点实例（含结晶） | ✅ | 能力缺口证据 |

→ LLM 节点不可训，**提示词就是它们唯一的进化面**；这就是 `prompt` 必须有独立版本身份的原因。
轨迹里不记 `prompt_pin`，蒸馏样本就无法归因，绑定变异也就无从对照。

**三个概念别混**：`Contract`（能力类，闭集 append-only，**编排模型的寻址单位**）
→ `NodeDecl`（实例，开集，同契约可有多个实现）
→ `MoE expert`（属于控制层，但其边界**也是契约**）。

**结晶必然是一次契约扩展（原稿自相矛盾，此处修正）**：把子拓扑折成单节点，必须为该节点**新建完整契约**
（不止 inputs/outputs）：

- `inputs` = 子图入口对外部输入的映射；`outputs` = 子图 `exit` 的输出位；
- `reads` = 子图各节点 `reads` 的并集，**减去**「由子图内部 publish 且该读取点在内部发布之后」的键（内部闭环
  不进新契约）；在内部首次发布**之前**被读的键必须保留（仍需外部供给）；
- `publishes` = 子图内所有 `publishes` 键的并集（对外暴露子图产出的**最终版本**，与 §4.3 规则 5 的偏序合并一致）；
- `pre` = 子图所有入口前置的合取（由 `agent/manager` 从子拓扑行为归纳，过对抗套件前置过滤）；
- `post` = 子图内**过程 post** 的合取归纳（dev 上归纳；阈值参数仍走 `put_threshold` 回合锚）。
  **不得**写成任务级验收式——那违反 §4.2 的两级验收分离；任务级验收永远只在 `exit` 触发；
- `refuses` = 子图内各节点合法拒绝码的并集；
- `effects` = 子图所有 `effect`/`agent` 节点端口/方法/caps 的并集（**取并集不取子集**，否则结晶后丢能力）；
- `cost` = 子图各节点实例 `cost_model`（缺省回退契约 `cost`）沿**最长路径**的聚合上界（聚合算法随 §14.1 结晶合成规则补）；
- `idempotent` = 子图所有节点**生效档位**（§3「幂等 ↔ 确定性对齐」解析后的 `min`）为 `exact` 时为 true，否则 false；
- `kind` = 子图含 `agent` 节点 ⇒ `'agent'`，含 `effect` 节点 ⇒ `'effect'`，全 `pure` ⇒ `'pure'`。

结晶契约合成是 `agent/manager`（决策层，§8）的核心职责，合成规则进 §14.1「尚未写死」。而契约 append-only
⇒ **结晶 = 契约扩展 + 新实例，两件事一起做**，因此必然触发：MoE 专家追加 + gate 追加式扩展 +
arch bump + 重训 + 门禁重跑（§13 阶梯第 2 档）。所以"结晶不增熵"指的是**结构复杂度 `H` 下降**，
不表示"不动可寻址面"——两者不矛盾，但必须**一起记账**。

**冷启动**：新能力类配**未知能力兜底槽**（零初始化）；新实例挂已有能力类时，由池内同能力类
实例的成功率统计竞争上岗（无需改控制层）。

**同契约多实例的实例选择规则（必须写死，否则不可复现）**：编排模型只输出**契约**，实例由运行时
按下面的确定性规则选：

1. **显式偏好优先**：编排 token 带实例偏好且该实例已转正（退出影子模式）⇒ 用它。
2. 否则按**健康分确定性排序**：`(影子状态, 成功率下界, 成本)` 取首；并列取 `node_id` 最小。
3. **A/B 强制**：评估绑定变异时必须**强制指定实例**，不许走默认规则——否则绑定效果与实例选择混淆。
4. **选择结果逐次入轨迹**（`chosen_instance`），否则"换了实例"与"换了模型"分不开。

**节点健康与金丝雀**：金丝雀集**按契约定义**（同一契约的所有实例共用同一集合，保证可比，§12-12），
滚动成功/校准/延迟统计**按实例**计算——漂移最现实的来源是某实例的绑定被 provider 静默升级。
该统计是**漂移判定的唯一输入**（§8）。没有金丝雀集，"节点漂移"只能是感觉。

## 4. 图文法（拓扑的唯一表示）

**不变量（代码层焊死，承附录 I.1）**：

1. 节点 = 一次能力调用，带 typed 契约（§3.1：`kind/inputs/outputs/pre/post`）。
2. 边 = **端口到端口的映射** `(u, out_port) → (v, in_port)`，类型必须兼容；图**无环**。
   端口绑定是拓扑的一部分并进 `sig(topology)`——**数据流完全由拓扑决定**。
   **边的 AND/OR 语义必须显式（否则"条件超图"与"路由选边"无法落地）**：入端口声明
   `binding_mode: all` ⇒ 所有入边**全部**满足（AND，用于 `cardinality:'n'` 汇聚）；`binding_mode: any`
   ⇒ 入边互为**候选**，运行时由路由**恰选一条**（OR）。拓扑因此是 **AND-OR 图**，实际执行的是满足
   `all` 端口与所选 `any` 边的**最小闭包**（= §6 的"活动子图"）。`any` 端口必须至少有一条候选边。
3. `entry` 禁入（无入边）、`exit` 唯一可达终点、**图至少含 1 个节点**（`entry→exit` 直连的零节点图
   非法）。**无环 ⇒ 任一节点在一条执行路径上恰好执行一次，故不设 `MAX_REPEAT`**（原"单节点访问 ≤
   `MAX_REPEAT`"在 DAG 下无落点，删除；L2 **子图递归深度**由 `MAX_RECUR` 管，DAG 内不存在节点重入）。
4. 所有路径收在 `exit`（= 任务级验收通道，§4.2）；**任务级验收只读 `exit` 前的产出端口，节点级判定只读 `post`**，两级不混。
5. 预算上限：节点数 ≤ `MAX_NODES`、边数 ≤ `MAX_EDGES`、深度 ≤ `MAX_DEPTH`、递归深度 ≤ `MAX_RECUR`。

**类型系统（"类型必须兼容"的判定，缺此则端口绑定 / 唯一匹配 / 汇聚不可实现）**：采用 **nominal
类型 + `type_id`**。`inputs`/`outputs` 的 `type` 是一个 `type_id`（字符串，进契约 append-only 类型
表，故类型集 append-only、`type_id` 不漂移）。兼容 = `type_id` 相等 **或** 显式声明的子类型关系
（类型表带 `subtypes: [type_id]`）；`cardinality:'n'` 汇聚要求所有入边 `type_id` 相等（子类型先规范化
到最小公共超型）。预留类型：`'artifact'`（默认产物）、`'verdict'`、`'refusal'`、`'prob'`
（§3.1 confidence 输出位）。**端口另带 `role` 标签**（如 `code`/`plan`/`critique`/`tests`），用于把
"唯一匹配"从稀有变成常态——只有 4 个类型时默认 `artifact` 会大面积歧义，显式端口对会吃掉 token。
`role` 进契约 append-only 表，故不漂移。等价/规范化算法进 §14.1「子图等价规范化」同列。

**生成 = 受约束解码**：编排模型吐 token 序列，解码器只产出合法图；运行时**只机械校验、
不做语义兜底**。非法图（若出现）计入 GA1 并在账本留拒因。

**子图（L2 委派）**：子图是**拓扑的同一种表示**，同样过闸、同样计入同一本预算账。父节点把
预算切给子图，子图不得无界扩张；每次委派留一条审计记录（父节点、深度、分到的预算、结果）。

**结构代际**：拓扑的规范形哈希 `sig(topology)` 为**精确去重键**；另有
`family_sig(topology)` = **节点/契约多重集签名**（忽略边），用作 EA 交叉域与 GA8⑥ 的"同多重集"族。
两者不可混：`sig` 相同 = 同一张图（交叉无意义），`family_sig` 相同 = 同族不同拓扑。
结构版本随池版本与图文法版本 pin。

### 4.1 生成算法（token 语法 + 拓扑序；缺这个无法实现）

**输出序列**：图按**拓扑序**生成，全局约束在生成期即成立。

```
Graph    := ( NODE | LINK )* EXIT                 // 交错生成：边可紧跟其端点
NODE     := CAP <contract_idx> STOP               // 节点按生成顺序 = 拓扑序（只可连向 i<j）
LINK     := LINK <i> : <out_port> -> <j> : <in_port>
          | LINK <i> -> <j>                       // 省略端口 = 唯一匹配时自动补齐
                                                  // all/any 由 v 的输入端口在契约里声明，不由 token 决定
EXIT     := EXIT_STOP                             // 显式收口；末节点 outputs 即任务级验收候选
```

**为什么必须按拓扑序**：新节点 `j` 只允许连向**已生成的 `i < j`**，于是——
① **无环自动成立**（局部约束，mask 好写）；② **`entry` 可达自动成立**（除首节点外每节点至少一条入边）；
③ **`exit` 可达 O(1) 可判**（末节点收口）。**全局约束交给生成顺序，不在生成后校验**——这才是
"运行时只机械校验、不做语义兜底"能成立的前提。

**五条必须写死**

1. **端口编号**：契约端口按声明序 `0..k-1`，token 只出现编号（契约不可变 ⇒ 编号不漂移）。
2. **入边约束**：`required: true` 的输入端口**至少一条入边**，否则该节点不可生成；`cardinality:'n'`
   在 `required:false` 时允许 0..N 条、在 `required:true` 时允许 1..N 条（扇出汇聚）；
   **除首节点外每个节点至少一条入边**（否则该节点从 `entry` 不可达），由解码期 mask 强制。
3. **上限是 mask 不是事后拒绝**：`MAX_*` 在解码期逐 token 生效。
4. 于是 **GA1 变成"assert 解码器无漏洞"**（**语法层**：闭合、类型兼容、上限），而不是"过滤非法图"；
   真出现**语法**非法图即解码器 bug。**语义层拒绝**（同键 publish 偏序、汇聚类型不可满足）不在解码器
   职责内，走 §6 编译期静态检查，记 `compile_reject`、**不计入 GA1**，但必须报 `compile_reject_rate`
   （高 ⇒ 生成器没学会约束，是 §13 证据候选）。
5. **`EXIT_STOP` 的 mask 条件**：仅当**所有已生成节点的 `required:true` 入端口均已连边**、且收口可达时
   才允许 `EXIT_STOP`；否则该 token 被 mask。**`BUDGET_STOP` 的补齐必须先闭合全部未满足的 required
   入边**（取最小下标、类型兼容前驱），再收口到 `exit`；补齐消耗**计入本任务预算**，并逐次记
   `greedy_completion`。**required 闭合优先于 `MAX_*` 上限**：预算不足时记 `incomplete`，不得产出
   未闭合的图（否则"解码器无漏洞"与 GA1 同时失效）。

**交错解码（与预算配合，缓解尾部偏置）**：`NODE`/`LINK` 交错采样（边可紧跟其端点），模型可显式吐
`EXIT_STOP` 提前收口；预算触顶 ⇒ 吐 `BUDGET_STOP`，用**确定性贪心补齐**（取最小下标合法前驱）收口到
`exit`。**不再"先采全部节点、再采全部边"**——那会让图尾部系统性退化为贪心结构。`EXIT_STOP` 与
`BUDGET_STOP` 都记 `decode_stop_kind` 入轨迹。**每次 rollout 产出的是"闭合图"（所有 required 入边已连）；
预算不足以闭合时记 `incomplete`，不得产出未闭合图**（见上第 5 条）。

**不可行入边的处理（必须写死，否则解码器不定 ⇒ 不可复现）**：分两种情形，不许混：

- **(a) 采样到的边不可行**（模型选的前驱/端口不满足类型兼容，但**存在**兼容前驱）：**不重采、不计
  GA1**，回退贪心——取**最小下标、类型兼容**的前驱补齐，记 `decode_fallback(kind=infeasible_sample)`。
- **(b) 该 `required:true` 输入确实无类型兼容前驱**：非首节点 ⇒ 该 `contract_idx` 在**解码期被 mask**
  （不允许在此生成），记 `decode_fallback(kind=no_compatible_predecessor)`；首节点 ⇒ required 输入只能由
  `entry` 的 typed 供给（§4.2）满足，`entry` 供给里无兼容项同样 mask。**若 mask 后无合法节点 ⇒ 池不变量
  （§4.2）或解码器被破坏：GA1 直接判红**，**不得**回退成空图、也不得静默 `EXIT`（§4 不变量 3：零节点图非法）。
  重采会破坏确定性；判非法会混淆"解码器 bug"与"采样撞墙"；**回退空图会把 bug 伪装成合法 rollout**。
  `decode_fallback` 带 `kind` 进轨迹与诊断列（`no_legal_node` 作为**断言失败**入账，不是正常回退路径）。

**贪心补齐的偏置与公平性**：贪心补齐系统性让"图尾部 = 贪心结构、非模型意图"，关键节点若落尾部会被
破坏。**交错解码（上文）已大幅降低但未消除该偏置**——预算触顶时仍走贪心补齐。因此：① **GA8 所有生成臂**
（自适应 / 随机合法图 / 无搜索纯生成）**共用同一补齐策略**，否则对照不公平；② 每臂必报
`greedy_completion_rate`（被补齐节点 / 总节点），高 ⇒ 编排学不会预算感知或 `MAX_*` 上限过紧（§12-2），
是 §13 升级的证据候选。

### 4.2 语义钉死（四个易混点）

1. **`entry` / `exit` 是虚拟边界，不是契约节点**：不进节点池、没有 `contract_id`、不占预算。
   `entry` 是初始 artifact 的注入点，其 **typed 供给集** `entry_supply = [{type_id, role?}]` 由任务 spec
   声明并 pin（每个任务至少提供 `'artifact'`）；首节点 `required:true` 输入必须能在此集合里找到类型
   兼容项，否则该契约在解码期被 mask（§4.1）。`exit` 触发"交验收"**动作**。
   **池不变量（保证首节点永远可生成）**：池中**必须始终保留至少一个只依赖 `'artifact'`（`inputs` 为空
   或全部可由 `entry_supply` 满足）的 `pure` 契约**（通用兜底首节点）。这是 §4.1"首节点 mask 后无合法
   节点"不可能发生的依据；删除/替换该契约即池不变量被破坏，GA1 判红。
2. **两级验收，绝不可混**：
   - **节点级（过程）** = `Contract.post`：逐步判定，产出 dense 信号、节点级 verdict / 拒绝码、漂移统计。
   - **任务级（终局）** = `exit` 时的**任务级验收器**（仓库状态 + 隐藏测试 + 测试文件哈希），
     产出 `pass@1`（**只有它决定 `S`**）与 `test_pass_fraction`（用例比例，只作诊断列，§0.1 / §12-13）。
   节点级验收器永远不能替代任务级——否则等于让考生自己判卷。
3. **"验收通道"的口径** = `exit` 触发的那一条任务级判分路径（`exec` 跑隐藏测试 + 哈希校验 +
   产物路径回写）。它**不是一个节点**，是一个动作。
4. **`kind` 三值语义**：`pure` = 不触达效果、可纯函数重算（`determinism: exact`）；
   `effect` = 触达端口（`fs`/`exec`/`net`），必须审计回灌；`agent` = 可发起 L2+ 委派（含子图），
   其决策与成本必须留痕。

### 4.3 状态与通信（`GraphState`）

边只说"类型兼容"是不够的——必须写死**边上流什么、谁能读写、状态归谁**。
但**"隔离"不等于"什么都看不见"**：协作者必须能读同一份材料。正确切法是
**可写面隔离、只读面共享**。

```
GraphState = {                          // 唯一状态对象，唯一写者是运行时
  task,                                 // 任务（不可变）
  shared: Record<SharedRef, Artifact>,  // 只读共享上下文（协作面）
  slots:  Record<SlotId, Artifact>,     // 单写者通信槽（点对点数据流）
  budget: { remaining, spent },
  step,
}
Artifact = { id: Hash, type, producer: { node_id, step }, pins? }   // 内容寻址；type ∈ 生产者 outputs
```

**两块状态的分工**

| 块 | 里面是什么 | 谁能写 | 谁能读 | 可见性 |
|---|---|---|---|---|
| `shared` 共享上下文 | 任务 spec、repo 快照、公共检索语料、记忆召回、风格/惯例表、上一轮讨论摘要 | **只有运行时**（初始化、父图、或节点的**显式 publish**） | 契约里声明了 `reads` 的节点 | 显式 read-set，按 scope 继承 |
| `slots` 通信槽 | 节点产物（点对点） | 该槽的**唯一生产者** | 仅入边指向它的节点 | 由拓扑决定 |

**协作者怎么用**：多个节点读**同一份** `shared`（同一 repo 快照、同一任务 spec、同一讨论记录），
各自写**自己**的 slot，最后由聚合节点收敛——"共享大脑、私有工作台"。这是协作可用性的来源，
同时不牺牲归因：谁读了什么、谁写了什么全在契约里声明。

**八条状态规则**

1. **节点不持有跨调用状态**（L0/L1/L2 一律）。L1/L2 的循环变量调用私有、随调用结束销毁、逐步入轨迹。
   想记忆就必须显式落成 artifact 或走外部记忆输入。
2. **四类声明必须齐全**：`inputs`（走边读）、`reads`（读哪些 `shared`）、`outputs`（写自己的 slot）、
   `publishes`（发布到 `shared`）。**未声明的读一律不可见**。
3. **可写面隔离（单写者）**：节点只能写自己 `outputs` 的 slot 与 `publishes` 声明的 shared 键；
   同一 slot 任一步骤最多一个生产者；越界即拒（GA1）。
4. **只读面共享**：`shared` 对声明了对应 `reads` 的节点可见且**只读**，不能就地修改。
5. **发布是受控动作**：更新共享上下文必须走 `publishes` + 运行时执行的发布（原子替换 + 版本化，
   旧版本仍可被轨迹与 `pins` 指到）。发布是**公开事件**：进轨迹、可审计、可撤销。
   **同键发布的偏序铁律（否则重放非纯函数、违反 GA9）**：同一 `SharedRef` 的所有发布节点两两之间
   **必须有拓扑偏序**（§6 编译期静态检查判，无偏序即 `compile_reject`，**不计入 GA1**——该约束是全局的，
   拓扑序语法不保证，故不能在解码 token 期 mask）；节点读 `shared` 键 K 时，看到
   **拓扑上先于该节点且 publish 了 K 的节点中、偏序最后者的版本**——由拓扑唯一决定、**不依赖运行时
   调度顺序**。这是"状态是执行的纯函数"（下文）能在多发布者下成立的必要条件。
   **并行化前置**：多分支/并行下"两两可比"不可满足，故 §13 并行化档上升前，必须先把跨分支 publish
   改为在**显式 join 契约**处合并版本（join 的确定性合并规则见 §14.1），否则并行档不允许开启。
6. **无隐式通道**：不得经文件系统、环境变量、全局模块变量通信。工作区是任务级沙箱、不是节点间通道；
   要传文件产物，就把路径哈希显式写进 slot 或 `shared`。
7. **子图作用域**：L2 子图继承父节点显式传入的 slot 与（可选的）`shared` 子集，内部 slot **不泄漏**到父图；
   返回时只交回 `outputs` 声明的输出位。
8. **值不可变、内容寻址**：写 = 新建 artifact；覆盖 = 版本化。大产物走 blob（只存哈希），对齐四档。

**作用域必须限死（三处，否则跨任务污染 + 重放失效）**

| 项 | 作用域 | 越界的后果 |
|---|---|---|
| `shared` / `slots` / 已发布版本 | **单任务单次执行**（task-scoped） | 跨任务可见 = 任务间污染，且重放不再是纯函数 |
| `memo` 短路 | **单任务单次执行** | 同 `(契约, 输入)` 出现在两个任务时复用产物 = **跨任务答案泄漏** |
| 跨任务持久 | 只能走 **memory def**（显式、版本化、逐次入轨迹） | 想"记住"就必须付"可审计"的代价 |

**成本标量化（消除"四项 cap"与"标量惩罚"的循环引用）**

```
cost_exec(G) = Σ_d w_d · used_d / cap_d,   d ∈ {calls, tokens, tool_calls, walltime},  Σ w_d = 1
默认 w = { calls:0.35, tokens:0.35, tool_calls:0.15, walltime:0.15 }
```

**L2 子图预算**：父节点把 `budget_slice` **转移**给子图（父图剩余同步减少）；子图未用完的部分
**不归还**（避免"用不完就退回"诱发的预算囤积），但入账分开记 `父图消耗 / 子图消耗`。

**为什么这样切**：隔离的真正目的是 ① 可归因（节点行为只由其**声明过的**依赖决定）
② 可重放（状态是纯函数）③ 无隐式竞态。**只读共享一条都不破坏**，而"全隔离"会把协作场景直接掐死；
反过来，可写面一旦共享（全局黑板），三条全废。所以共享只能共享"读"，不能共享"写"。

**状态是执行的纯函数**：`(任务, shared 初值, 拓扑, 池版本, 权重, 种子, 审计回灌) → GraphState`。
重放不产生第二个 state；若有 effect 未回灌而 state 漂移 ⇒ 违反 GA9。
**记忆不是状态**：长期记忆经 `context_policy` 从 `shared` 注入并逐次入轨迹（§3 三级内容）。

**防冗余三条机制**（"3 个 LLM 节点依次回答同一个问题"必须在结构上挡住，不能靠祈祷）

1. **幂等 memo 短路**：调用键 = `H({task_id, contract_ref, 输入 slot 版本向量, 解析后的 reads 版本向量,
   生效 bindings pin, variant_index})`（**`task_id` 必须入键**，不能只靠"存储 task-scoped"的口头约定）。**必须含 `reads` 解析到的 shared 版本**——否则同一任务内
   shared 键被重新 publish 后会命中旧产物（静默错误）。契约 `idempotent: true` 时同键已算过 ⇒
   **直接复用产物、不花预算**（对齐 DataGraphLab 的 `dup` 短路）。**memo 命中时若该节点声明了 `publishes`，
   必须按同一产物重放 publish 事件（版本哈希不变、不额外计费）**——否则下游对该键的读取会解析不到本应存在的
   版本（静默错误）；publish 是产物的纯函数，重放不破坏幂等。`idempotent: false` 的节点必须显式带
   `variant_index`（"我要第 k 个候选"）；**L1 重试由 `retry_policy` 自动递增 `variant_index`**，
   不得裸重试；不带 `variant_index` 而同键第二次调用 ⇒ 判**冗余**并拒绝。
2. **进展强制**：每一步要么产出**新的 slot 内容**，要么产出新信息（verdict / 拒绝码 / 路由决策）。
   两者皆无 ⇒ 冗余步，拒绝调度并计入 `redundant_step_rate`。与 DataGraphLab 的
   `path_excess` / `hasShortcut` 同构——**冗余是可测的，不是感觉**。
3. **单写者 + 显式扇出**：同一 slot 在任一步骤**最多一个生产者**；跨节点写同名 slot ⇒ 拒绝
   （否则"下游读到谁"由执行顺序决定 = 隐式竞态，归因当场失效）。
   要多路回答同一问题，必须**显式建模为扇出-聚合**：输入端口 `cardinality: 'n'` + 一个聚合契约
   （vote / judge / merge）消费全部 N 个产物。于是"3 个节点答同一题"变成一个**可对照的实验因子**
   （N=1 vs N=3 的效果与成本），而不是缺陷。

**router 必须看得见进度**（承 DataGraphLab R7 的教训）：路由/编排的输入必须含**已执行能力集合、
已写 slot 摘要、剩余预算**。DataGraphLab 实测：模型自己学不会"这个已经执行过"——顺序槽把首步路由
提到 0.88，但 step1–3 只有 0.74–0.75，直到把"下一个待执行算子"显式做成特征才追平。
**没有进度特征，重复执行是必然，不是偶然。**

**GA12 状态隔离与共享（门禁）**

- 写未声明 slot、写未 `publishes` 的 shared 键、读未声明 `reads` 的 shared 键、读未入边 slot ⇒ 拒绝。
- **诱饵测试（读隔离）**：往 `shared` 里塞不属于该节点 `reads` 的诱饵字段（含 `expected`、holdout
  任务哈希等敏感键），断言节点输出**逐字节不变**——DataGraphLab G0.4「特征单源零命中」的同构。
- **共享正向测试（协作可用性）**：把同一份 `shared` 材料喂给两个协作节点，断言两者都读到。
  协作不是靠"看不见"实现的——这条是为了防止把隔离做成"信息窒息"。
- 同一步、同输入的重复执行必须产出逐字节相同的 artifact（带回灌效果者除外）。
- 每步读写集与发布事件必须可从轨迹重建：`(step, node_id, 读的 slot/shared 集, 写的 slot 集, 发布事件)`。
  一等事件类型（统一 trace schema，§14.1）：`chosen_instance`、`decode_fallback(kind)`、`decode_stop_kind`、
  `publish`、`memo_hit`、`redundant_reject`、`autonomy_decision`、`budget_event`。

## 5. 控制层（可训部分零 LLM）+ 课程

> **口径**：本节"零 LLM"只指**可训控制层**本身。固定 LLM **编码器**（表示层）与 LLM **manager**（§8）
> 是外挂组件，不计入"控制层"；前者成本按 §0.1 计入预算，后者记外环预算。

三模型 + 课程独立（已拍）：

| 模型 | 输入 | 输出 | 训练信号 |
|---|---|---|---|
| **分解**（含规划） | 任务描述 + 难度向量 + 上下文 | 子目标序列（含目标态） | 蒸馏自搜索/教师的分解；成功轨迹的正样本 |
| **编排** | 任务 + 子目标 + **能力类池** + 历史统计 + 搜索提示 | 拓扑（token 序列 → 受约束解码） | expert iteration：搜索/教师产好图 → 监督蒸馏；**终局稀疏奖励不直接训** |
| **路由** | 当前节点 obs（产物、**已执行能力集 / 已写 slot 摘要**、预算余量） | 出边/候选实现选择 | **节点级验收器**的 dense 信号 + 局部成功/失败 |
| 课程 | 世代统计、失败模式、漂移 | 任务/难度调度 | 外环信号（稀疏，允许） |

**MoE 的归属（已拍：用 MoE，但它只是编排模型的内部稀疏层）**

- **MoE 不是独立的路由器模型**。否则"MoE 路由选能力类"与"编排模型生成含能力类的图"会对同一件事
  各投一票，训练信号互相干扰、归因不出。落法：**MoE 是编排模型内部的一层**（`任务/子目标 → top-k
  专家`），专家输出喂给解码器；**"路由模型"只做图内步进选择**（在已生成的拓扑上选边 / 选实例）。
- 专家 = **能力类（契约）**，闭集 append-only；执行层选择 = 契约 → 实例（§3 实例选择规则）。
- 兜底/未知能力专家必设；负载均衡损失防坍塌；`top-k`、专家数、参数量进版本并计入 MDL 惩罚。
- 陷阱：专家边界**必须**是契约，不能是实例——否则池生长 = 改模型结构（违反 §3 铁律）。
- **契约扩展时的 gate 扩展策略**：gate 输出维度随专家数变化 ⇒ 用**追加式扩展**（旧 gate 列原样保留、
  新专家列零初始化，训练时**冻结旧列**），保证历史能力不被破坏（GA10 的延伸）。整表重训只允许在
  §13 的"容量诊断"档中作为一次独立实验，并登记预期。
- **权重迁移与防遗忘（架构定案）**：arch bump 时除冻结旧 gate 列外，**旧专家权重按专家 id 保持可加载**
  （GA10），新专家独立零初始化；重训只在"被激活专家 + 受影响节点"上做（§7 惰性训练）。每次 arch bump
  必须过一条"旧权重可加载 + 旧金丝雀不回退"的迁移门禁，否则回退旧 `ver`。
- **gate 的信用分配（listwise 序列损失传 gate 偏弱）**：蒸馏主损失是整图 listwise softmax（§7），
  传到每个位置的 gate 决策时信用分配弱、gate 训练易不稳。加**节点级辅助损失**：位置 j 的 gate 选的
  top-k 专家 ≠ 搜索器在该位置选的契约 ⇒ CE 惩罚，作为序列主损失的辅助项，稳定 gate 与专家对齐。
  辅助损失权重进版本并计入 MDL。

**表示层（任务/子目标怎么变成向量，之前完全没写）**

- 自然语言任务与子目标**必须过固定编码器**：结构化字段（难度向量、契约 id、预算余量）走白名单特征；
  自由文本走**固定 LLM 编码器**（`encoder_pin` 进 manifest）。
- **编码器不属于可训控制层**：它的输出只作为输入特征；但它的调用成本**按 §0.1 计入预算**。
- **编码器成本口径（定死）**：编码器是运行时表示层，其调用成本**计入本任务 `B`**（§0.2"cap 第一性"，
  **不得剥离出 cap**）。同一任务在整个实验里**只真正编码一次**（缓存）；为避免先跑的臂承担、后跑的臂
  白拿，**每臂每任务按同一 `encoder_cost` 名义等额计费**（实际调用走缓存），使 `cost_to_solve` 跨臂
  可比。`encoder_cost` 单列报告、**不并入 `cost_exec(G)`**（`cost_exec` 只含图执行）。
- 编码器不参与训练 ⇒ 控制层仍满足"零 LLM、可 CPU 训练、可逐字节重放"；但**它一旦换版本，
  全部历史权重作废**（特征语义变了），所以 `encoder_pin` 必须进 arch 的 fail-fast 检查。
- **编码器贡献必须可归因（否则泛化被算到编排头上）**：frozen LLM 编码器可能承载跨任务语义泛化、
  掩盖编排贡献。GA8⑨「冻结编码器 + 随机编排」臂隔离编码器贡献；归因报告单列"编码器消融列"。
  `encoder_pin` 变更触发的历史世代重跑范围进 §13.1 事故后路（与 holdout 污染同列：编码器语义变 ⇒
  全历史权重作废 ⇒ 重跑受影响世代）。
- **编码器与编排共享、head 独立（架构定案）**：编排模型与路由模型共用同一 `encoder_pin` 特征，输出
  各自独立 head。理由：完全分离会削弱节点级 dense 信号到编排的信用分配；共享特征后仍用 GA8⑨
  「冻结编码器 + 随机编排」臂隔离"编码器贡献"。

**特征不变式（承附录 I.2）**：`NODE_SLOT` 追加式稳定槽；`cand_mask` 变长 bitset；
控制层 dims **与节点实例数无关**；`weights.json` 的 `arch` 记 `{池版本, 图文法版本, 精确 dims}`，
不符 **fail-fast**，禁跨版本静默加载。

## 6. 运行时与自治

**解析执行**：运行时读**已编译的调度计划**（见下"执行前先编译"）→ 逐节点调度 → 节点产出经 typed 校验 → 路由模型选边 →
`exit` 或预算耗尽 → 交验收。**拓扑的唯一来源是编排模型**（L3 除外，见下）。

**拓扑是 AND-OR 图、执行是路由实例化（显式，否则"拓扑 vs 路由"归因边界模糊）**：编排生成的是**条件
超图**（含分支 / 扇出 / 多出边，`binding_mode:'any'` 端口即 OR 候选），路由模型在运行时**为每个 `any`
端口恰选一条边**（§5、§4 不变量 2） ⇒ 实际执行的是超图的**活动子图**（满足 `all` 端口与所选 `any` 边的
最小闭包）。故：`sig(topology)` = **超图签名**（去重 / 对照用）；`pass@1` 测的是**路由实例化执行**，
不是超图本身；GA8⑥「拓扑打乱」测超图携带的信息量，GA8⑦「同图随机路由」测路由贡献——两者**正交**，
须分开归因。默认串行拓扑执行（§0.1 walltime 口径）；并行化列为 §13 阶梯一档。
**执行前先编译（架构定案）**：`GraphDef → 静态类型检查（含 `all/any` 与类型兼容、**同键 publish 偏序**）→
调度计划骨架 → **执行期按路由逐 `any` 端口实例化活动子图** → executor`。**活动子图不能在执行前定死**——它取决于
路由对 `any` 端口的选择，而选择依赖运行时产物；编译期只做静态可判的部分（类型、可达性、上限、publish 偏序）。
静态检查失败记 `compile_reject`（**不计入 GA1**，§4.1）；运行时只执行已编译计划 + 逐边实例化，不做语义兜底（§4 不变量）。

**自治档位（已拍：L2 第一版开）**

| 档 | 节点能做什么 | 约束 | 默认 |
|---|---|---|---|
| **L0** | 纯函数：一次调用出结果 | 无 | 工具节点 |
| **L1** | 内部有界循环：自检、重试、**请求追加输入**、拒绝并给原因、换工具 | 迭代上限 K、预算上限、退出条件由节点参数**声明**（可版本化可回滚） | LLM 节点 |
| **L2** | **子目标委派**：把子目标交回编排模型现场生成子图 | 递归深度 ≤ `MAX_RECUR`、预算切分、子图过同一图文法闸 | 可选节点 |
| **L3** | 自己产出子拓扑（绕开编排模型） | 仍过同一图文法闸 + 同一预算账 + 同一审计流 | **登记待决，先不开** |

**三条自治不变量**

1. **自治只能花预算，不能拿权限**：不得调未声明端口、不得越出已声明 caps。
2. **自治决策必须留痕**：每次"节点自己决定"（重试/请求输入/委派/拒绝/换工具）产出一条记录
   （节点 id、决策类型、消耗、结果）。这是**监控指标层的一等输入**——失败模式聚类直接落在决策流上。
3. **自治不改变可寻址面**：对外仍是 typed 契约；自治是内部实现细节。

**L1"请求追加输入"必须声明式（否则 = 绕过 `reads` 的隐式通道）**：L1 节点能"请求追加输入"，但可请求的
输入键集合必须在契约 `reads` 中**预声明**（可标 `optional`、带"运行时按预算供给"语义）；运行时按
剩余预算决定是否供给。**不许运行时动态请求未声明键**——否则违反 §4.3 规则 2（未声明读不可见），
且让归因（节点行为只由声明依赖决定）当场失效。供给协议进 §14.1「尚未写死」。

**为什么 L3 先不开**：它会让"拓扑唯一来源"破功（一个学的、一个节点现场拍的），归因不清。

## 7. 训练与蒸馏

**搜索的定位（别混）**：搜索是**数据生产手段**（产蒸馏目标），**不是运行时的组成部分**。运行时
默认只跑编排模型的前向；"搜索进运行时"是 §13 阶梯上的一档，不是默认态。

**主路 = search/teacher → 目标 → 蒸馏（expert iteration）**：

```
① 搜索器（MCTS / EA / 有界 beam）在真验收下搜索拓扑
② 好图-任务对入库（只认验收通过；对抗套件前置过滤，防 hack 验收器）
③ 蒸馏进编排/分解模型；路由用节点级验收信号在线校正
④ 用新权重再搜（回到 ①）
```

> 这个闭环的**数据侧规格**（三层数据、四道入库闸、四个消费者转速、三个断点）见 §7.1 数据飞轮。

**搜索空间必须分层（三个变异面耦合搜会爆预算）**

| 层 | 搜什么 | 代价 | 谁做 |
|---|---|---|---|
| 结构 | 拓扑（受约束解码空间内的增删 / 重连 / 分支 / 合流） | 高（每次都要真跑验收） | MCTS / EA |
| 绑定 | 提示词 / 模型 / 解码参数（不占生长额度） | 中（可缓存、可 A/B） | 有界 beam / 网格 |
| 分解 | 子目标序列 | 低 | **只由 llm teacher 与蒸馏产出，不进搜索** |

**MCTS 口径（照此实现）**：`state` = 部分拓扑（受约束解码前缀）；动作**分两层**（先选 motif / 契约，
再选端口），减少昂贵验收次数；**motif** = 池内既有子拓扑片段（含 §8 结晶出的单节点、以及反复出现的
"分解→生成→校验"子图），按 `sig` 规范化后建库，**库构建与规范化规则进 §14.1**；`expand` 只展开过闸的合法扩展；选择用 **PUCT**，先验 = 当前编排策略
（**评估臂可关先验以保持"不依赖未训策略"的对照**），`value` = 验收通过 + 成本惩罚 + 学到的 value head；
`rollout` 兜底仍是**确定性贪心补齐**到 `exit`；`backup` 用访问均值；按 `sig` 建 transposition table；
预算 = 展开次数 + 控制层 token，**记 `ROUND_B`（§0.1、§12-11），不摊进 `cost_exec(G)`**。

**`value head` 不是独立模型**：它是**编排模型的辅助输出头**（与 gate 辅助损失同档），参数量与 MDL
计入编排模型（§5、§12-6），训练信号 = 验收通过 + 成本惩罚；不单列模型、不单列预算、不进 §5 的模型清单。
**EA 口径**：变异算子白名单承附录 I.3（插入 / 删除 / 同契约替换 / 边重定向 / 加 skip / 分支 / 合流 /
early-exit），交叉只在同 **`family_sig`**（节点/契约多重集，§4）内，等价结构按 `sig` 去重。

**蒸馏目标：visit 分布 / 帕累托采样、集合级，禁 one-hot**（多解是本域的结构性事实，不是噪声）

- 搜索对同一任务通常产出**多张同样验收通过**的图（多解）。**用单张图的 one-hot 序列 CE 会摊平**：
  DataGraphLab goal 族的 `safe_action_conflict_rate ≈ 0.999` 同病，且它实测过后果——**均匀软化反而
  掉分**（`0.29 < 0.55` 基线）。
- **软目标按下列优先级取一（写死，不再并存两套权重）**：
  ① **visit 分布（AlphaZero 风格，首选）**：搜索 visit 分布天然非均匀、携带搜索置信，天然满足"禁均匀软标签"；
  ② **帕累托采样（visit 不可得时的退化档）**：从同任务好图集合里按"成本-复杂度**帕累托前沿**"采样——
     前沿上的图**等权**、被支配者降权；损失 = **集合级 softmax（listwise）**；
  ③ 单解任务退化为普通 CE。
- **禁止 `1/(成本×复杂度)` 全集合加权**：它对大图双重惩罚，会蒸馏出"总生成最便宜最小图"的偏置（小图泛化差）。
  必须报"蒸馏目标 `|V|` 分布 vs 搜索产出 `|V|` 分布"，分布系统性偏小 ⇒ 采样过强，调权重。
- **禁止**均匀软标签（有反例证据）；**禁止**只取搜索到的第一个解（会引入搜索顺序偏置）。

**holdout 禁搜**：搜索与 teacher 只跑 dev（§0.2）。这条是 §7 与 §10 GA5 的直接接口。

**信号分层（明确声明）**：

- **dense（主）**：节点级验收器（每节点产物可判）+ 局部成功/失败 + 预算消耗。
- **中（主）**：搜索与 llm teacher 产的图/分解目标 → 监督蒸馏。
- **稀疏（外环）**：会话成败、漂移判定、采纳门禁、课程调度。**不用它直接训编排模型**，
  理由不是"稀疏学不会"，而是：① 采不到正样本时它是**恒零信号**；② 它不给跨节点的信用分配；
  ③ 本域已有 dense 的节点级验收器，用它更省。

**口径修正（2026-09-16，纠上一版）**：曾用 DataGraphLab G2.3 的 follow `0.0000` 论证"稀疏 RL
打不过密集监督"，**该读法作废**。读产物 `runs/phase2-g23-20260914T232039/g23_report.json` 的事实是：
`bc_trained_s0_10k.follow_pass1 = 1`（同批特征，脚本注"同 arch v6"），RL 臂 collected
`10246 rollouts / 174 solved / meanReward 0.0170`，且**报告未按 style 分列**；
follow 需精确轨迹匹配 ⇒ 随机初始化策略几乎采不到正样本 ⇒ **无信号，不是学不会**。
教训：**探索必须被引导**——这正是本实验把搜索器与课程模型列为必需件（而非可选件）、
并把节点级验收器当主信号的原因。

**推论（新增一等可观测量）**：搜索器的**正样本产出率**（`solved/rollout`、`meanReward`）必须进
每次 P3 报告——它决定蒸馏集会不会饿死。DataGraphLab 那次 `174/10246 ≈ 1.7%` 的采集率是
"下游学不到"的直接原因；本实验若搜索器产不出正样本，故障点在搜索器，不在编排模型。

**推论二（expert iteration 退化监控）**：主路（搜索→蒸馏→再搜）是标准 expert iteration，已知陷阱是
**策略与搜索器共退**——策略学搜索器偏置 → 引导搜索器 → 正反馈坍缩到少数拓扑族。须监控并报三个量：
`H(π_policy)`、`H(π_search)`（拓扑族按 `family_sig` 分桶归一化后的香农熵，bits）与
`Ei = D_KL(π_policy ‖ π_search)`（bits）。**共退判据 = `Ei` 与 `H(π_policy)` 同向单调下降**——仅 `Ei`
下降而搜索器仍多样，只说明策略追平搜索器，不算坍缩；触发课程/探索干预。进 P3 报告必出列，与正样本
产出率并列。公式若调整须登记（§14.1）。

**llm teacher 的红线**：teacher 只在 **dev** 上用；**holdout 判分只用隐藏测试**，
**禁用 llm 打分 holdout**（防自欺）。teacher 产出与提案文本一律过泄漏扫描（GA5）。

**惰性训练**：只训被激活的能力类专家与受影响节点；触发条件与预算由外环登记（§8）。
新能力类 = 新专家零初始化槽，**旧专家权重不动**（GA10）。

### 7.1 数据飞轮（data flywheel）

**定义**：飞轮 = "执行 / 搜索产数据 → 数据过闸进训练集 → 训出新权重或新节点 → 新权重产出更好的数据"的闭环。
本实验的飞轮**只在 dev 上转**（§0.2）；**holdout 是只读测速仪，不是燃料**。

**数据三层（版本化、内容寻址，承 §1.1 `data/`）**

| 层 | 对象 | 产出者 | 消费者 | 门禁 |
|---|---|---|---|---|
| **原始轨迹层** raw | 逐次执行 events、审计回灌、预算账 | 运行时（每次执行） | 诊断、重放 | 只增不改；随 run 冻结 |
| **训练集层** train | 「任务→图→结果」三元组、节点级 dense 标签、分解目标、搜索 visit 分布 | 搜索 / teacher / 执行 | 分解 / 编排 / 路由 / 课程四模型 | 对抗套件 + 泄漏扫描 + 去重 + 可重放校验 |
| **评测层** eval | dev / holdout bench、金丝雀集 | 任务生成器 | 门禁、漂移 | 钉死哈希；**holdout 只读** |

**四个消费者与各自的飞轮转速（对应 §5 四模型）**

| 模型 | 吃什么数据 | 反馈时延 | 触发 |
|---|---|---|---|
| 路由 | 节点级验收 dense + 局部成败 | **每步（在线）** | 每次执行 |
| 编排 | 搜索 / teacher 好图集合 + visit 分布 | **每回合（离线蒸馏）** | expert iteration（§7 主路） |
| 分解 | teacher 分解 + 成功轨迹正样本 | 每回合（离线蒸馏） | 同上 |
| 课程 | 世代统计、失败模式、漂移 | 每世代（外环稀疏） | §8 触发条件 |

**飞轮四条不变量**

1. **只在 dev 上转**：训练集不得含任何由 holdout 任务驱动的产物；GA5 在**数据层再判一次**，不只判提示词。
2. **每条训练样本可溯源**：样本 → 轨迹 event → 任务 id → 池 / 权重 / 提示词版本；不可溯源样本不得入集。
3. **入库前过四道闸**：对抗套件（防 hack 验收器）、泄漏扫描、去重（内容寻址两级去重）、可重放校验
   （回灌下逐字节等价）。四道闸的判定式进 §14.1。
4. **转速与退化可观测**：正样本产出率（§7 推论·正样本产出率）、Ei 散度（§7 推论二）、**训练集分布漂移**（新样本 vs
   存量在难度向量 / 契约 / `|V|` 上的分布）三项进每次 P3 报告；散度单调下降或正样本率枯竭 ⇒ **停轮诊断**，
   不许硬转（否则等于用退化数据喂退化模型）。

**三个已知断点（预先声明）**

- **燃料断点**：搜索器产不出正样本 ⇒ 训练集饿死（DataGraphLab `174/10246` 的教训，§7）。
- **反馈断点**：离线蒸馏时延 = 1 回合；回合过长会让路由的在线信号与编排的离线信号脱节。
- **污染断点**：把 holdout 或"为提升而跑"的产物混进训练集 ⇒ 整条飞轮作废（§13.1 事故后路）。

## 8. 进化外环（监控指标层 + 管理 agent）

**监控 = 指标层（非 LLM）+ 决策层（LLM manager）——图外、回合后运行（架构定案）**

监控是**图外、回合后**运行的两层组件。两层职责与实现手段不同，**不可混成一层**：

| 层 | 实现 | 输入 | 输出 | 为什么是这个实现 |
|---|---|---|---|---|
| **指标层（monitor）** | **非 LLM、确定性、阈值可声明/可版本化** | 冻结记录：轨迹 events、defs/events 链、金丝雀滚动统计、预算账 | **证据**：漂移越界、失败模式聚类（typed 拒绝码 / verdict）、覆盖缺口、预算异常 | 门禁与升级触发的证据必须**可复算、可重放、零 LLM 噪声**（GA9/GA11）——LLM 诊断不能充当证据 |
| **决策层（manager，即 `docs/agent.md` §7 的 `agent/proposer`，此处改名 `agent/manager`）** | **LLM（dev-only）** | 指标层证据 + 抽样轨迹 + 池现状 | **提案**：绑定变异 / 实例生长 / 契约扩展 / 结构结晶（**节点池增删全在此**） | "为什么失败、缺什么能力、该加什么节点"是语义归纳，正是 LLM 的长处；每回合一次，成本低 |

- **两层都不在图内**：不是节点、不进节点池、不占 per-task `B`、不写 `shared`/`slots`、执行期零干预。
  `kind:'agent'` 契约只用于图内 L2 委派，不得拿来实现监控或管理。
- **运行时机**：每个**回合结束后**（`ROUND_DEV_N` 跑完；检查点回合另含 holdout 判分），读取**已冻结的只读记录**，
  **不读实时执行流**。决策层的 LLM 调用记外环预算，不占 per-task `B`。
- **manager 只是提案者，不是执行者**：它**不得直接写池 / 写账本**；节点添加一律走
  "证据 → 提案 → 门禁 → 双集门槛 → 采纳（`declare_node` / `declare_capability` / `crystallize`）→ 可回滚"。
- **每条提案必须挂证据 id**（指标层的 `evidence_id`）+ 预注册预期收益；**无证据提案直接拒**
  （禁时钟驱动生长）。manager 永不接触 holdout，提案文本过泄漏扫描（GA5）。
- **两层分签**：指标层只产证据、manager 不能自造证据；manager 只产提案、指标层不能改提案——
  "自己诊断自己改"的自欺入口被结构性堵死。
- **理由**：① 运行时纯函数性不被观测者污染（GA9）；② 外环成本不混进 per-task `cost_exec(G)`；
  ③ "做题者 ≠ 判卷者"在时间上分离——监控无法影响它正在评判的那一轮；④ 回放只需 events，不必重放观测者。

**触发条件（必须先有证据，禁时钟驱动生长）**

| 触发 | 证据 | 动作 |
|---|---|---|
| 能力缺口 | 某能力类在 ≥ N 个 dev 任务上失败，且图内重连无法修复 | 结构搜索（MCTS/EA）或新增节点 |
| 节点漂移 | 金丝雀集滚动统计超界（成功 / 延迟；**校准 ECE 仅对声明了 `confidence` 的契约**，§12-12） | 隔离 / 重训 / 降级（**必留痕**，记 `quarantine`） |
| 会话结晶 | 同一 `sig` 子拓扑在 ≥ k 个 **dev 任务**上**任务级验收通过**（不是节点级 post 通过） | **结晶为单节点**（见下） |
| 覆盖缺口 | 课程某难度档无可用节点 | 课程调度或节点合成 |

**池生长 = 子图结晶**（**唯一使 `H` 下降**的生长方向；实例级生长只是不增 `H`）：把反复出现的稳定子拓扑提升为单个节点，
图复杂度同时下降 ⇒ 生长与 MDL 不冲突（对齐 `docs/agent.md` 的 skill 结晶）。

**世代与回合（缺这个，"跨世代曲线"无从测量）**

- **回合（round）** = 一段固定的 `dev` 批量（`ROUND_DEV_N` 个任务）+ 一次采纳判定。
  **采纳判定要求 `new` 与 `incumbent` 在当轮同一 `dev` 批上共评**（配对检验的前提；代价是 dev 计算翻倍，
  但课程每回合重采样 dev，不共评则"同任务配对"不成立）。
- **holdout 改为注册检查点制**：默认每 `HOLDOUT_EVERY = ESC_ROUNDS = 3` 回合判分一次 + 结论回合判分
  （冻结模型前向），**不参与任何搜索 / 蒸馏**；所有检查点判定用 BH-FDR 校正，判分次数入账。
  非检查点回合只出 `S_dev`，不写 holdout 结论（防反复偷看同一测速仪）。
- **世代号 = 回合号**；每次采纳写一条 `add_ver`，回滚写一条 `set_active`（指回旧 `ver`）。
- 每回合预算 `ROUND_B`（= 各任务 cap 之和 + `search_cost`；运行时控制层 decode 已含在各任务 `B` 内，
  **不重复计入**；holdout 判分成本单列 `holdout_cost`，不计入 `ROUND_B`）随结果入账；
  曲线 = `(回合, S_dev, 检查点 S_holdout, 成本)`。

**适应度与接受闸（可执行口径，承附录 I.4/I.6；`fit` 的 λ/μ 字母分配按 `docs/agent.md` G7，见文首覆盖表）**

```
fit(G)  = pass@1_dev(G) − λ·cost_exec(G) − μ·H(G)
cost_exec(G) = Σ_d w_d · used_d/cap_d   （§4.3 唯一公式，**已归一化到 [0,1]**；**勿再除预算**；不含搜索成本）
H(G)    = (|V|+|E|)/|V_seed|           （|V_seed| = 人工固定图臂 GA8② 的节点数，pin 进 manifest；**H 不归一化到 [0,1]**，
                                        μ 按此量纲取 0.01，勿与 cost_exec 的 [0,1] 混比）
λ = 0.10（成本项；cost_exec 已归一化）、μ = 0.01（结构/MDL 项）   （§12-6，住账本可版本化）
search_cost = MCTS/EA 展开 + 离线控制层 decode   （round 级，进 ROUND_B，单列报告；不进 cost_exec）
接受闸分硬/软（避免进化停滞在"降成本刷分"而非提能力）：
  硬闸（不满足即整轮作废并回滚）：
        dev 配对非劣检验成立：**单侧 CI 下限 ≥ −δ**，累计 `n ≥ max(200, 预注册功效分析所需 n)`
          为前置；**且实测 CI 半宽 h ≤ δ**，否则本回合只记"未判定"（不采纳、不算失败）——
          这条防"h > δ 时硬闸退化为'必须显著更好'"（§12-3）
        且（**仅检查点回合**）S_holdout(new) ≥ S_holdout(incumbent) − ε   （holdout 点估计非降，ε=0.02）
  软闸（入曲线、不阻断采纳）：
        fit(new) > fit(incumbent) + margin                     （cost/H 改进只记账）
        采纳写只增版本目录 + hash 链 + manifest
```

> `H` 用 `(|V|+|E|)/|V_seed|` 而不是"度数分布熵"：它可执行、与 MDL 惩罚同源，且**子图结晶会使它下降**
> （子图折叠成 1 节点 ⇒ `|V|` 减少），正是"生长不增熵"要的方向。
> `pass@1_dev` 用全过口径；`test_pass_fraction` 只作诊断列，**不进接受闸**（防部分通过刷分）。
> **硬/软闸拆分的理由**：硬闸已保证 pass@1_dev **非劣（允许 ≤ δ 的统计噪声内下降）**；fit 的 cost/H 改进**只作软闸**——否则
> pass@1_dev 持平时仅靠 cost 下降过 margin，进化偏向"越练越便宜"而非"越练越能"，且因仍"达标"
> 而不触发 §13 升级。故 **§13 `ESC_ROUNDS` 升级触发改挂 pass@1_dev 严格提升**：连续 `ESC_ROUNDS`
> 回合无严格提升 ⇒ 上升一档，不再以 fit 无提升为触发（防成本优化永久规避升级）。

**课程模型的可执行验收**：课程 = 按难度向量的采样分布策略；判据 = **难度-成功率单调性**
（对齐 DataGraphLab G1.2 的单调性条款）——难度升则 `S_dev` 不增，违反即课程实现有 bug。

**"模型自治"的红线**：控制层**不得在运行时自改自身结构**——那只能走
「提案 → 门禁 → 双集门槛 → 采纳 → 可回滚」。运行时自改 = 没人记录 ⇒ 可回退当场失效。

**提案的 owner（角色分离）**：**指标层只产证据、不提案**；提案由**决策层 `agent/manager`（LLM）**
产出（承 `docs/agent.md` §7 的"做题者 ≠ 改自己者"——manager 不是图内执行体）。两层用 `evidence_id`
接口连接：manager 的每条提案必须引用指标层证据。**提案四类，映射 §3 变异通道三分**：
**绑定变异**（绑定通道）；**实例生长**、**契约扩展**（生长通道的实例级 / 契约级）；**结构结晶**
（契约扩展的特例：契约扩展 + 新实例，且 `H` 下降）。**权重变异不是提案**（走蒸馏 / 微调，§7）。

## 9. 账本与版本（standalone，形状对齐内核）

```
Entry = { seq, prev, op, args, argsHash, by, ref?, at }     // 链式哈希；argsHash 进链
op ∈ { declare_capability, declare_type, declare_shared_ref, declare_node, crystallize,
       publish, memo, put_prompt, put_policy, put_threshold, add_ver, set_active,
       quarantine, note, snapshot, accept }
```

- **回退不是独立 op**：回滚 = `set_active` 指回旧 `ver`，不设 `rollback`，以免出现两套回退机制。
- `declare_capability` 只在**新增契约**时出现（契约 append-only）；已有契约不得再声明。
- `publish` = 共享上下文的受控发布（§4.3 规则 5），必须记 `by`/`ref`，便于审计与撤销。
- `memo` = 幂等短路命中记录（§4.3），让"未重复计费"可证。
- `put_threshold` = **阈值参数**以数据身份入库（§3.1 post 的 (b) 层、§12）；**判定式结构不在此 op**
  ——改判定式 = `declare_capability`（新 `contract_id`）。与"判据改动只影响下一轮"的回合锚配合。
- `put_policy` = **控制层在线策略参数**（如 L1 重试策略、路由选边的确定性优先级）以数据身份入库，
  回合锚下可热改可回滚；**不改契约结构**（改结构走 `declare_capability`）。
- `snapshot` = **run 级 manifest 版本快照**（§1.1 门禁 harness 口径）：把本轮 `world/manifest/fixture`
  的规范哈希钉进账本，供事后重放与只读冻结（§13.1）。

- **两条 append-only 日志，职责分离**：**defs 链**（版本声明：`declare_*` / `put_*` / `add_ver` /
  `set_active` / `crystallize` / `accept` / **`quarantine`**）与 **events 轨迹**（运行期：`publish` /
  `memo` / `note`），以 `run_id` join。重放读 events，版本只读 defs，避免运行期事件污染版本链。
  **`quarantine` 必须在 defs 链**：节点隔离/降级是**池状态变更**，要进 `worldRev`、要能 `set_active`
  回退（§14 红线"所有变更可回退"、GA11）；放进 events 会导致降级不进版本、不可回滚。
- `accept` = **回合级采纳判定**（记两端分数、门禁结论、`evidence_id`；采纳与拒绝都写）；`add_ver` 只在
  实际采纳时追加版本。二者成对，缺 `accept` 的 `add_ver` 非法。
- **真源 = defs 链**；版本目录是派生。`worldRev` 同构 = `H({defs 键集, ids 摘要})`，**摘要不含履历**。
- `declare_type` / `declare_shared_ref`：类型表与 `SharedRef` 键表也是 append-only，须有 declare op；
  `quarantine` 承载 GA11 的"隔离 / 降级必留痕"。
- **pin 全员**：池版本、能力类表、图文法版本、控制层权重、提示词、阈值常量、bench 清单、
  scorer、**回合锚**（本轮判据冻结：改判据只影响下一轮）。
- **回退**：`set_active` 指回旧世代 = 一条追加；**不删任何历史**。
- **效果审计**：每个 `EffRequest→EffResult`（含 LLM 调用、`exec`、文件写）配对一条审计 def，
  被写请求 `ref` 指向；**落盘字节保真**（禁语义往返重写）。
- **可重放**：`(任务, 池版本, 权重, seed)` + 审计回灌下逐字节等价；真 LLM 的不可复现由
  **回灌**表达，不由重跑表达（承 `docs/agent.md` §9）。
- **回滚必须可验证**：回滚后重跑同一任务，**在回灌条件下**必须逐字节复现旧结果；
  回灌缺失时不得声称"回滚成功"，只能记"回滚未验证"。

## 12. 默认值（已定；改动须走"提案 → 记账"）

> 依据：DataGraphLab 既有阈值口径 + 真 LLM 噪声预算 + 本实验的证伪需求。所有数值以数据 def
> 形式住账本，可版本化、可回滚；**调参必须落一条提案与理由，禁静默改**。

| # | 项 | 默认值 | 理由 |
|---|---|---|---|

**评估协议（只有阈值没有协议 = 不可复现）**

- 每臂每档 **累计 `n ≥ max(200, 功效分析所需)` 个任务**（跨回合累计）**且**配对非劣检验成立（dev 配对差值单侧 CI 下限 ≥ −δ **且实测半宽 ≤ δ**）（§12-3）；**`n` 由功效分析定、`n ≥ 200` 是下限，不是替代判据**。严格提升（CI 下限 > 0）另作升级/软闸判据。
- **主命题另立判据**：vs `fixedgraph` 的配对差值**单侧 CI 下限 ≥ Δ**（BH-FDR 校正），点估计并列。
- 臂网格 = **GA8 十一臂**（§10）× **≥ 3 个 seed**；主表先出 5 个主臂
  `{固定图, 随机合法图, 无搜索纯生成, 自适应, 单节点}`，消融臂 ⑥⑦⑧⑨⑩⑪ 按 GA8 补齐（⑩ P3 后、⑪ P4 后）；报每格均值 + CI。
- **配对比较**：**同任务、同 seed 配对，且 `new`/`incumbent` 在同一 dev 批上共评**（§8），报**差值的 CI**；不做非配对均值比较（真 LLM 方差大，
  非配对比较会把噪声读成增益）。
- **断点续跑**（承 DataGraphLab `resume`）：真 LLM run 很贵，任务级结果逐个落盘；续跑与一次跑完
  必须账本等价，且**续跑不得改变结论**——若改变，说明存在未入账的状态。
- 如实红：任何门禁红了就红着记录；**不得**为了让报告好看而重跑直到偶然变绿（重跑次数入账）。

**成本与归因报告（每次 run 必出，缺一即不可采信）**

`S_dev / S_holdout / cost_to_solve（四维帕累托前沿 + 各维中位数）/ incomplete_rate / redundant_step_rate /
greedy_completion_rate / compile_reject_rate / 搜索正样本产出率 / Ei 散度（蒸馏后策略拓扑族熵 vs 搜索器拓扑族熵）/ 训练集分布漂移（§7.1）/
每实例金丝雀统计`，以及**三张分层表**：按难度向量分档、按契约分档、按自治档位分档，**外加编码器消融列**（GA8⑨）。

## 13. 升级阶梯（Escalation Ladder）

> 原则：**关闭的功能不是删掉，是排在阶梯上**。两条上升通道——
> **阶段门**（某阶段验收全绿 ⇒ 解锁下一档）与**失败驱动**（连续 `ESC_ROUNDS` 个回合 **pass@1_dev 无严格提升** ⇒ 上升一档）。
> **一次只上升一档**、必须登记假设与**预注册预期收益**；上升后重跑门禁、必要时 arch bump 重训；
> 每一档都可回退（`set_active` 指回上一 `ver`）。

| 机制 | 起始档 | 上升触发 | 上升后必须做 | 回退 |
|---|---|---|---|---|
| 生长 · 实例级 | 新实例挂**已有契约** | 默认（无需上升） | — | — |
| 生长 · **契约扩展** | 关闭 | 连续能力缺口（≥ `N` 任务）且"实例级"手段全部试过仍不达标 | 新 `contract_id` ⇒ **MoE 专家追加 + arch bump + 重训 + 门禁重跑** | 回上一 `ver` |
| 自治 **L3** | 关闭 | P4 全绿 **且**归因测试通过（**指标层**能区分"编排产拓扑"与"节点产拓扑"） | 归因门禁成为硬前置；L3 产出仍过图文法闸与同一预算账 | 关回 L2 |
| 搜索进运行时 | 关闭（离线） | P3 全绿 且 离线搜索的正样本产出率见顶 | 搜索成本进 `B`；展开顺序确定 ⇒ 运行时搜索仍可重放 | 回离线 |
| 账本迁内核 | 关闭（standalone） | 出现多宿主 / 跨进程共享需求，或"回滚与审计"成为瓶颈 | `Entry` 形状已对齐 ⇒ 只换存储；`verify`/`replay` 接管回滚验证 | 回 standalone |
| 沙箱 | Node 目录隔离 | 出现越权 / 逃逸证据，或需执行不可信代码 | 升 Rust 沙箱 / 容器；`exec` 端口换实现，**契约不变** | 回目录隔离 |
| 扇出上限 | `N ≤ 3` | 出现"多路显著增益且**全计费下**仍划算"的证据 | 上调 `N`；报 N-成本曲线 | 回 3 |
| 并行化拓扑执行 | 关闭（串行，§0.1） | 串行 `walltime` 成为瓶颈，**且**跨分支 publish 已改为在显式 join 契约处合并版本（§4.3） | 并行执行；并行度进 manifest；`walltime` 改有效挂钟口径；报并行度-成本曲线 | 回串行 |
| 控制层容量 | 专家 ≤ 32、参数 ≤ 2M | **容量诊断**（欠拟合证据），而不是仅"不达标" | arch bump + 重训 + F1–F4 | 回旧 arch |
| 多 agent 角色分离 | 指标层 + 单 manager | P5 全绿 | 诊断（证据）/ 提案 / 做题三方分离，成为结构前置 | — |

**禁止**：同时上升两项（归因不出）；跳档（跳过中间档）；把"不达标"直接当成"该上升"——**必须先是可署名
的失败证据**（能力缺口 / 漂移 / 覆盖缺口），并登记假设与预期收益，否则就是在给系统加旋钮而不是做实验。

> `ESC_ROUNDS` 的 pass@1_dev 停滞是**检测信号**而非可署名证据本身：它触发"进入诊断"，但表格里任一
> 档的**上升**仍须先定位到能力缺口 / 漂移 / 覆盖缺口并登记预期收益——停滞本身不许直接当成"该上升哪一档"。

**与 DataGraphLab 课程序同源**：DataGraphLab 计划 §7 的课程序（轨迹约束 → 自模仿过滤 → KD）就是"上一个
杠杆不达标才开下一个"。本实验把它一般化为阶梯，并把每一档的**上升前证据**写死。

### 13.1 负结果与事故的后路（预先写好，免得事后找借口）

- **负结果处置**：若 GA8① 单节点臂打平 ⇒"编排有增益"**判负**。处置不是删档，而是**缩小声明**：
  改为"在 ≥ 某难度档 / 某任务族上编排有增益"，并给出**分层归因表**；若分层后仍无一处增益 ⇒
  结论为"编排在本域无效"，照实发表，并触发**域侧复查**（任务难度分布是否根本不产生编排收益），
  而不是继续加旋钮。
- **holdout 污染事故**（GA5 红）：① 标记该 holdout 版本作废 ② **重建新模板族** ③ 全部历史世代在
  新 holdout 上重跑（贵但必须）④ 账本留 `note` 记录事故范围。**不许**"只重跑受影响的部分"。
- **编码器版本事故**（`encoder_pin` 变更）：特征语义变 ⇒ 全历史控制层权重作废。处置：① 标记受影响
  世代 ② 从受影响世代起在**新 `encoder_pin`** 下重训 + 重跑门禁 ③ 不可只重跑"看起来没事"的部分。
  与 holdout 污染同列（都是"语义地基变了"，必须整段重跑）。
- **预算耗尽 ≠ 失败**：任务在 `B` 内未完成记 `incomplete`（与 `fail` **分开统计**），既进 `S@B`
  的分母，也单独报 `incomplete_rate`；否则"提前停"与"做错"被混为一谈。
- **真 LLM 不可用**（下架 / 限流枯竭）：① 走 §12-4 降级链 ② 门禁与回归**全部回放到 stub**；
  live run 排队等配额。**不得**因端口不可用而降低门禁。
- **运行时自身也要 pin**：不只池 / 权重——`runtime` 进程代码、依赖锁文件、`exec` 沙箱镜像一律进
  manifest。否则"回滚到旧 `ver`"只回滚了数据、没回滚执行体。
- **结论依赖的 run 必须可冻结**：任何被写进结论的 run 目录**只读**；后续重跑写新目录，
  旧的原地不动（DataGraphLab 的"run 级 manifest + 只增不改"口径）。

## 14. 红线

- **不改测试**（GA4）、**不手写 `passed`**、**阈值由机器从指标重算**。
- **回合锚**：本轮评分引用钉死的 bench/scorer 哈希；提案改判据只影响下一轮。
- **holdout 绝不进**提案上下文、蒸馏集、提示词、记忆召回；**禁用 llm 打分 holdout**。
- **禁时钟驱动生长**：一切结构/池变更必须先有可署名的能力缺口或漂移证据。
- **禁运行时自改控制层结构**（只能走提案 → 门禁 → 采纳 → 可回滚）。
- **所有变更可回退**：一次变更 = 一条 `Entry`；回滚 = 一条追加，不删历史。
- **绝对性能数字不入规格文本**：只写比率、量级与测机。
- **如实红**：任何门禁红了就红着记录，先登记后扩展，不放宽断言、不改阈值。
- **无证据的增长**：一切采纳必须落一份 run + manifest；说不清来源的变化不许合并。
