# 内核之后的阶段开发（暂不用看）

前置：`docs/kernel.md` 的 P0–P2 完成（内核可跑：建世界 / 写内容 / 重放 / 机械校验 / 求值 / 发射效果）。

本文件只回答一件事：**从那之后，按什么顺序做什么。** 每阶段以"**新动词能跑起来**"定义，不以"架构更完整"定义。

---

## 0. 排序依据（三条规则）

| # | 规则 | 违反会导致 |
|---|---|---|
| R1 | **先驱动，再内容** —— 没有宿主循环，世界里的内容既写不进去也跑不起来 | 内容无处可放，只能先堆框架 |
| R2 | **先确定性，再不确定性** —— 判定标准必须在没有随机性的世界里先稳住 | LLM 一进来，"同输入同评分"不再成立，你连自己有没有变好都不知道 |
| R3 | **先能判断，再能改** —— 没有判定标准的自进化等于自毁 | 系统朝任意方向乱改，且无法察觉 |

两条推论：

- R4 **先闭环，再规模**：先跑通一次完整的「观测 → 归因 → 提案 → 采纳 → 回滚」，再谈多候选、多实体。
- R5 **先无特权，再生态**：第一方的代码与数据一律走外来路径，接口才经得住第三方（`kernel.md` §2「第一方内容无特权」）。

---

## 1. 阶段总表

| 阶段 | 新动词 | 一句话交付 | 关键判据 |
|---|---|---|---|
| **S1** 驱动 | 跑起来 | 最小宿主：调 `run` → 执行效果 → 回灌 → 落盘 / 载入 | **跨进程续跑**：进程 A 挂起落盘，进程 B 恢复跑完，结果与一次跑完逐字节一致 |
| **S2** 内容 | 写进去 | 第一份数据包：宏 + 一个执行器 + 1–2 份 schema | 一个确定性回合能跑完，且**宿主代码零增长** |
| **S3** 评分 | 判断 | 确定性判定标准 + 证据记录约定 | 同输入两次评分相同；改一个定义，评分变化可归因到那一次改动 |
| **S4** 自改 | 改自己 | 提案装配 + 审核回路 + 写请求 + 回滚（**无 LLM**） | 一次完整闭环走通；驳回后世界逐字节未动；回滚后 `worldRev` 等于记录值 |
| **S5** 接外 | 接真实世界 | `model` 端口 + 能力表 + 装载器（只为代码插件） | 真实模型回合；**卸载全部第一方代码插件后测试仍全绿** |
| **S6** 看见 | 观测 | 观测流 → 最小界面（回合 / 谱系 / 判决 / 一键回滚） | 界面状态全部可派生，**刷新即重建，无第二真源** |
| **S7** 学习 | 学 | 样本导出 + 训练器（外部，经端口）+ 新世代回灌 | 同身份 A/B 两世代在同一 held-out 上，B 显著更好才许采纳 |
| **S8** 生态 | 接别人 | 插件声明约定（共享 schema）+ 授予 + 空能力试跑 | 一个**我们没写过**的插件，能在同一门禁下装、用、卸、回滚 |
| **S9** 交付 | 出品 | 安装 / 升级 / 会话 / 命令面（全是投影） | 升级可一键回退；用户可见面不含内核词 |

**关键路径 = S1 → S2 → S3 → S4 → S5。** 走到 S4 末，**自进化第一次真实存在**——而且是在一个没有不确定性的世界里跑通的。

---

## 2. 逐阶段

### S1 · 驱动（最小宿主）

**目标**：让内核动起来，并且能跨进程续跑。

**最小交付**（`packages/host-min/`）

| 文件 | 职责 |
|---|---|
| `drive.ts` | 循环：`run` → 若有 `pending` 则执行 → 把结果并入 `results` → **同 `run_id` 再调** → 直到 `done` / `refused` |
| `persist.ts` | `world` 与 `journal` 落盘 / 载入（文件即可，先不引数据库） |
| `ports-stub.ts` | 端口桩：记录被调用的效果并返回固定值 |
| `index.ts` | 导出面 |

**判据**

1. 进程 A：跑到挂起 → 落盘 → 退出；
2. 进程 B：载入 → 回灌结果 → 跑完 → 落盘；
3. B 的结果与"一次跑完"**逐字节一致**（含 `journal` 逐条）。

**主要风险**：宿主开始写领域逻辑。
**纪律**：宿主只做四件事——调 `run` / 执行效果 / 落盘 / 载入。**任何"业务判断"都不许出现在宿主里。**

**不做什么**：不做插件装载、不做界面、不做并发、不做多进程调度。

---

### S2 · 内容（第一份数据包）

**目标**：世界里第一次有可运行的东西，而且**它是数据**。

**最小交付**：一份 JSON 数据包（经一次 `batch` 写入世界）

| 内容 | 说明 |
|---|---|
| 宏（约 10 个 term） | `and` / `or` / `not` / `eq` / `lt` / `cat` / `len` / `let` 等，全部由 8 原语派生 |
| 一个执行器定义 | 用 term 写的最小状态机：读上下文 → 算 → 写输出 |
| schema ×1–2 | 例如「执行器」与「判定标准」两份，供后续按类型查询 |

**判据**

1. 数据包作为**一条 `batch`** 写入（日志里只有一条 entry）；
2. `eval` 执行器，产出确定输出；
3. **宿主与插件代码行数为零增长**——内容全在数据里。

**主要风险**：宏写不出来就想加原语。
**纪律**：加原语必须先证明它**不可由现有原语派生**（`kernel.md` §12.1）。

**不做什么**：不引入 LLM、不做图、不做工具调用。

---

### S3 · 评分（判定标准 + 证据）

**目标**：能回答"这次执行好不好"，并且答案可复现。

**最小交付**

| 内容 | 说明 |
|---|---|
| 判定标准（term） | **确定性**评分器：只看公开产物，不看内部中间量 |
| 证据约定 | 每次执行产出一条记录，带 `pins`（它依赖的绑定）与 `sig`（兼容性签名） |

**判据**

1. 同输入两次执行 → 评分相同；
2. 改一个定义 → 评分变化**可归因到那一次改动**（用 `stale` 把受影响的旧证据隔离）；
3. 判定标准本身的每次修改，都留下"为什么改"的记录。

**主要风险**：评分器有漏洞，进化会**合法地**往漏洞里长。
**纪律**：**判定标准是一份普通数据，但它不能被"顺手"改**——改它要单独走一次提案（见 S4）。

**不做什么**：不引入 LLM（LLM 参与评分放 S5 之后）。

---

### S4 · 自改（审核闭环，无 LLM）

**目标**：**在没有不确定性的世界里把自进化闭环跑通。** 这是整个路线的重心。

**最小交付**

| 内容 | 说明 |
|---|---|
| 提案装配 | 从证据 → 候选改动（先由测试或人显式发起，不做自动触发） |
| 审核回路 | 批准端口：可自动（阈值）可人批——**两者在内核眼里只是端口** |
| 写请求装配 | 审核通过后组装 `WriteRequest`，交给内核 |
| 回滚 | 把 `active` 指回旧世代 + 追加一条 entry |

**判据（本路线最重要的一组）**

1. 一次完整闭环跑通：观测 → 归因 → 提案 → 审核 → 采纳 → 评分变化；
2. **驳回后世界逐字节未动**（`worldRev` 不变）；
3. **回滚后 `worldRev` 等于回滚前记录的值**，且世代链长度不变；
4. 重放整段历史得到同一世界；
5. 判定标准（阈值 / 评分器）必须**先于提案存在**于世界。

**主要风险**：提案方自己定及格线。
**纪律**：及格线在提案之前就固定；改及格线要单独走一次提案（这正好是 S3 §3 的要求）。

**不做什么**：不做 LLM、不做多候选并行、不做自动触发、不做调度。

---

### S5 · 接外（端口 + 装载）

**目标**：接真实世界，同时**第一方仍无特权**。

**最小交付**

| 内容 | 说明 |
|---|---|
| `model` 端口 | 真实模型；协议级 JSON，不 import 任何厂商 SDK |
| 能力表 | 每次调用一份，项无法构造能力 |
| 装载器 | **只为代码插件服务**（数据插件不需要装载） |
| 一个第一方适配器 | **走与第三方完全相同的路径** |

**判据**

1. 真实模型回合；
2. **把全部第一方代码插件卸载，内核与 S1–S4 的测试仍全绿**（这是"第一方无特权"的可测形式）；
3. 未授权端口调用被拒。

**主要风险**：不确定性涌入，破坏 R2 建立的"同输入同评分"。
**纪律**：把不确定性**收进一个效果**（端口后面），效果之外的世界仍是纯的。

**不做什么**：不做生态分发、不做完整沙箱（先做最小隔离）、不做工具市场。

---

### S6 · 看见（观测 / 界面）

**目标**：人能看到一次自我修改发生并一键退回。

**最小交付**：观测流 → 最小界面：回合列表 / 谱系视图 / 判决视图 / 一键回滚。

**判据**：界面里的一切都由 `observations` 与世界派生；**刷新即重建，不存在界面自有的状态**。

**主要风险**：界面自建状态 → 出现第二个真源（这正是历史上一切漂移的起点）。
**纪律**：界面不许有"它自己知道的东西"。

**不做什么**：不做主题、不做多语言、不做仪表盘、不做设置项收集。

---

### S7 · 学习（训练回路）

**目标**：从多世代样本里得到更好的世代。

**最小交付**

| 内容 | 说明 |
|---|---|
| 样本导出 | 按「身份 × 世代」归因，带兼容性签名，**用 `stale` 过滤** |
| 训练器 | 外部代码，经端口调用（内核不碰训练） |
| 新世代回灌 | 训练产物作为新世代载荷，走正常审核 |

**判据**：同一身份的 A/B 两世代在同一 held-out 上，**B 显著更好**才允许采纳；签名不兼容的样本拒绝迁移。

**主要风险**：样本污染 / 过拟合到评分器。
**纪律**：绑定一变，旧样本立即标记 `stale` 并隔离（内核已给判定，纪律在 S3 的证据约定里）。

**不做什么**：不做分布式训练、不做在线强化、不做自动调参循环。

---

### S8 · 生态（第三方接入）

**目标**：第三方插件与第一方**同权同路**。

**最小交付**

| 内容 | 说明 |
|---|---|
| 插件声明约定 | 一份共享 schema：能力需求 / 依赖 / 度量契约 / 兼容性签名 |
| 授予与试跑 | 空能力试跑 → 审核 → 授予能力 → 每次调用留痕 |
| 卸载 | 与数据插件走同一套身份/世代记账 |

**判据**：一个**我们没写过**的插件，能在同一门禁下装、用、卸、回滚。

**主要风险**：供应链。
**纪律**：版本 pin + 空能力试跑 + 每次调用留痕 + 可一键卸载。

**不做什么**：不做市场、不做评分排行榜、不做自动升级。

---

### S9 · 交付（产品）

**目标**：交付给人用。

**最小交付**：安装 / 升级 / 会话 / 命令面——**全部是世界的投影**。

**判据**：升级可一键回退到上一版；用户可见面不含内核词。

**主要风险**：产品需求倒逼内核长词。
**纪律**：产品需要的新概念一律落在世界内容里（`kernel.md` §2 的名词/动词规则）。

**不做什么**：不为产品需求往内核加任何概念。

---

## 3. 每阶段通用门禁

三条，全部可测：

| # | 门禁 | 判据 |
|---|---|---|
| G1 | 交付质量 | `prettier --check` 零差异、`tsc --noEmit` 零错误、测试全绿（`coding-standard.md` + `code-review.md` 预检口径） |
| G2 | **第一方无特权** | 本阶段新增的第一方代码插件，**全部卸载后测试仍全绿** |
| G3 | **业务逻辑不许写进宿主** | 本阶段新增的"判断/规则/流程"，其实现位置是**世界内容**；宿主与插件代码行数零增长（S5 的适配器除外，且它走端口路径） |

G3 是最容易失守的一条，也是唯一能防止"内容为空、框架先行"的机制。

---

## 4. 明确不排期

以下都是**世界内容的一种**，不是能力前提。它们可以在任何阶段之后作为一份数据包出现，不需要提前留位：

- 多实体协作（两个身份各自有谱系、样本不串——能力上 S4 之后就已具备）
- 图 / 流程 / 拓扑形态
- 领域算子与专用工具
- 界面主题、多语言、仪表盘
- 插件市场与排行
- 分布式与并发

> 判断标准：**如果它写进世界内容就能实现，就不要为它改任何代码。**
