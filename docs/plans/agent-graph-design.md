## 一、定位：产品的 agent 图不是实验的 agent 图

没有"agent 插件"这一个东西可设计——`docs/plugins.md` §一 已写死 `agent engine = 宿主 + 全部插件 + 世界`，
**无特权插件**；角色类能力（分解 / 评审 / 课程 / 效果评估 / 交接）是 **#33 图里的节点**，`#35 agents` 只是
模板 / 实例 / 通道的**数据索引**。

**三条结构差异（由内核决定，不是选择）**：

| | 实验 | 产品 | 根据 |
|---|---|---|---|
| 拓扑来源 | 编排模型现场生成（受约束解码） | **写期生成**：上一轮 run 产出写计划 → 下一 run 执行 | `kernel.md` §十三「运行期造不出新 def、算不出新哈希」 |
| 回合内自适应 | 拓扑级 | **只到走哪条边**：图固定于数据世代，实际路径由条件现场定 | 同上；选边不造新 def |
| 控制层 | 可训小模型（三模型 + MoE + 蒸馏） | **无**。判定是**服务内声明式规则**（#33 服务求值），图/阈值是数据 | 无权重世代通道；判定必须是数据（`kernel.md` §三） |

⇒ 产品的自进化 = **结构与数据的进化**（图 / 契约 / 提示词 / 阈值 / 实例 / 人格 / 技能 / 插件源码），**不训权重**。
实验那套搜索 / 蒸馏 / visit 分布 / δ-ε-BH-FDR / dev-holdout 分离**全部不搬**。

**借用的五条**：① 两层分签；② 禁时钟驱动生长；③ 提案必挂 `evidence_id`；④ 采纳与拒绝都落账；⑤ 子图结晶。

## 二、为什么必须分段执行（这条推导定了整套形状）

`kernel.md` §十二 三个硬事实叠起来定死了执行形状：

1. **单 pending**：同时挂起多个效果语义上不可能 ⇒ 一次 eval 内**不能并行**。
2. **不捕获续体**：一个 directive 内 k 个效果 ⇒ 每次续跑重放前缀 ⇒ **O(k²)**。
3. **纪律明写**：效果放叶子、长循环拆多 directive。

这三条只约束**宿主 run**。图执行已改由 **#33 execute 服务自驱**（见顶部修订），故不受 O(k²) 约束：

```
interpret(bag)：
  loop:
    读图数据（#14 入口 term 读投影后随 bag 传入）
    → 解析当前节点 → 求值 pre → port.call 节点能力类（发出者 = #33）→ 求值 post → 按 when 定下一节点
  到 sink：返回计划值（write(batch: session gen + trace)）交 #14 入口 term 作顶层 $directives
```

四条收益，缺一条形状就不对：

- **不产生宿主 eval 重放**：图遍历在服务内，节点经 `port.call`（反向调用）派发；游标 / slots / shared 是服务进程内状态，不落账。
- **游标不进世界**：只有回合尾一次 `write` 落账 ⇒ 逐步推进**零世界增长**。
- **图数据随 bag 传入**：#14 入口 term 读投影后交给服务（服务不读投影），段间可见新落账内容。
- **审批往返天然成立**：`enqueue` 正常返回、本 run 结束；游标写入队列项后由宿主触发**新 run** 恢复（#32 既定口径，不是内核 `waiting`）。

**代价（明写）**：改 `pre` / `post` / `when` 判定代码 = 换 execute = 换代；图 / 阈值数据仍住数据世代、可热改可回滚。
**产物两档**：小产物服务内存传递；大产物段尾 `write` 成 def、后续按哈希经 `refs` 引用（阈值住数据）。

**服务内节点不并行（v1）**：`interpret` 顺序跑完 N 路 + 聚合节点，N 路全计费；**run 之间可并发**（threads-design §二：run 级并发 + 提交队列 + 乐观校验，锁收窄为 commit 期间）。

## 三、控制流：推式条件边

**先作废一条口径**：本文早期版本照搬实验的拉式惰性（从 sink 反向 demand、`any` 端口先选边再求值前驱），**已作废**。

理由具体：实验的路由是**可训模型**，obs 刻意排除候选产物内容，为的是让 OR 在**搜索**场景真省预算。
产品没有可训路由，且回合里最核心的那个决定——**模型这次要不要调工具**——只有看了模型的**实际输出**才知道。
拉式惰性在候选产出**之前**选边，结构上表达不了它。

**采纳：推式前向执行 + 条件边。**

```
edges: [{ from:[u,out_port], to:[v,in_port], when?:"<规则名>" }]
```

- `when` 是**服务内声明式规则引用**（与 `pre`/`post` 同形），入参 = `u` 的产出 + 状态摘要；缺省 = 无条件。
  #33 服务内置几个种子判定（`nonempty` / `eq` / `verdict_is`），复杂条件作为规则数据登记（求值器住 execute）。
- 执行：从首节点前推，每步按**已求值**的产出算 `when`，只沿成立的边走。
- **OR 仍真省预算**：没走的分支 0 计费、不进执行流，只记一条聚合计数（`branch_not_taken`）。
  推式比拉式**更 informed**——用真实产出判，不用静态特征猜。
- `binding_mode` 语义随之变准：`all` = 所有入边都会触发（AND 汇聚）；
  **`any` = 恰有一条入边会触发**（互斥分支汇合），`cardinality=1`。这是控制流的**结果**，不再是一个路由决策。
- **"多路都跑再挑"仍必须显式建模**为 `cardinality:'n'` 的 `all` 端口 + 聚合契约（`vote`/`judge`/`merge`），N 路全计费。
  两套机制语义不同、不可互相顶替——这条从实验借来，与推/拉无关。

**可重放性不受影响**：活动路径由 `(拓扑, 各节点实际产出)` 唯一决定；LLM 产出不确定，但
**`eff_log` 回灌配对下的等价**（`kernel.md` §十四：端口结果照单回灌）。**#33 服务自驱：节点经 `port.call` 派发、不入世界审计（`protocol.md` §2.4）；每步记 `eff_log`、回合尾随 trace 落世界；shadow / post dense 信号以 `eff_log` 为底座（2026-09-20 修订）。** 产品的可重放承诺本来就是"回灌下等价"，不是"重跑等价"。

**DAG 保留**（不因推式就放开环）：无环买到三样——单写者 slot 键唯一、publish 偏序可静态判、
"一条路径上任一节点至多执行一次"。环会让这三条同时失效，而终止性已由 `MAX_STEPS` + `gas` 保证，
放开环换不到东西。**循环靠图重入表达（§7），不靠环。**

### 3.1 拒绝的控制流：短路到 sink（写死）

Scope 的出口只有两种（§8.1）：过 `post` 的 `outputs`，或带码的 `refusal`。**拒绝后怎么走必须定**，
否则"出口只有两种"落不完整。

**口径：Scope 拒绝 ⇒ 解释器直接跳 sink，带拒绝码收口。** 不需要在图里为每个 Scope 画一条拒绝出边。

- sink（`turn.commit`）收到的是 `refusal` 而非正常产物 ⇒ 落一条带错误的消息（#11 既有的
  `system` 消息 + `meta.error` 形状），回合正常结束、**不是 run 失败**。
- **未求值的 Scope 记 `branch_not_taken`**，与条件边未触发同一口径、0 计费。
- **`trace` 必须记 `refused_at`**（`node_index` / `iter` / 拒绝码 / `attributable_to`）——
  这是这条让步的**补偿**：图里看不见拒绝路径，但轨迹里必须能完整还原。

**这是对"数据流完全由拓扑决定"的一处明确让步**（不掩饰）：拒绝跳转是解释器的隐式控制流，不在图里可见。

接受它的理由：拒绝的处理逻辑是**统一的**（收口 + 落码 + 记轨迹），不值得在图里重复表达 N 次。
种子图 6 个节点已有 9 条边；若每个节点再接一条拒绝边会到 15 条，而这 6 条边做的是同一件事。
让步的边界也很清楚——**只有拒绝短路是隐式的，正常产物的流向 100% 由边决定**。

**需要"拒绝后走别的路"怎么办**（例如 `code` 拒绝后想转 `clarify` 而不是收口）：
那不是拒绝，是**互联**（§8.2）——Scope 产出一个"请求跳转"而非"我做不了"，走 `links` 白名单。
两者语义不同：拒绝 = 这条路走不通了；互联 = 换条路继续走。

## 四、核心概念统一：节点 = agent = 作用域

**这是本文最关键的一条口径，它让好几个机制同时塌成一个。**

```
Scope = 节点 = agent = 一个可寻址的执行单元
```

一个 Scope 有四样东西，缺一不可：

| 组成 | 是什么 | 住哪 |
|---|---|---|
| **契约** | 能力边界：inputs/outputs/reads/publishes/effects/pre/post | `#33 contracts` 条目 |
| **人格** | 是谁：system_prompt / model / decoding / 偏好工具 | `#35 agents` instance 条目（被 `bindings.agent` pin） |
| **实现** | 怎么跑：`atomic`（一次 eff）或 `composite`（内含子图） | `#33 nodes` 条目的 `impl` |
| **边界** | 能看见什么、能改什么：读可见性 + 写面 + 权限 | 契约声明 + 解释器强制 |

**四个此前分立的概念现在是同一个东西的不同粒度**：

| 你原来说的 | 在统一口径里是什么 |
|---|---|
| 子代理 | 一个 Scope（`impl:atomic`，带人格） |
| 协作者 | 多个同层 Scope 读同一份 `shared`（§7.4 通道 + §5.2 隔离） |
| 子图 | 一个 Scope（`impl:composite`，内含子图） |
| 工作流 | **顶层 Scope 的子图**（不再是"另一张图") |

**四条直接收益**：

1. **选图机制整个消失。** 早期版本需要 `graphs` tail + `Graph.trigger` + run 首选图 term。现在只有**一张图**，
   "专门化"表现为顶层某个 `composite` Scope 内部的子图，进不进它由 `when` 边条件定。
   ⇒ 少一个机制、少一处不确定、少一类"选错图"的故障。
2. **`composite` 从特例变通则。** 早期版本里 `composite` 只是结晶产物（特例），现在它是"有子图的 Scope"，
   结晶只是**自动**产生 composite 的一条路径，手工"加一个工作流"是**另一条路径**，两者同形。
3. **隔离有了统一的单位。** 早期版本的隔离规则散在 slots/shared/权限三处，现在一律按 Scope 边界表述（§5）。
4. **自治与互联有了统一的作用域。** 你指出的两个病症正是因为原来它们的作用域没定（§8）。

**统一的代价（明写）**：所有东西都是 Scope ⇒ 必须靠 `impl` 与 `depth` 区分粒度，
否则"一个节点"与"一整条工作流"在数据里长得一样，UI 与报表会分不清。故 `nodes` 条目必带 `impl` 与
（composite 时）`subgraph`；深度按子图深度折算进 `MAX_DEPTH`（否则反复结晶可无限绕开深度上限）。

### 4.1 Scope 的数据形状

```
Scope（= #33 nodes 条目）= {
  node_id, contract_id,
  impl: 'atomic' | 'composite',
  entry?:    {cap, method},           // impl=atomic：派发目标（能力类 + 方法，按 #33 pins 路由）
  subgraph?: {nodes, edges, sink},    // impl=composite：内部子图（同一图文法，递归）
  bindings: { agent?, prompt?, model?, decoding?, tools?, context_policy?, retry_policy? },
                                       // 每项都是 {"def":hash}；agent pin 到 #35 实例
  autonomy: L0 | L1,                   // 见 §8
  links?: [<contract_id>…],            // 互联白名单，见 §8
}
```

- **`bindings` 必须 pin 不内联**（规矩 A）：内联提示词 ⇒ 改一个词就换 `H(Scope)` ⇒ 池里多一个节点
  ⇒ **提示词 A/B 与漂移归因当场做不了**。pin 住之后可问"同一 Scope、同一图、只换 `prompt`，成绩变多少"。
- **`entry` = 能力类 + 方法**，节点经反向调用 `port.call` 派发（发出者 = #33，按 #33 `pins` 路由）。
  写期机械校验：`effects.ports` ⊆ #33 `pins`，否则**拒绝写入**（把"运行时才炸"提前到写期）。
- **同契约多实例的选择规则（必须写死，否则不可复现）**：图里只写 `contract_id`，不写 `node_id`；
  运行时按字典序 `(隔离升序, 成功率下界降序, cost 升序, node_id 升序)` 取首，记 `chosen_instance`。
  A/B 必须**强制指定实例**，否则绑定效果与实例选择混淆。

## 五、作用域隔离：图通用，工作区信息隔离

**口径（写死）**：**图是通用的，不按工作区分叉。** 切工作区 / 切会话隔离的是**信息**，不是**结构**。
理由：结构按工作区分叉会让每个工作区的样本量除以 N ⇒ 证据永远攒不够 ⇒ 进化环空转；
而工作区之间真正不同的是**材料**（代码库、惯例、技术栈），不是**流程**（想 → 做 → 验 → 交）。

但"图通用"必须配一个机械强制点，否则会出现你指出的问题：**A 工作区专门适配的 agent / 子图被 B 工作区用上**。
只靠边条件 `when` 写对不够——那是"靠纪律"。

### 5.1 `scope` 字段：专门化的机械边界

Scope 与 `#35` 人格、`#36` 技能都带 `scope`：

```
scope: { kind: 'global' | 'workspace' | 'session', workspace_id?, session_id? }
```

| `scope.kind` | 可见范围 | 典型内容 |
|---|---|---|
| `global` | 所有工作区 | 通用流程节点（assemble / step / gate / dispatch / commit）、通用子代理 |
| `workspace` | 仅 `workspace_id` 匹配时 | 该项目专属子代理（"本仓库的 Rust 评审员"）、专属工作流 |
| `session` | 仅该会话 | 一次性实验性 Scope（不进长期结构） |

**强制点在实例选择，不在边条件**（这是关键）：

- 解释器按 `contract_id` 选实例时，候选集**先按 `scope` 过滤**：
  `scope.kind='workspace'` 且 `workspace_id ≠ 当前会话的 workspace_id` ⇒ **不进候选集**。
- 过滤在**实例选择**这一步，是机械的、不可绕过的；`when` 写错最多走错分支，**不会**让 B 工作区用上 A 的专属 agent。
- **池不变量补一条**：任一契约必须至少有一个 `scope:global` 实例——否则某工作区下该契约无实例可选 ⇒ 路径断死。
  写期校验：删掉最后一个 global 实例 ⇒ 拒（`last_global_instance`）。

**这条同时解决了"图通用但工作区特性不同"**：图里是 `contract_id`（通用），选到哪个实例按 scope 定（专门化）。
⇒ 专门化落在**实例层**，不落在**结构层**。结构共享 ⇒ 样本量不被除；实例专属 ⇒ 材料不串味。

### 5.2 五层隔离与各自的强制点

这一节的重点不是列隔离，而是**说清每层由谁强制**——强制点决定了它挡得住什么。

| 层 | 隔离什么 | 机制 | 强制点 | 挡得住 |
|---|---|---|---|---|
| **读可见性** | Scope 读不到未声明的东西 | `inputs`（走边）/ `reads`（shared）；未声明一律不可见 | **#33 服务** | 写错 |
| **写面** | Scope 写不了别人的槽 | 单写者：slot 键 = `(node_index, out_port, iter)`，生产者唯一 | **机械闸（写期）+ #33 服务** | 写错 |
| **专门化** | B 工作区用不到 A 的专属 Scope | `scope` 过滤发生在实例选择 | **#33 服务**（候选集过滤） | 写错 |
| **权限** | Scope 调不了未声明端口 | `effects.ports/methods/caps` = 上限，未声明不注入 | **#33 服务**（构造 eff 时按契约过滤）+ **宿主**（`pins` 解析、`caps` 恒等于输入） | 写错 + 部分恶意 |
| **进程** | 插件崩了不牵连别人 | 各执行件独立进程、独立换代、fail-closed 隔离 | **宿主 assembly** | 恶意 |
| **文件系统** | 工具写不出范围 | #25 sandbox 四档钳制 + 一次性 `caps.grant` | **#25**（不是图） | 恶意 |

**必须明写的限制：前四层的强制点在 #33 服务，不在宿主。**

宿主不认识图、不认识契约 ⇒ 它**不会**替你检查"这个 eff 是否在契约声明内"。宿主只保证两件事：
`EffRequest.caps` 恒等于输入（不扩权，内核不变量）、`eff` 的 port 按发出者 `pins` 解析。
而 `host.md` §落账 已明写 **v1 无 op 级鉴权**（宿主不限制 term 改哪个身份）。

⇒ **图层隔离防的是"写错"，不是"恶意"。** 真正的硬隔离只有三条：
`caps` 不扩权（内核）、进程隔离（宿主）、#25 沙箱 fs 钳制。
这不是缺陷而是分层的结果——但它是"审批段不可绕过"（§6.4 第 4 条）与"回滚入口在图外"（§12）存在的**另一个理由**：
既然图层隔离靠 term，那"图被改坏"就必须在写期拦，且回滚入口不能也在图里。

### 5.3 Scope 嵌套的隔离规则

`composite` Scope 内部是子图，所以隔离要说清嵌套语义：

1. **子图 slot 不泄漏到外层**：composite 对外只暴露契约声明的 `outputs`；内部 slot 键带父 `node_index` 前缀，
   外层节点无法寻址。
2. **`reads` 只能收窄不能放宽**：子图节点的 `reads` 必须 ⊆ 父 Scope 契约的 `reads`（写期校验）。
   否则把一个节点塞进 composite 就能扩大读面。
3. **`effects` 取并集但受父契约上限**：父契约的 `effects` 必须 ⊇ 子图各节点 `effects` 的并集（写期校验）。
   ⇒ **不能靠嵌套扩权**。
4. **`scope` 继承且只能收窄**：子图节点的 `scope` 不得比父 Scope 更宽（`global` 父可含 `workspace` 子，反之拒）。
   否则 `workspace` 专属 composite 里塞个 global 节点，专门化边界就漏了。
5. **Scope 不持有跨调用状态**：L0/L1 一律。L1 的循环变量调用私有、随调用结束销毁、逐步入轨迹。
   ⇒ **子代理没有私有持久记忆**；要记就显式落 #21（带 tag + scope），走同一条记忆通道。

**通道没有隔离（明写，别误以为有）**：`#35 channels` 是世界数据，任何能读 #35 投影的 term 都能读全部通道。
要分隔离只能在 term 判定里做，或拆身份。v1 不做。

## 六、图的形状与不变量

### 6.1 六类条目，各自成 def + 链式 tail

图与策略住 **#33 自身的数据世代**（`draft-design.md` §1.2 第 9 条：策略/图/实例一律住世界数据身份，
不放包内文件——否则改一次策略就要走换代）。

**不能塞进一个 body**：契约是 append-only 闭集、Scope 是开集、提示词各自独立、阈值要热改。
全塞一个 ⇒ 改一个提示词就重写全量 ⇒ O(N²) 写放大。用 **#11 / #21 / #35 同一招**：

```
ids["loop-policy"].body = {
  contracts:     {tail,count},   // 能力类（闭集 append-only）
  nodes:         {tail,count},   // Scope 实例（开集，含 composite）
  prompts:       {tail,count},   // 提示词（各自成 def；含保留 id `system` = 图级系统提示词）
  graph:         {def:hash},     // **唯一顶层图**（单值，不是 tail —— 见 §9）
  thresholds:    {tail,count},   // 阈值（热改）
  refusal_codes: {tail,count},   // 全局拒绝码表（append-only）
}
```

条目各自成 def、带 `prev` 成链；写一次 = `put(条目) + put(新 body) + add_gen`；
条目 body 由**宿主投影引用闭包解析**放进 `refs`（已登记的宿主待补能力，服务 #11/#21/#35，本文复用）。

**`graph` 是单值不是 tail**（与早期版本的 `graphs:{tail}` 不同）：单图口径 ⇒ 顶层只有一张；
历史版本由**数据世代**承载（`add_gen` 追加、`set_active` 回滚），不由 tail 承载。
⇒ 回滚一次图变更 = 一条 `set_active`，与"回滚 = 一个记账动作"同路。

### 6.2 契约

```
Contract = { contract_id, role_tag,
  inputs:  [{name, type, role?, required, cardinality:1|n, binding_mode:all|any}],
  outputs: [{name, type, role?, cardinality:1|n}],
  reads:     [{key:SharedRef, optional?}],
  publishes: [SharedRef],
  pre:  "<规则名>",        // 服务内规则：不满足则 Scope 合法拒绝
  post: "<规则名>",        // 服务内规则：Scope 级验收器（唯一 dense 信号源）
  refuses: [RefusalCode],  // 只能引用全局码表
  effects: {ports, methods, caps},   // = 权限上限，未声明即不注入
  idempotent, touches_effects, can_delegate,
  cost: {tokens?, calls?, tool_calls?, walltime?},   // 先验，不是计费真源
}
```

- **契约不可变**：改 `inputs`/`outputs`/`pre`/`post` 的**判定式结构** = 新 `contract_id`。可寻址面 append-only。
- **阈值热改**：`post` 里的阈值不内联，按 `thresholds.<name>` 从**随 bag 传入的图数据**读。改阈值 = 改 `thresholds` 条目 = **热生效**；
  改判定式 = 换 execute 代码 = 换代（服务自驱既定代价）。实验的 `put(slot=threshold)` + 结构指纹校验**不需要**——
  结构与阈值天然分居规则与数据两侧。
- **`post` 的输入面（写死，否则不可复算）**：只能引用本 Scope 的 `outputs`/`inputs`/`reads` 解析到的产物、
  `thresholds.*`、本步 `trace.eff_log` 记录（2026-09-20 修订）。**不得**引用其它 Scope 的 slot、全局统计或预算余量。
- **两级验收不混**：Scope 级 = `post`；回合级 = sink 产出 → `session.commit`。Scope 级永不能替代回合级。

### 6.3 拒绝码（全局 append-only，聚类唯一来源）

失败聚类必须**跨契约可比**，否则"缺什么能力"问不出来。契约只能引用码，不能自造。

| 码 | retriable | attributable_to |
|---|---|---|
| `pre_unsat` | false | node |
| `input_insufficient` | true | graph |
| `capability_mismatch` | false | **graph**（编排选错了 Scope，不是 Scope 不行） |
| `budget` | false | budget |
| `undeclared_read` | false | node |
| `downstream_refusal` | false | graph |
| `redundant` | false | graph |
| `transport_failed` | true | node |
| `stale_dep` | false | graph |
| `scope_mismatch` | false | graph |
| `link_denied` | false | graph |
| `needs_approval` | — | **user** |
| `denied` | false | **user** |

> **`no_progress` 不在此表**：它是**证据类型**不是运行时拒绝码（§8.1 已定）——
> L1 迭代在 Scope 内部（一次 eff），解释器看不到内部迭代，让 Scope 自己判又破"不能自己决定完成"。
> 故运行时不拦，由指标层事后聚类产证据。

**`attributable_to` 必须有 `user` 这一维（产品特有）**：用户拒批 20 次是**偏好**，不是能力缺口。
少这维，审批拒绝会被聚类成"能力缺口"并触发一串无谓提案。
`='graph'` ⇒ 改提示词/改接线；只有 `='node'` 且**跨多契约重复**才是**新能力**的证据。

### 6.4 图与六条不变量

```
Graph = { nodes:[contract_id…],                              // 生成序，下标 = node_index
          edges:[{from:[u,out], to:[v,in], when?:"<规则名>"}],
          entry_supply:[{type_id, role?}],
          loop:{ when:"<规则名>", max_iter:<thresholds 名> },   // 回合内重入（§7）
          sink:<node_index> }
```

**闭合**：required 入边全连 ∧ 非首节点 ≥1 入边 ∧ 每节点有向路径到 sink ∧ `|V|≥1` ∧ 无环。
**sink 唯一**；要多终产物就让 sink 用 `cardinality:'n'` 汇聚。多个无出边节点并列充当终点**不允许**——
否则"回合读哪些产出"依赖运行时排序，收口面不唯一。

**类型系统 = nominal + `type_id`**（append-only 表，带 `subtypes`）；端口带 `role`（`code`/`plan`/`critique`/…）
把"唯一匹配自动补齐"从稀有变常态。歧义时必须写显式端口对。

**六条图不变量（机械闸校验，防提案抄近路）**：

1. **兜底首节点**：池中始终保留一个只依赖 `entry_supply` 的 `touches_effects:false` 契约。
2. **`join` 契约必在**：跨互斥分支的 shared 合并必须有合法手段（§7.4 publish 偏序段）。
3. **`subagent` 契约必在**：保证"加子代理不必改图"（§10.1）。
4. **审批段不可绕过**：声明了高危端口（`fs` 写 / `exec` / `plugin-admin` 的 `write` / `orchestration-admin` 的 `propose`；**实际判据 = (port=提供者能力类名, 工具名)**，2026-09-19 与 #26/#27 口径对齐）的 Scope，
   其可达路径上**必须存在** `guard → approval` 段；否则**写期拒**。
   理由：#25 sandbox 仍钳制四档 fs 范围，所以删了审批**拿不到**范围外权限；但"升级弹卡"这一档
   **只能由图表达** ⇒ 图能删它就等于静默降档。这是唯一一处"图能削弱权限"的口子。
   **对 composite 同样生效**：子图含高危端口 ⇒ 折叠后的契约仍须落在审批段之后。
5. **`llm_chain_max`（堵"三 LLM 串联"）**：任一路径上**连续 LLM Scope** 数 ≤ `thresholds.llm_chain_max`（默认 2）。
   **判据 = 契约的 `effects.ports` 含 `model`**（不引入实验的 `implementation:llm` 字段——产品的 Scope 只有
   `impl:atomic|composite`；用已有字段判，且与"`model` 是效果端口"同一口径，机械可查）。
   超了必须在中间插非 LLM Scope（工具 / 校验 / 聚合），或合成一个 Scope。
   理由：连续三次 LLM 无中间验证，每步都可能漂移且中间没有产物被 `post` 拦；且每个 LLM Scope 一次真实调用、
   永不 memo（`model` 是效果端口）⇒ 成本线性叠加、用户立刻感知。**这是"不做池子组装"的机械兜底**（§9）。
   composite 按其子图的**最长连续 LLM 链**折算，不按 1 计。
6. **`last_global_instance`**：任一契约必须至少有一个 `scope:global` 实例（§5.1）。

## 七、初始图与回合重入

### 7.1 先解决：DAG 怎么表达工具循环

工具循环天然是环（model → tool → model → …），而图是 DAG。三条候选里两条不行：

- **放开环**：破单写者 slot 键唯一 + publish 偏序静态可判，换不到东西（终止性已由 `MAX_STEPS` 保证）。
- **塞进 L1 内部**（`retry_policy` 里循环）：工具派发与审批就**不再是图节点** ⇒ §6.4 第 4 条
  「审批段不可绕过」**无从校验**（机械闸看不见 Scope 内部），且工具结果拿不到自己的 `post` ⇒ dense 信号丢一半。
- **采纳：回合 = 多次图执行。** 图描述**一次模型轮次**；本轮派发过工具 ⇒ 按 `Graph.loop` 重入，`iter+1`。
  这正是 `kernel.md` 的在用惯例——**无 while，长循环拆多 directive**；`Graph.loop` 是它的声明形式。

重入带来四条好处，不是将就：① 图是 DAG 且小；② 审批段是真节点、不变量可校验；
③ 每次重入是**全新 slots** ⇒ 单写者平凡成立；④ **iter 间产物（工具结果 / 消息）走 #33 服务内存 `slots`/`shared`、#11 回合尾一次写**（2026-09-20 与 loop-policy §六 统一——同一次 `interpret` 内不落账），
下一**回合**的 `context.assemble` 才从 #11 看到工具结果。

### 7.2 加强口径（2026-09-19，先读这段）

早期版本的种子图只有六节点、**零实质 `post`**、且不使用任何池不变量要求的契约。那有一个**自举漏洞**：

> `agent.step` 是一个铁块 ⇒ 失败全归到这一个契约上 ⇒ 指标层**没有可归因的粒度**、没有逐 Scope 成功率、
> 没有 `post` 分辨率 ⇒ **进化环冷启动不了**。

「没有证据支持哪种拆法」这条理由对**怎么拆**成立，对**一点结构都不给**不成立。本轮加强三处：

1. **机械 `post`**（§7.4）：零 token、零新节点，把"下游才炸"的检查提前成 Scope 级判定 ⇒ dense 信号有了来源；
2. **`verify` 节点**（§7.5）：条件分支 + `scope` 分档，给产品域一个**最接近 oracle 的信号**，且默认零成本；
3. **池词汇补全**：`join` / `subagent` 契约与全局实例从第一天就位 ⇒ 不变量 2 / 3 / 6 可机械通过。

**三处都不碰默认路径** ⇒ 验收 1 的逐字节等价仍成立：简单问答仍是 `assemble → step → commit` 三步。

### 7.4 种子图

```
nodes: [ assemble(0), step(1), gate(2), approval.wait(3), dispatch(4), verify(5), commit(6) ]
edges:
  0:messages   → 1:messages                              (无条件)
  1:tool_calls → 2:calls         when nonempty(tool_calls)
  1:message    → 6:message       when empty(tool_calls)
  2:verdict    → 4:verdict       when verdict_is(allow)
  2:verdict    → 3:request       when verdict_is(escalate)
  2:verdict    → 6:refusal       when verdict_is(deny)
  3:decision   → 4:verdict       when verdict_is(approved)
  3:decision   → 6:refusal       when verdict_is(denied)
  4:results    → 5:changes       when wrote_files(results)      ← 本轮新增分支
  4:results    → 6:results       when not wrote_files(results)
  5:report     → 6:report                                (无条件)
loop: { when: dispatched_tools_or_verify_failed, max_iter: thresholds.max_turn_iter }
sink: 6
```

- 节点 6（`turn.commit`）入端口 `binding_mode:any` / `cardinality:1`——**五条入边互斥**，恰一条触发。
- **种子判定**（包内附，`when` 引用）：`nonempty` / `empty` / `eq` / `verdict_is` /
  **`wrote_files`**（本轮新增，机械查 results 里有无写类工具成功项）。

**无工具路径（默认路径，必须与 #14 原管道逐字节等价）**：

```
iter1: assemble → step(模型直接答) → commit        // = context.build → model.chat → session.commit ✓
loop.when 为假 ⇒ 收口
```

⇒ **加强完全没有落在这条路径上**：简单问答仍是三步、零额外模型调用、零额外成本。

**有工具路径（等价于既定 `26 → 27 → 32 → 39 → 33`，尾部多一个条件校验）**：

```
iter1: assemble → step(产 tool_calls) → gate
         ├ allow    → dispatch ─┬ wrote_files → verify → commit
         │                      └ 未写文件      → commit
         ├ escalate → approval.wait（入队）⇒ 本 run 正常结束
         │              #39 裁决落账 → 触发新 run（带 resume 游标）
         │              ├ approved → dispatch → …（同上）
         │              └ denied   → commit（落拒绝）
         └ deny     → commit（落拒绝，不执行）
loop.when 为真（派发过工具 或 verify 失败）⇒ iter2
iter2: assemble（现在含工具结果 + verify 报告）→ step(模型看着失败详情自己修) → commit
loop.when 为假 ⇒ 收口
```

达 `max_turn_iter` 仍在派发 ⇒ 落 `budget` 拒绝码并收口（**不静默截断**）。

### 7.5 机械 `post`（零 token、零新节点）

收益最高、代价为零的一处加强：不加节点、不加调用，只把"本来在下游才炸"的检查提前成 Scope 级判定，
于是它同时成为 **dense 信号源**（`post` 本是唯一 dense 来源，但早期种子图没有一个实质 `post`）。

| Scope | `post` 检查什么 | 挡住什么 |
|---|---|---|
| `context.assemble` | messages 非空、末条为 user/tool、请求参数含 model | 组装出空上下文就调模型 |
| **`agent.step`** | 产出**非空** ∧（message 或 tool_calls 恰有其一）∧ tool_calls **结构合法**（name 非空串、args 是对象、call_id 不重复） | **模型吐畸形 tool_call**（原本要到 #27 才失败，且归因指向 #27 而非模型） |
| `tool.dispatch` | results 条数 == calls 条数 ∧ 每项有 `ok`/`error` ∧ 失败项带码 | 部分结果丢失被当成全成功 |
| **`verify`** | report 形状合法（`skipped` 或 `passed`+`detail`） | 校验器自身坏了被读成"通过" |

**只做结构检查，不查语义**：`post` 的输入面被写死为"本 Scope 的 outputs / inputs / reads + `thresholds.*` +
本步 `trace.eff_log`（本步记录）"（2026-09-20 修订），**读不到工具目录** ⇒ 只能查 `name` 是**非空字符串**，不能查"这个工具是否存在"
（后者在 #27 派发时查，本来就在那儿）。这条边界是刻意的：放宽 `post` 输入面会让 dense 标签依赖全局状态、不可复算。

### 7.6 `verify` 的 scope 分档

`verify` 一个契约、两类实例，**靠 `scope` 过滤自动选中**：

| 实例 | `scope` | `bindings` | 行为 |
|---|---|---|---|
| `vf-noop` | `global` | 无 | 返回 `{skipped:true}`，**不发 eff、零成本** |
| `vf-<ws>` | `workspace`（该工作区） | `tools` 绑定校验命令（如 `cargo test` / `npm test`） | eff #27 跑命令，产 `{passed, detail, exit_code}` |

- **默认零成本**：只有 `vf-noop` 时 `verify` 节点是一次纯计算，不调工具、不花 token。
  用户给某工作区配了校验命令才产生真实执行 ⇒ **加强不向未配置的用户收费**。
- **这是 `scope` 机制的第一个真实用例**：结构通用（图里只有 `contract_id = verify`）、
  专门化落实例（每个项目自己的校验命令）——正是「图通用、专门化落实例层」口径的兑现。
- **安全性**：校验命令来自 `bindings`（pin 住的数据、由人或提案设定），**不是模型输出**
  ⇒ 与"模型自选命令"风险档次不同。不变量 4 仍机械要求路径上有 `guard → approval` 段，
  而种子图里 `gate` 在 `dispatch` 之前、`dispatch` 在 `verify` 之前 ⇒ **结构上已满足**。
- **不阻断收口**（明写的判断）：`verify` 失败**不拒绝、不丢工作**，只把报告带进 `commit`，
  由 `loop.when` 触发下一 iter 让模型看着失败详情自己修。
  理由：阻断会让已写入的文件变更失去落账机会；而重入本来就是"再来一轮"的既定机制（§7.1）。
- **顺带解决一件事**：§11.2 提过"有测试的工作区可加第四道门禁（跑真测试判分）"，
  `verify` 的 `passed` 就是那道门禁的**数据来源**——它是产品域**最接近 oracle** 的信号。

### 7.7 本轮明确**不加**的三样

| 不加 | 为什么 |
|---|---|
| `plan` / `critique` / `repair` 预拆 | 这才是**该由证据驱动**的部分。预先拆 = 凭感觉写死，且每个 LLM Scope 一次真实调用永不 memo ⇒ 简单问答成本翻倍。等 `failure_cluster` / `no_progress` 证据指向再拆（提案方向已在 #44 标注） |
| 把 `gate + approval` 折成 composite | 会把审批段藏进子图。不变量 4 虽对 composite 同样生效，但**保持审批段在顶层可见**让人读图时一眼看到"这里会弹卡"，这个可读性不值得换 |
| 任何落在**默认路径**上的节点 | 验收 1 要求与 #14 原管道逐字节等价；且默认路径是最高频路径，加什么都是全局成本 |

**加强后种子图仍是"下限不是目标"**：它现在有了可归因的粒度（四个实质 `post`）、
一个近 oracle 信号（`verify`）、完整的池词汇（`join` / `subagent`），
但**流程结构仍然扁平**——怎么拆 `agent.step` 依然留给证据决定。

**进化的方向 = 把种子图里隐式的东西显式化。** 例如证据显示"改代码类任务反复失败、失败码集中在 `post` 不过"，
提案会把 `agent.step` 变成一个 **composite Scope**，内含 `plan → code → critique → repair` 子图：
每个子 Scope 有自己的 `prompt` pin、自己的 `post`、自己的成功率统计。
这才是图存在的理由——**把不可测的隐式循环变成可测、可归因、可回滚的显式结构**。

**审批段的准确时序（纠一处易错表述）**：内核的 `waiting` 是**效果未回灌**时的状态
（`kernel.md` §十二），而 `approval.enqueue` 本身**会正常返回**（入队成功）⇒ 那一轮不是 `waiting`。
正确形状：

1. `approval.wait` Scope 发 `eff(approval.enqueue)` → 正常返回 → 该 Scope 产出"已入队"；
2. 解释器据此**不产下一个 eval directive**，只产 `write`（落队列项）+ `extern`（回执）⇒ **本 run 正常结束**；
3. 人在 #39 裁决 → `approval.decide` 的计划落账 → 该计划**带一个 resume 游标**（`iter` / `cursor` / slots 摘要）；
4. 宿主据此触发**新 run**，解释器从游标恢复继续走 `dispatch` 或收口。

⇒ 与 #32 既定的"**跨 run** 挂起/续跑"一致。游标能跨 run 是因为它在 eval `args` 里、可被写进队列项
（§7.8 通道表：跨 run 必须落世界）。**本文早期"本 run 以 waiting 收口"的表述作废。**

**种子图的定位（加强后仍成立）**：它是**下限，不是目标**——与 #14 逐字节等价（验收 1）与坏图时的回落目标（§12）。
它现在有了可归因粒度、近 oracle 信号与完整池词汇，但**流程结构仍然扁平**：怎么拆 `agent.step` 依然留给证据决定（§7.7）。

### 7.8 状态通信：三条通道，生命周期不同

```
GraphState = { task,
  shared: Record<SharedRef, Artifact[]>,            // 只读协作面，同键版本 append-only
  slots:  Record<(node_index, out_port, iter), Artifact>,  // 单写者点对点槽
  budget: {remaining, spent}, iter, cursor }
Artifact = { id:Hash, type, role?, producer:{node_index, iter, instance_id}, bytes_ref }
```

| 通道 | 谁能写 | 谁能读 | 活多久 | 落账 |
|---|---|---|---|---|
| **slots** | 该槽**唯一**生产者 | 仅入边指向它的 Scope | **一次图执行**（重入即清空） | 否（走 eval args / 段尾 def） |
| **shared** | 只有运行时（初始化 / Scope 显式 `publish`） | 声明了 `reads` 的 Scope | **一个 run**（跨 iter、跨 `waiting` 续跑） | 否 |
| **世界数据身份** | 计划通道落账（#11 / #3 / #21 / #35） | 任何读投影的 term | **永久** | 是 |

**三条推论，缺一条就会写出错的东西**：

1. **跨回合通信必须落世界。** slots/shared 住 eval `args`，而 eval 不落账（§2）⇒ run 一结束就没了。
   "让下一个回合的 Scope 知道这件事"只有一条路：写 #11 / #3 / #21 / #35。
2. **跨 iter 的消息走 #11，不走 shared。** 技术上 shared 能跨 iter 活着，但消息的真源是 #11
   （`draft-design.md` §1.2 第 12 条红线：#11 是展示真源、全量追加）。让消息在 shared 里另存一份 ⇒ 两份真源。
   ⇒ **shared 只装"本 run 内派生的协作材料"**（任务 spec、工作区快照、讨论摘要、召回片段），不装消息本体。
3. **续跑安全**：内核 `waiting` 续跑（同 `run_id` / 同 `directives` / 同 `now`，`results` 只增不改）用于**效果未回灌**。审批 / 提问往返是另一条路：本 run 正常结束，游标随队列项落世界，宿主触发**新 run** 恢复——不是「waiting 零额外机制」。

**`publish` 是受控动作**：追加新版本、进轨迹、可审计。
**同键发布的偏序铁律**：同一 `SharedRef` 的所有发布 Scope 两两**必须有拓扑偏序**（写期静态检查）——
否则"状态是执行的纯函数"不成立、重放不确定。Scope 读键 K 看到的是**拓扑上先于它、已求值、偏序最后**的版本；
该发布者若落在未触发的分支上则跳过、取偏序上再前一个。**由 (拓扑, 实际产出) 唯一决定，不依赖调度顺序。**

**互斥分支例外**：分属互斥分支的两个发布者无需可比，但跨分支合并必须收在显式 `join` 契约处。
互斥判据**充分不必要**：判不出即视为可同时命中 ⇒ 保守拒。
代价明写：会拒掉一部分实际安全的图；这是刻意选择——"确定被拒"比"可能重放不确定"安全。

**三处标识必须分开**（否则轨迹 join 不上）：`node_index`（图内生成序）/ `node_id`（Scope 实例，不进图）/
`contract_id`（能力类）。slot 键与 `producer` 一律用 `(node_index, iter)`——同一 Scope 在不同 iter 各产一次。

**`#35 channels` 的真实定位 = 跨回合留言板，不是实时总线。** 两条既定口径卡死：
宿主 `event` **只透传客户端、不投递给插件**（`host.md`），且插件间不得直连（红线 3）。
⇒ 通道只能"写进世界 → 下一回合 Scope 经投影读到"。实时协作要先解决并行与投递，后置。

## 八、路径走岔的两条出路：作用域自治 + 作用域互联

**问题**：推式条件边只能沿**预设的边**走。若模型产出落在设计者没预料到的形态上，路径会走岔——
要么卡在某个 Scope 出不去，要么沿着一条错的边一直走到 sink 交出废结果。

两条出路各有已知病症，必须先说清病症再定约束：

| 出路 | 机制 | 病症 |
|---|---|---|
| **自治** | Scope 内部自己多试几次 / 换法子 | **突然 end**：进行到某步自己决定收工，外部看只是"没做完"，且无处归因 |
| **互联** | Scope 之间可跳到非邻接 Scope | **跳到不相干节点**：跳转目标不可预测，`(拓扑,产出) → 路径` 的唯一性失效，重放与归因全崩 |

**统一口径（按 §4 的 Scope 统一）**：自治与互联的**作用域单位都是 Scope**——
即"agent 自治 = 作用域自治 = 节点自治"是同一件事，"agent 互联 = 作用域互联 = 节点互联"也是同一件事。
这正是 §4 统一带来的收益：不必为三种粒度各定一套规则。

### 8.1 作用域自治：只开 L0 / L1，且必须有进展证明

| 档 | 能做什么 | 约束 |
|---|---|---|
| **L0** | 纯函数：一次调用出结果 | 工具 Scope 默认 |
| **L1** | 内部有界循环：自检 / 重试 / 换工具 / 请求追加输入 / 拒绝并给原因 | 迭代上限、预算上限、退出条件由 `bindings.retry_policy` **声明**（可版本化可回滚） |

**三条自治不变量**：① 自治只能花预算、**不能拿权限**；② 自治决策必须留痕（指标层的一等输入）；
③ 自治不改变可寻址面。`autonomy:L1` ⇒ `retry_policy` 必填。

**堵"突然 end"（四条，缺一条病症就回来）**：

1. **L1 不能自己决定"完成"，只能产出或拒绝。** Scope 的出口只有两种：
   合法 `outputs`（过 `post`）或 `refusal`（带码）。**没有第三种"我不干了"**。
   ⇒ "突然 end"在类型层面不存在；它只能表现为一条**带码的拒绝**，而拒绝码进聚类、可归因。
2. **`post` 是机械的、不由 Scope 自己判。** L1 内部循环再怎么自治，出口产物仍要过契约的 `post` term。
   自己说"做完了"但 `post` 不过 ⇒ 判 `pre_unsat` 之外的相应拒绝，不是"完成"。
3. **迭代上限住声明、不住代码**：`retry_policy` 是 pin 住的 def ⇒ 可版本化、可回滚、可被提案调整。
   实现里写死上限 = 改一次要换代。
4. **`no_progress` 是证据类型，不是运行时拒绝码（写死，理由在下）**：
   L1 迭代发生在 Scope 内部（一次 eff），解释器**看不到内部迭代**；而让 Scope 自己判"我没进展"
   正是第 1 条禁止的"自己决定完成"。所以运行时**不拦**。
   落法：`trace` 记 L1 的**迭代次数**与**是否打满上限**（这两项是 eff 结果里本就有的过程数据）；
   `evolve-metrics` 发现某 Scope 反复打满 ⇒ 产 `no_progress` 证据，提案方向是**拆分该 Scope**。
   **代价明写**：那一轮该花的钱照花，运行时不省。可接受——成本已由 `retry_policy` 的迭代上限封顶，
   损失有界；而要运行时拦就得让所有 L1 契约多一个必填输出位回报迭代详情，契约面变宽、
   且"进展"的字面定义（产物哈希不变）对语义相近但字面不同的产物无效。

**L1"请求追加输入"必须声明式**：只能取 `reads` 里 `optional:true` 的 shared 键，
**不能触发新的前驱求值**——否则活动路径在执行期变形，`(拓扑,产出) → 路径` 的唯一性当场失效。
供给判据必须确定性（按剩余预算逐维比较），不许用"看着还够"这类运行时启发。

**L2 委派 / L3 自产拓扑不开**：L2 要跨 run 才能生成子图（run 内造不出新 def），时序复杂度远超收益；
L3 会让"拓扑唯一来源"破功，归因不清。**多层子代理靠 composite 嵌套表达**（§4），不靠递归委派。

### 8.2 作用域互联：白名单 + 声明式，不是自由跳转

**自由跳转不可接受**：它让"跳到哪"成为运行时决定，`(拓扑, 产出) → 路径` 的唯一性失效 ⇒
重放不确定、`sig` 不可比、成功率统计无意义。所以互联必须**在写期就可枚举**。

**落法：`links` 是 Scope 上的白名单，互联边仍是图里的边。**

```
Scope.links: [<contract_id>…]     // 本 Scope 可跳往的契约白名单
```

四条约束：

1. **互联目标必须在 `links` 白名单里**，且**白名单项必须在图里有对应 Scope**（写期校验）。
   不在白名单 ⇒ 运行时拒 `link_denied`。
   ⇒ 跳转集合**写期可枚举** ⇒ 路径空间有限、可静态分析、`sig` 仍可比。
2. **互联边进图、进 `sig`**：一条互联跳转在数据里就是一条 `edge`，只是它的 `when` 引用"上游要求跳转"这个产出位。
   ⇒ **互联不是绕过图的旁路，而是图里显式声明的边**。这条是与自由跳转的根本区别。
3. **不得破 DAG**：互联边同样受无环约束（写期校验）。**要"回到前面重做"只能靠 §7.1 的重入**（`iter+1`），
   不能靠互联边指回去——否则单写者 slot 键与 publish 偏序当场失效。
4. **互联跳转必须留痕**：记 `link_taken` 事件（源 Scope / 目标契约 / 原因码），与 `edge_choice` 同路。
   不记就分不开"设计的路径"和"跳出来的路径"。

**为什么这样仍能解决"路径走岔"**：走岔的典型是"`code` Scope 发现需求没说清，但边只通向 `review`"。
有 `links:[clarify]` 后，它可以显式要求跳 `clarify`——**而这条跳转在写期就被声明、被校验、被计入图**。
设计者仍然掌握"可以跳去哪"，模型掌握"这次要不要跳"。

**代价（明写）**：`links` 白名单要人（或提案）维护；白名单过宽 ⇒ 路径空间变大 ⇒ 每条路径样本量摊薄 ⇒
归因变弱。故 `links` 长度受 `thresholds.max_links` 限，且**扩白名单属结构变更、走门禁**（§11）。

### 8.3 两条出路的分工（写死，防重叠）

| 情形 | 用哪条 | 理由 |
|---|---|---|
| 同一能力再试一次 / 换个工具 / 换个措辞 | **自治（L1）** | 能力边界没变，不必让图知道 |
| 需要**另一种能力** | **互联** | 换能力就是换 Scope，必须在图里可见 |
| 需要**重做整轮**（含重新组装上下文） | **重入**（§7.1） | slots 要清空、消息要落 #11 |

**不许用自治模拟互联**（L1 内部偷偷调另一个能力类的端口）：契约 `effects` 没声明的端口运行时不注入，
所以这条**在权限层已经被堵**——但要在文档里明写，否则会有人试图把多能力塞进一个 Scope 的 `retry_policy`。

## 九、演化口径：单图渐进演化，不做池子组装

**决策（写死）：顶层只有一张图，靠 fork 后有限改动演化；禁止从池子现场组装拓扑。**

### 9.1 为什么不组装（理由比"可能不稳定"更硬）

实验能用池子组装，是因为它有**任务级 oracle**（跑隐藏测试拿 0/1）+ **可训编排模型** + **搜索器**：
组装出的图好不好，它能测出来。产品三样全没有——没 bench、没 oracle、样本量撑不起统计闸（§11.1 不做统计闸的同一理由）。

> **没有判优手段的组装 = 随机结构生成。** 那不是自进化，是掷骰子。

组装派在产品里会产生四个具体病症：

| 病症 | 机制 |
|---|---|
| **成本爆炸** | 每个 LLM Scope 一次真实调用、永不 memo（`model` 是效果端口）⇒ 三 LLM 串联 = 三倍 token，用户立刻感知 |
| **提示词漂移** | 三个 Scope 三份 prompt pin，没人保证它们讲同一件事 |
| **归因崩塌** | 结构天天变 ⇒ 每张图样本量 ~1 ⇒ 成功率全是噪声 ⇒ 证据层产不出可信证据 ⇒ 环空转 |
| **不可比** | `sig` 每轮都变 ⇒ 去重、漂移检测、金丝雀统计全部失去锚 |

### 9.2 演化的四条规则

1. **fork-only**：新图只能**从当前 active 图 fork 后改**，写 `derived_from`（旧图 def 哈希）；
   **禁止从空白生成整图**。写期校验 `derived_from` 存在且可达。
2. **diff 上限**：一次采纳的结构改动 ≤ `thresholds.max_graph_diff`（加/删/改的节点数 + 边数之和）。
   这是生长额度的真实作用——**一次只改有限项，增益才归因得到"这一条"**。
3. **`min_runs_before_fork`**：新图必须攒够 N 次回合才能成为下一次 fork 的基。
   否则噪声上叠噪声——在样本量不足时连续 fork，等于随机漫步。
4. **`llm_chain_max ≤ 2`**（§6.4 第 5 条）：机械兜底。即使提案想串三个 LLM，写期直接拒。

### 9.3 池子是词汇表，不是拼装原料

`contracts` / `nodes` 两个 tail 仍然存在且会增长，但它们的作用是：

- **`contracts`** = 可寻址的能力**词汇**（append-only 闭集）；
- **`nodes`** = 每个词汇的**可选实现**（开集，含不同人格、不同 scope、不同绑定）。

演化用它们的方式是**替换与插入**（把某个 `contract_id` 换成另一个、在两个 Scope 之间插一个），
**不是**"从词汇表里抽 N 个词重新造句"。

### 9.4 专门化不走结构分叉，走实例 scope

早期版本设计过 `graphs` tail + `Graph.trigger` + run 首选图 term（多图共存、按触发选一张）。
**该机制整体作废**，原因：

- 多图 ⇒ 每张图的样本量除以图数 ⇒ 与规则 3 冲突；
- "选错图"是一整类新故障（且 trigger 匹配本身不可测）；
- 专门化的真实需求是**换材料/换人格**，不是换流程（§5 的口径）。

替代：**一张图 + `scope` 过滤实例 + `when` 边条件 + `links` 白名单**。三者分工：
`scope` 管"哪个工作区能用这个实现"（机械）、`when` 管"这次走哪条边"（现场）、`links` 管"能跳去哪"（写期枚举）。

### 9.5 允许的四类结构变更

| 变更 | 例子 | 占额度 |
|---|---|---|
| **绑定变异** | 换某 Scope 的 prompt / model / decoding / retry_policy | ❌ |
| **实例生长** | 加一个新人格实现（同契约、不同 `bindings.agent` / `scope`） | ✅ 实例级 |
| **结构改动** | 插入 / 删除 / 替换 Scope、改边、改 `links` | ✅ 契约级或实例级 |
| **折叠（结晶）** | 把反复成功的子路径折成一个 composite Scope | ✅ 契约级 |

**折叠是唯一使复杂度下降的方向**：同一子路径在 ≥k 个回合上**回合级成功**（不是 Scope 级 post 通过）⇒
折成 composite Scope（新契约 + `subgraph` pin 住子路径）。用户手动"加一个工作流"走**同一条路**（§10）。

- 合成不变量：`effects` / `publishes` / `refuses` 取**并集**（取子集就丢能力）；`pre` 取入口前置合取；
  `post` 取**所有活动路径都执行**的 Scope 的 post 合取（不得并入只在部分分支上的 post，否则被未走分支误杀）；
  `idempotent` = 各 Scope 全确定才 true；`scope` 取各子 Scope 的**最窄**者；深度与 LLM 链按子图折算。
- **收益边界（防"折叠 = 免费提速"）**：子图内部逐 Scope 照常执行、照常计费。折叠降的是**外层可寻址复杂度**
  （图更小、提案生成更短、去重更强），**不降执行成本**。若出现"折叠后成本下降"，只可能来自路径变化，
  必须单独归因。

## 十、用户驱动的结构变更

**先纠一条容易读反的：禁时钟驱动生长 ≠ 禁用户驱动生长。** 红线防的是"没人说、没证据自己开始长"。
**用户指令本身是一等证据**：`evidence.kind='user_request'`，body 带原始消息的 def 哈希（可溯源、可审计）。
自主提案挂指标层证据，用户请求挂用户证据——**同一条提案通道、两个入口**，门禁同一套。

### 10.1 四种请求的代价（按 §4 统一后更整齐）

| 用户说 | 写什么 | 生效方式 | 改图？ |
|---|---|---|---|
| 加一个**子代理 / 协作者** | `#35` 人格 + `#33` 一条 Scope（`impl:atomic`，pin 人格） | **数据世代，热生效** | **不用**（走 `subagent` 契约） |
| 加一条**工作流 / 子图** | `#33` 一条 Scope（`impl:composite` + `subgraph`）+ 接入顶层图的边 | **数据世代，热生效** | 是（fork + 有限 diff） |
| 让某能力**专属本项目** | 给该 Scope / 人格写 `scope:{kind:'workspace', workspace_id}` | **数据世代，热生效** | 不用 |
| 加一个**新能力实现** | 插件包 `execute/` 源码 | **代码换代**：新服务 + 握手 + 旧服务 drain；失败即该分支隔离 | 要，且 #33 换代扩 `pins` |

⇒ **前三种全热生效、回滚 = 一条 `set_active`**；只有第四种碰进程、有隔离风险。
"加工作流"与"加子图"在统一口径下**是同一件事**（都是 composite Scope），这是 §4 的直接收益。

### 10.2 门禁在用户请求下的三条调整

1. **机械闸照跑、不放宽**——用户也写不出闭合正确的图；这道闸零成本。且 §6.4 六条不变量必须同样生效，
   否则"帮我去掉确认步骤"就是一句话提权、"帮我串三个模型互相检查"就绕过 `llm_chain_max`。
2. **影子回放照跑，但只呈现、不否决**——用户明确要的东西不该由系统替他否决，但必须**告诉他**
   （token / 步数 / 审批触发率 diff 进审批卡片）。
3. **人闸仍要一次**——对话里说的是**意图**，不是对 agent 生成的**具体图 diff** 的批准，两者常常不一致。
   例外：`auto` 档直接落（复用既有四档，不新造）。

### 10.3 推演：用户要 agent 写两个代码项目

按当前设计逐步走，**第一个项目能跑通，第二个项目会撞上四个问题**——失败点不在图，在会话/工作区绑定。

第一个项目：工作区 A 新建会话 → `workspace_id` 钉死 → 种子图 assemble/step/gate/dispatch 循环 →
iter 间产物走服务内存、#11 回合尾一次写 → 收口。这条路通。

第二个项目暴露的问题，按严重度：

| # | 问题 | 根据 | 处置 |
|---|---|---|---|
| 1 | **一个会话绑死一个工作区** ⇒ 两个项目必须是两个会话，而两会话间上下文不共享、L1 摘要各一条 | `#11` `workspace_id` **创建即钉死**；`#41` 明写"换工作区 = 新建会话" | v1 **明写不支持并行项目**；多项目形态登记后置 |
| 2 | **`#1 input` 原为全局单值寄存器** ⇒ 并发线程的输入互相覆盖 | `#1` 单值寄存器后写覆盖 | **版本提升 #1**：body 改 per-thread 键控 `slots[<thread_id>]`；**v1 已知限制**：整值 `put` 下不同键并非真正可交换（同线程键写者唯一 + 服务侧清槽取入口 term 轮首 ctx；跨客户端 last-write-wins，见 `plugins/input/DESIGN.md`） |
| 3 | **L3 跨项目召回可能串味** | `#22` 有工作区范围过滤但需显式开 | 召回默认按当前 `workspace_id` 过滤（登记到 #22） |
| 4 | **进化证据被两项目混合分布污染**（最隐蔽）：Rust 项目与前端项目失败模式不同，混在一起聚类 ⇒ "能力缺口"其实是"项目特性不同" | 指标层按 `(码, 归因)` 聚类，原设计不分工作区 | **证据聚类必须带 `workspace_id` 维度**；跨工作区证据**不得合并**成一条能力缺口（见 §11） |

**正确形态**：两个会话 + 两个工作区 + **证据分区** + 各自的 `scope:workspace` 专属实例。
v1 只支持**切换**不支持**并行**；要真并行需多 run 编排 + 写锁排队（已登记后置）。

### 10.4 L2 记忆这条是对的，不用改

`#3` 的 L2 是**每工作区一条**，两个项目天然分开。这条既定设计正好承接多项目场景，无需调整。

## 十一、自进化环：证据 → 提案 → 门禁 → 采纳 → 回滚

**两层分签（借自实验，结构性堵"自己诊断自己改"）**：

| 层 | 实现 | 输入 | 输出 |
|---|---|---|---|
| **指标层** | 执行件 `evolve-metrics`（**非 LLM、纯计算、同输入同输出**） | 轨迹投影（含 `trace.eff_log`；`host.audit` 读 `EffectAudit` 保留为补充）（2026-09-20 修订） | **证据**：失败聚类、成本异常、实例漂移、折叠候选、`no_progress` 聚集 |
| **提案层** | 图内 Scope（LLM）／`orchestration-admin`（用户驱动） | 证据投影 + 图现状 | **提案**：绑定变异 / 实例生长 / 结构改动 / 折叠 |

指标层只产证据不提案；提案层只产提案不能自造证据；两层用 `evidence_id` 连接。
**每条提案必须挂 `evidence_id`；无证据提案直接拒。**

### 11.1 证据的四个维度（含工作区分区，补漏）

聚类键 = `(RefusalCode, attributable_to, workspace_id, contract_id?)`：

- **`(码, 归因)` 是主维**：按契约分组只能回答"哪个契约差"，回答不了"缺什么能力"——
  后者才是契约扩展提案的依据。`='graph'` ⇒ 改提示词/改接线；只有 `='node'` 且**跨多契约重复**才是**新能力**的证据。
- **`workspace_id` 是必须的分区维（§10.3 问题 4）**：不同项目技术栈不同、失败模式不同。
  **跨工作区的证据不得合并成一条能力缺口**——那会把"项目特性不同"误诊成"能力缺失"。
  **两档聚合**：① 工作区内聚类 ⇒ 可提 `scope:workspace` 的专属实例提案；
  ② **仅当同一 `(码,归因)` 在 ≥`thresholds.min_workspaces` 个工作区独立出现**，才可提 `scope:global` 的结构提案。
  ⇒ 通用改动需要跨项目证据，专用改动只需单项目证据。这条同时兑现了 §5"图通用、专门化落实例"的口径。
- **`no_progress` 聚集是 Scope 划分不当的信号**（§8.1）：同一 Scope 反复 `no_progress` ⇒
  提案方向是**拆分该 Scope**（折成 composite 或插入前置 Scope），不是加能力。

### 11.2 门禁（三道）

1. **机械闸（term，零成本）**：闭合 / 类型兼容 / 端口 ⊆ `pins` / 节点解析可达 / publish 偏序 / 上限内 /
   契约 append-only 未被改写 / **§6.4 六条不变量** / **§9.2 四条演化规则**。不过 ⇒ 拒，只落一条 `verdict`。
2. **影子回放（确定性，零 token，由 #44 `shadow` 方法跑）**：取最近 M 个回合的历史输入（#43 `trace.directives_summary`/`ctx_summary`）+ **`trace.eff_log`** **回灌**（`host.audit` 读 `EffectAudit` 保留为历史对照补充，v1 以 `eff_log` 为准，2026-09-20 修订），新旧两版图各跑一遍，
   比**确定性过程指标**：token / 调用数 / 步数 / 工具失败率 / 审批触发率 / 裁剪率 / 拒绝码分布 / `link_taken` 频次。
   **回灌是它成立的唯一理由**（`kernel.md` §十四）——不重新调模型，所以零成本、可复现。产出 `pass`/`fail`/`unverified` 写进 `verdict.gate.shadow`。
   **限度明写**：过程指标不等于"做对了没有"；挡得住"变贵了 / 变啰嗦了 / 拒绝变多了"，挡不住"答得更差了"。
3. **人闸（#32 / #39）**：图变更是高危写，入审批队列、整批裁决、走既有四档；**跨 run 续跑**（新 `run_id`，宿主按队列项 resume 游标触发，非内核 `waiting`）。

**不做统计闸**：无 bench、无 oracle、样本量撑不起配对非劣检验，硬造只会产出
"看起来严格实际上是噪声"的结论。**有测试的工作区**可加第四道（跑真测试判分），但只覆盖代码域，
不能当通用判据——否则把"能测的"过度优化、其余场景无监督。
**这道门禁的数据来源就是种子图的 `verify` 节点**（§7.6）：它把"该工作区有没有校验命令"变成
`scope` 分档，配了就产 `passed`，没配就是 `skipped`（零成本）⇒ 有测试的场景自动获得近 oracle 信号，
无测试的场景不被强加成本。

### 11.3 采纳与回滚

- **采纳 = `add_gen`**（新数据世代，热生效）；**回滚 = 一条 `set_active`**。
  `run` 内 `set_active` 只对下一 run 生效 ⇒ 采纳不打断在途回合。
- **判定单位是"候选版本"不是单条提案**：一回合通过额度的全部提案打包成一个候选，一起过闸、一起采纳或一起作废。
  代价明写：打包内某项有害某项有益会被一起拒——此时下回合按 `evidence_id` **拆开重提**（被拒不销毁证据）。
- **采纳与拒绝都落 `verdict`**（含全部 `proposal_id` 与 `evidence_id`）。只记采纳 = 环不可审计。
- **生长额度**：每回合契约级 / 实例级各一上限（住 `thresholds`）；绑定变异不占额度。
  用户显式请求**不占额度**，但仍逐条过门禁。**额度不是证据门的替代**——无证据仍直接拒。

### 11.4 触发与预算

- 回合尾只跑**确定性零 token** 的轻量指标（失败聚类 / 成本 / 拒绝码分布）⇒ 常态零额外成本。
- **达阈才启动提案层**（唯一花 token 处），记外环预算、单列，不混进回合预算。**机制（v1 闭环，2026-09-19）**：回合尾 #33 eff #44 `aggregate` 产证据落 #43 → #33 读新证据投影，达阈 ⇒ 触发 `evolve.propose` 种子契约（LLM Scope，独立触发、不与 `agent.step` 串链、受 `llm_chain_max` 约束）产提案写 #43 `proposals` → 三道门禁（机械闸 / #44 `shadow` / 人闸）→ `verdict` → 采纳 `add_gen`。
- 用户可显式催一次，或直接下结构指令（§10）。**不设定时批量**——时钟驱动与"必须先有证据"冲突。
- **用户请求的证据生产者 = #44 `record`**（落 `class:'user_request'` 证据），#45 `propose` 只引用 `evidence_id`（保分签：提案层不产证据）。

## 十二、坏图的出路

`plugins/loop-policy/DESIGN.md` 验收 1 只有"**无**图数据时回落静态管道"。缺的是"**有但坏**"：

> 图改坏了 ⇒ 下一回合起改回的入口本身也在图里 ⇒ **自锁**。

机械闸挡坏声明，挡不住"逻辑上永不到 sink / 每次都失败 / 步数打满"。四道出路，**全不需要宿主认识业务**：

1. **写期前移**（已有）：机械闸在写入前拒。
2. **种子图兜底**：`graph` 为空 / 解析失败 ⇒ 回落**包内种子图**（§7.3，随 #33 入世的 term + 常量图）。
   单图口径下没有"选另一张图"，所以兜底必须是**包内**的，不能是世界里的另一条数据。
3. **运行期自限**：`MAX_STEPS` / `max_turn_iter` + `limits.gas` ⇒ 坏图**必定终止**（`refused`），不挂死；
   每次失败落 `trace`（含 `eff_log`）（2026-09-20 修订）。
4. **回滚入口在图外**：连续失败判定住 **#17 的 term**（独立于 #33，图坏了它照跑），
   #17 出"编排健康 + 回滚到上一世代"，#38 推通知；回滚 = 入站面直接提交 `set_active`。
   `host.md` §落账 已允许发起者在入站面直接提交 directive ⇒ **零宿主改动、零新动词**。

**为什么不放宿主 watchdog**：让宿主在连续失败时自己走 #33 的 fallback 入口 = 宿主认识 #33 的业务，
破 `host.md` §一「载体不认识业务」。判定必须是 term，触发者必须在图外——两条同时满足的只有
"图外插件的 term + 人按一下"。

## 十三、两个管理面：编排面与插件面

**决策：不复用 `plugin-admin`，另设 `orchestration-admin`；但共用机械闸与审批路径。** 三条理由：

1. **代价与生效语义完全不同**：`plugin-admin` 写源码 ⇒ 代码换代 ⇒ 起新服务 ⇒ 失败即 fail-closed 隔离；
   `orchestration-admin` 写图数据 ⇒ 热生效、进程不动、回滚一条 `set_active`。
   塞进一个 `write` 后面挂两套风险，权限档也没法分开配。
2. **安全语义不同**：`plugin-admin` 需要**依赖完整性**保护（下文 13.1）；编排面需要**图不变量**保护（§6.4）。
   混在一起两套语义互相污染。
3. **边界冲突**：`plugin-admin` 的边界已写明"装配与换代归宿主"、它不认识图；让它认识 #33 的数据 schema 就是越界。

**一处刻意的不对称（写明理由，别强行统一）**：`plugin.write` 产**写计划**（审批闸在执行前拦）；
`orchestration.propose` 产**提案条目**（门禁在采纳前拦）。
根因是**影子回放**：编排变更能用历史输入 + **`eff_log` 回灌**验证（2026-09-20 修订），所以需要提案态承载影子指标给人裁决；
源码变更换的是进程，**跑不了影子回放** ⇒ 提案态对它没有额外价值，只多一跳。

### 13.1 `plugin-admin` 的三处修正（含一个真漏洞）

**漏洞：`sandbox` 可被绕开——可见性过滤是黑名单，而攻击面在依赖关系。**

`plugins/plugin-admin/DESIGN.md` 只过滤 `sandbox` 与自己。但 agent 可以：

- 写 `tool-fs` / `tool-shell` 的源码，让它**不 pin `#25`** ⇒ 工具不经沙箱 ⇒ 四档 fs 强制失效；
- 写 `#26 guard` 的判定 ⇒ 危险操作不再升级；
- 写 `#27 tools` ⇒ 改派发目标。

**修正 1：受保护 `pins` 不可删（`protected_pin_removed`）。**
`write` 时机械校验：新世代的 `pins` 不得删除对受保护身份（`sandbox` / `guard` / `secrets` / `approval`）的引用；
删了直接拒。这条在**宿主入世校验**里就能做——`pins` 是宿主解析的，**不需要认识业务**，
与 `plugins.md` §二「引脚未解析即拒」同路。

**修正 2：可见性名单必须住包内，不能住世界数据。**
现设计名单住 `schema/plugin-admin.json`（世界数据），但**改数据不用经 `plugin-admin.write`**——
agent 可让别的路径产出 `add_gen(plugin-admin, 新数据世代)` 改名单。
`host.md` §落账 明写 **v1 无 op 级鉴权**（term 可改任意身份）⇒ 名单在世界数据里等于没锁。
⇒ 名单钉在**包内 schema**（改它 = 代码换代 = 走人闸），不走数据世代。

**修正 3：`validate` → `write` 强制顺序。**
现在 `validate` 是可选的。写死：`write` 必须携带上一次 `validate` 的结果哈希，否则拒——
把"运行时才炸"提前到写期，与 §11.2 机械闸同一口径。

**两个管理面共同受约束（写死）**：① 不得削弱受保护 `pins`；② 不得绕审批段（§6.4 第 4 条）；
③ 都要 `validate` 前置。

**必须明写的限制**：`host.md` **v1 无 op 级鉴权** ⇒ "编排面不改源码、插件面不改图"是
**工具面约定 + 审批闸**，不是内核强制。要硬强制需要 op 级鉴权，属后置档。

## 十四、新增身份与跨插件登记

3 个新身份，**已正式编号 #43–45**（`plugin-admin` 已占 #42，故接续；编号连续、无跳号）：

| # | 身份 | 类型 | 职责 | 依赖 |
|---|---|---|---|---|
| 43 | `evolution` | **数据身份**（schema only） | 四类 tail：`trace` / `evidence` / `proposals` / `verdicts`；条目各自成 def + 链式 tail | 无 pins；`<-` #33、#44、#45、#17 |
| 44 | `evolve-metrics` | **执行件**（纯计算，非 LLM） | 证据聚合：按 `(码, 归因, workspace_id)` 聚类、成本异常、实例漂移、折叠候选、`no_progress` | `+` 43；`<-` #33（pins） |
| 45 | `orchestration-admin` | **执行件** | `orchestration.list` / `orchestration.read` / `orchestration.validate`（本地复刻机械闸 dry-run）/ `orchestration.propose`；**只产提案、不产写**；user_request 证据由 #44 `record` 产 | `+` 33、43、11/41；`<-` #27（pins，以工具类 `orchestration-admin` 暴露） |

**为什么 `evolution` 合成一个身份**：轨迹高频可清理、证据/提案/判定低频要永久，生命周期不同；
但 `Identity.schema` 在身份诞生时固定、改数据契约须 `fork`（`host.md` §源码），一次定齐四类 tail 即可，
且"证据可溯源到轨迹"在同一身份内 `refs` 闭包就能解。省一个身份。

**为什么证据聚合是执行件不是 term**：跨会话大规模统计受 `Fold`（集合长度）与 `gas` 限制；
纯计算执行件满足"同输入同输出"的可回放纪律（`draft-design.md` §1.2 第 4 条）。

**为什么它必须与 `orchestration-admin` 分开**：两层分签。给指标层加写面（哪怕只是提案面）
就等于"自己诊断自己改"，评审再也无法机械验证。同理它也**不得**产证据。

**轨迹控量**：`trace` 条目只存**摘要 + 引用**（`node_index` / `iter` / `contract_id` / `chosen_instance` /
`chosen_agent` / `workspace_id` / verdict / 拒绝码 / `link_taken` / 四维用量 / `eff_log`（每步记录）），正文不重复存（2026-09-20 修订）。

## 十六、验收（可测断言）

1. **回落等价**：`graph` 为空时与 #14 原管道**逐字节等价**；种子图无工具路径同样等价
   （**加强不落在默认路径上**：简单问答仍是 assemble→step→commit 三步、零额外调用）。
2. **审批往返等价**：种子图有工具路径与既定 `26 → 27 → 32 → 39 → 33` 时序一致，含跨 run 续跑（游标随队列项落世界）。
2b. **机械 `post` 生效**：模型吐畸形 tool_call（name 空串 / args 非对象 / call_id 重复）⇒ `agent.step` 的 `post` 不过并落码，**不进 #27**；`post` 只查结构不查"工具是否存在"（输入面读不到工具目录）。
2c. **`verify` 默认零成本**：未配校验命令的工作区只选中 `vf-noop`，该节点不发 eff、不花 token；配了命令的工作区选中 `vf-<ws>` 并跑真命令。
2d. **`verify` 不阻断收口**：校验失败仍 `commit`（已写文件照常落账），报告进上下文并由 `loop.when` 触发下一 iter。
2e. **池词汇完整**：`join` / `subagent` 契约从第一天存在且各有 `scope:global` 实例 ⇒ 不变量 2 / 3 / 6 可机械通过（即使种子图未接线它们）。
3. **分段执行**：图执行住 #33 服务内循环，不产生宿主 eval 重放；节点经 `port.call` 顺序派发。
4. **热生效与换代边界**：写图 / 改阈值 / 加子代理 / 加工作流（composite）= 进程不动、身份数不变；
   改 `pre`/`post`/`when` 判定代码 = 换 execute = 换代（服务自驱既定代价）。
5. **分支真省预算**：未触发分支的 Scope **0 计费、不进执行流**，只记一条聚合计数。
6. **循环有界**：达 `max_turn_iter` 仍在派发 ⇒ 落 `budget` 拒绝码并收口，**不静默截断**。
7. **`scope` 强制**：B 工作区会话下，`scope:{workspace:A}` 的实例**不进候选集**；
   构造只剩 workspace 实例的契约 ⇒ 写期拒 `last_global_instance`。
8. **自治不能静默完成**：L1 Scope 的出口只有"过 `post` 的 outputs"或"带码 refusal"，无第三种；
   构造一个反复打满迭代上限的 Scope ⇒ 运行时正常收口（不拦），但 `trace` 记迭代次数与打满标记，
   且 `evolve-metrics` 能据此产 `no_progress` **证据**（不是运行时拒绝码）。
8b. **拒绝路径可还原**：任一 Scope 拒绝 ⇒ 短路到 sink 且落带错误的消息；
   `trace` 的 `refused_at` 能完整还原"在哪个 `node_index`/`iter` 因什么码拒绝"，
   未求值 Scope 记 `branch_not_taken` 且 0 计费。
9. **互联不越界**：跳往 `links` 外的契约 ⇒ `link_denied`；互联边破 DAG ⇒ 写期拒；
   每次跳转有 `link_taken` 事件。
10. **`llm_chain_max` 生效**：提交含三个连续 LLM Scope 的图 ⇒ 写期拒（composite 按子图最长链折算）。
11. **演化规则生效**：`derived_from` 缺失或不可达 ⇒ 拒；diff 超 `max_graph_diff` ⇒ 拒；
    未攒够 `min_runs_before_fork` 就再 fork ⇒ 拒。
12. **嵌套不扩权**：子图节点 `reads` ⊄ 父契约 `reads` ⇒ 写期拒；
    父契约 `effects` ⊉ 子图并集 ⇒ 写期拒；子 Scope 比父 `scope` 更宽 ⇒ 写期拒。
13. **publish 确定**：同键多发布者无拓扑偏序且判不出互斥 ⇒ 写期拒；跨互斥分支缺 `join` ⇒ 写期拒。
14. **隔离可测**：Scope 读未声明键 ⇒ `undeclared_read`；调未声明端口 ⇒ 拒且不产生 `EffRequest`；
    写别人的 slot ⇒ 写期拒。
15. **审批段不可绕过**：提交删掉审批段却含高危端口的图 ⇒ 写期拒；用户请求路径同样被拒。
16. **受保护 pins 不可删**：提交删掉 `tool-fs → sandbox` pin 的插件世代 ⇒ 入世拒 `protected_pin_removed`。
17. **证据分区**：同一 `(码,归因)` 只在一个工作区出现 ⇒ 只能提 `scope:workspace` 提案；
    跨 ≥`min_workspaces` 个工作区才可提 global 结构提案（机械可查）。
18. **坏图必终止**：构造"永不到 sink"的图 ⇒ 达上限后 `refused`，宿主不挂死；#17 能读到健康并回滚成功。
19. **环可审计**：任一采纳可从 `verdict` 反查 `proposal_id` → `evidence_id` → `trace` → `eff_log`（2026-09-20 修订）；
    无证据提案被拒且拒绝也落 `verdict`；用户请求与自主提案落同一 tail、过同一门禁（无旁路写）。
20. **分签成立**：`evolve-metrics` 输出不含提案；`orchestration-admin` 不产证据、不产写；
    提案 Scope 的输入不含它自己产的证据。
21. **通道不越界**：通道消息只经宿主事件给客户端，**不投递给插件**（协议层可查）。
22. **回滚可验**：回滚后同输入重跑，在 **`eff_log` 回灌配对**下逐字节复现旧结果；回灌缺失时只能记"回滚未验证"（2026-09-20 修订）。
23. **影子零成本**：影子回放全程不新增模型调用（`eff_log` 回灌面可证）。

## 十七、不做什么

- **不做控制层可训模型**（三模型 / MoE / 受约束解码 / 蒸馏 / 搜索器）——产品无权重通道。
- **不做池子组装拓扑**（§9）——无判优手段的组装 = 掷骰子；`llm_chain_max` 是机械兜底。
- **不做多图共存 + 选图**（早期设计已作废，§9.4）——样本量被除、"选错图"是一整类新故障。
- **不做拉式惰性路由**（早期设计已作废，§3）——无可训路由、且工具决策必须看实际产出。
- **不做统计采纳闸**（配对非劣 / BH-FDR / group-sequential / dev-holdout）——无 bench、样本量不够。
- **不做回合内拓扑生成**——run 内造不出新 def，结构限制不是选择。
- **不放开图的环**——换不到东西，破三条不变量；循环靠重入。
- **不做自由跳转互联**（§8.2）——跳转集合必须写期可枚举。
- **不做 L2 委派 / L3 自产拓扑**——多层子代理靠 composite 嵌套表达。
- **#33 服务内节点不并行**（v1）——`interpret` 顺序派发节点（`port.call` 可挂多路但 v1 保守串行）；run 之间并发由 threads-design §二 承载（run 级并发 + 提交队列 + 乐观校验）。
- **不支持并行多项目**（v1，§10.3）——一会话绑一工作区 + `#1` per-thread 键控（不再全局单值）；只支持切换。
- **不做 agent 间实时消息总线**——event 不投递给插件、插件不得直连。
- **不把编排管理并进 `plugin-admin`**——代价、安全语义、边界三重不同（§13）。
- **不做 op 级鉴权**（v1）——明写限制：工具面分工靠约定 + 审批闸，不是内核强制。
- **不做特权 engine 插件**（#33 是普通 execute 服务，宿主不给它特殊路径）；宿主新增动词仅限本设计登记的四条（受保护 `pins` 不可删 / 定时触发扩围 / 入世 dry-run / 保留能力类 `host`）。
- **不给用户请求开免审批直通**——`auto` 档是既有权限档，不是新开旁路。
- **不预拆 `plan` / `critique` / `repair`**（§7.7）——这是该由证据驱动的部分；预先拆 = 凭感觉写死，
  且每个 LLM Scope 一次真实调用永不 memo ⇒ 简单问答成本翻倍。
- **不把审批段折进 composite**（§7.7）——保持顶层可见，让人读图时一眼看到"这里会弹卡"。
- **不在默认路径上加节点**（§7.7）——验收 1 要求逐字节等价，且默认路径是最高频路径。
- **不定义尚未写死的数值**（`MAX_STEPS` / `max_turn_iter` / `llm_chain_max` / `max_graph_diff` /
  `min_runs_before_fork` / `max_links` / `min_workspaces` / 聚类阈值 / 折叠 k / 额度 / 影子回合数 M /
  大产物阈值）——一律住 `thresholds`，实现前补齐，不许顺手自定。
