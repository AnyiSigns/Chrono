## 0. 四条不可违反的前提

1. **本轮内核代码改动只有三处**：T2（1 行）、T3（2 行）、T5（局部）。其余全是规格文字、宿主代码、测试、以及**一份数据**。
2. **"轻"的度量是名词数，不是行数。** 放开 `note` 载荷 = 1 行、0 新概念，合法；加 `truncate` / `compact` / `index` 之类 op = 加动词，**禁止**。
3. **不得改动 `H` 的口径、`argsHash` 的口径、链格式、任何既有哈希语义。** 放宽形态检查向后兼容（旧链仍合法）；收紧不兼容（禁止）。
4. **绝对性能数字（ms、MB/s）一律不得写进规范文本**，只写比率与量级并注明测机。理由：同一份实验两次跑差 13×。

**四向路由判据**（决定新需求归属，别再讨论一遍）：坏数据能进世界 → 内核；宿主自己算错自己的账 → 宿主；要语言生态/进程隔离/可丢弃可重算且 `协议往返 ≪ 任务成本` → 执行件；是判定标准本身 → 写成数据进世界。

### T2 · 内核：`note` 放行载荷（1 行 + 6 测试）｜建议现在做

```diff
-  note: (c) => c.keys.length === 0,          // packages/kernel/commit.form.ts:70
+  note: () => true,   // 任意 JSON 对象：hasForm 前置（第 43 行）已保证 args 是非 null、非数组对象
```

**为什么值得现在做**：宿主的替代方案（把留痕摘要做成小 def `put` 进世界）会让 `cloneWorld` 按**事件量**线性付费，实测 **1.33µs/def**：5 万条 ⇒ 每次调用 ~66ms，10 万 ⇒ ~133ms。**若已确定累积事件 ≤5000，本项可推迟；否则现在做。**
**为什么它绕不过**：不带载荷的 `note` 是空槽，带内容的记录只能进 `defs` ⇒ 留痕增长率 = 热路径增长率。这是唯一一个"外包会污染所有宿主共享的热路径"的项。

**评审补 6 条测试**：

1. 载荷 note 正例（`{kind:'obs', step:3, blob:<hash>}` → `ok:true`）；空 `{}` 仍过（向后兼容）；`args` 顶层为数组/字符串 → `bad_form`。
2. **同载荷 note 提交两次 → 两条 entry**（`isNoop` 恒 false，**故意不去重**；"处理过没有"归上层 `WriteRequest.id`）。这是行为变更，以前从没被测。
3. 改载荷不改 `argsHash` → `args_hash_mismatch`。它是 `journal.b:257`（"`entryHash` 不读 args"）的**镜像**，也是"留痕不可抵赖"的唯一正向证明。
4. 新不变量 16（见 T1 最后一行）：只含载荷 note 的链 `replay ≡ EMPTY_WORLD` 逐字节、全程 `worldRev` 不变、`cloneWorld` 的 `defs` 键数与 note 条数无关（计数桩）。**这条就是规矩 B 的可执行定义。**
5. batch 内 `note` 载荷含 `{"$n":k}` 且**经 `commit` 的完整形态路径**（现有 `journal.b:360` 是 `applyEntry` 直测）。
6. 载荷 note 双跑逐字节一致。

**同步落**：`§14` 表末加第 16 行；`§15` P2 那格 `15 条全绿` → `16 条全绿`。
**回退**：无条件安全（放宽形态向后兼容）。
**依赖**：T1（d/e 两处措辞）。

### T3 · 内核：`verify` 不再抛异常（2 行 + 3 测试）

**现状（读代码得，无任何文档写过）**：`journal.apply.ts:52-53` 对 `snapshot` 的 `world_rev` 不符是 `throw KernelError`；`verify`（`journal.ts:76-99`）不 catch，只在 `!r.ok` 时返回 `apply_failed`。于是——**改 `prev`/`args` 走返回码，改 `snapshot` 的 `world_rev` 异常穿出**，而 `verify` 的签名契约是 `{ok, error?}`，且 `replay` 自己的 docblock（`journal.ts:58`）`@throws` 也只列了两个码、漏了这一支。

**实现方**：`verify` 内 `try { … } catch (KernelError e) → { ok:false, error: e.code }`；`replay` 保持抛（它的契约就是抛），但把 `world_rev_mismatch` 补进 `@throws`。理由：`verify` 是"报告完整性"的函数，它自己不该成为异常路径——宿主调它就是来拿一个能打勾叉的结果。
**评审补 3 条**：① 篡改链中 `snapshot` 的 `world_rev` → `verify` **返回** `world_rev_mismatch`（不是抛）；② **`replay(尾段, 错的基础)` 不报错**——把"不保证"写死成断言（例：尾段一条 `add_identity` 在真实历史上本该 `id_taken`，接错基础却成功 ⇒ 产出链上从未被授权的世界）；③ 完整三步 `verify([],anchor,{worldRev})` → `verify(段,anchor)` → `replay(段,anchor.world)` 的结果与 `full` 逐字段等价。
**依赖**：T0。与 T2 并行。

### T5 · 内核：`dup` 短路（可选，收益最大）｜排在 T2/T3 之后

`applyBatch` 段 1 结束即可定论：**若本批全部子操作都是 `put` 且每个键都已存在于 `defs` → 直接 `isNoop = true`，跳过段 2**。实测重复提交要付一次真写的 **88%**，而重试是自进化系统的常态路径。
**边界写死**：只对"全 `put`"批短路；含 `add_gen` / `add_identity` / `note` 的混合批仍走段 2（那些 op 的 `isNoop` 不由键存在性决定）。规格在 §10.3 补这一句。
**验收**：计数桩断言同批 `H` 次数 `2N → N`；短路前后 `verdict`（`ok`/`reasons`/`pos`/`written`）与现实现逐字节一致且 `entry === null`；实验复测 `dup/put`：**原期望"<10%"经评审裁决（2026-09-16）作废**——`dup` 短路只免段 2，段 1 预哈希是 `argsHash` 链格式、不可免（`kernel-design.md` §13 省幅上限 = 一半），H 账口径的达标线改为 **≤ 50%**（本机实测 40–49% 在界内）。评审计数桩按 §14-14 口径断"段外两笔算常数"：`2N+1 → N+1`。
**注意**：宿主缓存只能省"没崩的重复提交"；**崩在 apply 之后、落盘之前**那一次只有内核能省——这是它不可完全外包的原因。
**为什么排第五**：不是不重要，是它要新增计数桩测试，而 T2/T3 已在动同一批测试文件。

### T6 · 规矩 A 生效：清单用 `pins` + 一份门禁数据（**不补就有沉默的错**）

1. `experiment/host.ts` 的清单改成 `add_gen` 带 `pins: { src: K_SRC }`，**body 里不重复列**同一个哈希（单一记录处；`stale` 只看 pins，两处冗余会漂移）。
2. **写第一份 `schema` def**：一条**可执行 term**，声明"该类型身份的 `pins` 必须含名为 `src` 的项"；宿主在 `add_gen` 之前求值它。这样门禁落在**数据**上（能热改、能追溯、能回滚），而不是落在宿主代码里（要重启）。**这也是 M2 归约机的第一个真实用户。**

**验收（关键——先让它红）**：构造：旧世代 pin 源码哈希 `K1` → `put` 改后源码得 `K2` → `set_active` 到新世代 ⇒ `stale(旧内容, world, id)` 必须 `=== true`。
- 按今天的 `pins:{}` 写法，**这条一定红**（证明确有洞，不是纸面担忧）；改完必须绿。
- **若补了 pins 仍红 ⇒ 不是约定问题，是 `stale()` 的 pins 口径实现有 bug**（§11.3：def 声明了而 gen 缺该名即坏），回来改内核。这一步就是那台机器的诊断用例。
3. 附带断言：漏写 pins 时 `validate` **应当通过**（内核不读 body），所以门禁必须在宿主侧 schema 判据里、且能拒。
**依赖**：T1（b/c/h 三处）。**必须在第一个真实插件存在之前完成**——见下"时效"。

### T7 · 约定：会话语义落到已有机制（零代码）

写进 `kernel.md`（§10.6 表加两行 + §0.4 一句话），**不加任何 op**：

- **分支 = 身份，不是链上的一段。** 一条"线"= `add_identity`/`fork`；线的一次状态 = `add_gen`（payload 指全量内容）；"哪条线为真" = `set_active`。于是"编辑重放 = 截断 + 新分支"表达为：从被编辑的世代 `add_gen` 一个新 payload 并 `set_active` 过去，**旧线仍在链上、只是不再被取用**。
  - **真截断禁止**：删尾部 = 改历史 = 放弃"历史改不掉"。这条不能既要又要。
  - **为什么挪一格更强**：旧线留着 ⇒ "我把它改成了什么、原来是什么"可审计，且**旧线上已真实执行过的效果有据可查** ⇒ 编辑重放不会把已经花掉的钱、已经发出去的请求再干一遍（配 §12.4 的幂等端口缓存）。
- **行级归属用 `Entry.ref`**：它是 entry 字段、被 `entryHash` 覆盖，内核不解释内容，但宿主可按它分组/过滤。约定：`ref` 指向"这条线/这条审计记录"的 def。

**这个模型的唯一实质税（写进文档，别让它意外发生）**：世界只增不减，而**编辑重放系统的历史增速远大于最终状态** ⇒ `defs` 字节 ∝ **总尝试次数**，不是 ∝ 会话数。所以四档分层在此用法下**不是优化，是前置条件**。

### T8 · 实验正规化（`experiment/bench-scale.ts`——**注意写权**）

先修两处口径（都是"结论被算错掩盖"）：
1. G 段 `X10` 改成按**绝对语料量**判（`1e9` / `1e10` 两档各判一次），别按"我恰好跑了多大的十倍"——现在那个 X10 = 2056 个文件，"heap 尚可"只在它以内成立。
2. 第 430 行 journal 体积 `A.lineChars * NCHUNK` → `* N`（C 段实测 journal = 语料 100% ⇒ ∝ defs 数不 ∝ chunk 数）。改后自洽：103K × 200 × 10 ≈ 0.21GB（现在打印 0.00GB，把"1GB 语料 ⇒ journal ≈1.06GB > 单串上限 536MB"这条结论整个掩盖了）。
再加纪律：A 段预热 3 次 + 30 次取中位数，并与 B 同进程同 warmup（现在 `2×8.3 = 16.6ms` vs 实测 14.2ms 差 ~15%，不闭合）。
**新测点——按四档各测一档**（这才是重点，测的是分层本身）：① 2500 × 20KB 真实尺度源码进 `defs`（预期全量审计 ≈8s、克隆 ≈3ms/次）｜② 1000 万条 200B 载荷 note（预期 `defs` **零增长**）｜③④ 1GB 本体进 blob、世界只存哈希（预期内核侧总哈希量降到几 MB）。
换一台机器跑真数（本机 8.4GB 总内存、空闲 1.0GB，≈5000 defs 就是天花板，测不到设计尺度）。**产出**：能进规格附录的常数表，**只写比率 + 量级 + 测机**。
**依赖**：T2、T3、T5、T6。

### T9 · 字块化哈希（**条件触发，默认永久搁置**）

触发：T8 之后 ① 档全量审计 > 30s/仓库，**或** ② 档 note 载荷平均 > 8KB。性质：输出逐字节等价、不破 §22（禁的是换算法）、可回退。
**为什么最后**：它的 ~4.7× 会让 T1–T6 显得可以不做——**用常数掩盖结构**是本轮最坏的可能结果。

### T10 · Rust `build` 执行件（第一个真实插件）

独立进程 + JSON-RPC（即 `design-conclusions` §2 定的执行件形式），接口 `build(sourceHash) → artifactHash`。秒到分钟级的活，RPC 那 1ms 在它面前不存在。
**为什么 Rust 在这里、不在哈希**：哈希是 0.14ms 的纯 CPU 活，宿主进程内 `node:crypto`（C++ + SHA-NI，本机实测 728MB/s）已经把它做到头；为它起进程是**把性能问题换成协议问题**（序列化成本是哈希的 3–6 倍）。
**它顺带第一次真测 §2 的自设判据**：**把这个第一方执行件整个卸载，内核与其测试必须全绿**（无特权检验）。
**它立刻要求两件事已存在**：③/④ 档的本体存储，和 `pins` 承载成员引用（否则"这个插件可达哪些 def"算不出）——也就是 T1 与 T6。

## 2. 顺序与并行

```
T0 ──► T1 ──┬─► T2（内核 1 行 + 6 测试）──┐
            ├─► T6（pins + 门禁数据）      ├─► T8（实验复测/真数）──► T9（条件触发）
            ├─► T7（约定，纯文字）         │
            └─► 规格补 T3 口径 ─► T3（内核 2 行 + 3 测试）──► T4（宿主四件）
T5（dup 短路）：与 T2/T3 同批或紧随其后，需 T1 定稿
T10：T1 + T6 之后任意时刻
```

**可并行**：T2 / T3 / T7 三条互不相干；T4 只依赖 T3 的**规格口径**（可先按"会抛"写 try/catch，T3 落地后删）。
**时效警告**：给现存声明补 `pins` 会改变 `H(Def)`，而 **`H(Def)` 就是 def 的键** ⇒ 换 payload = 开新世代。今天成本为 0（只有 `host.ts` 一个假插件）；有真实数据之后，成本 = 全量重 `put` + 谱系断裂。**T1 与 T6 是唯一"晚一天就变贵"的两项，优先做完。**

## 3. 这批做完的验收总闸（五条，全部可证伪）

1. `npx vitest run` 全绿，且测试数从 **183 增加 ≥ 9 条**（T2 六条 + T3 三条），无一条是放宽既有断言得来的。
2. **T6 那条 `stale` 测试先红后绿**：红过 ⇒ 证明洞是真的；绿 ⇒ 依附判定第一次真正生效。若绿不了而 pins 已写对 ⇒ 是实现 bug，当场修内核。
3. 只含载荷 note 的链：`replay` 结果与 `EMPTY_WORLD` 逐字节相同、全程 `worldRev` 不变（= 规矩 B 生效，留痕不再挤热世界）。
