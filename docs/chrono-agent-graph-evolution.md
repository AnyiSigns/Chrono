## 一、进化外环

> **本文与《契约与图》的分工**：契约 / 实例 / 结晶不变量的**定义**在《契约与图》§一；本文只写**外环怎么用它们**
> （证据 → 提案 → 门禁 → 采纳 → 回滚）与账本记账。冲突时以《契约与图》为准。

**监控 = 指标层（非 LLM）+ 决策层（LLM manager）——图外、回合后运行**

监控是**图外、回合后**运行的两层组件。两层职责与实现手段不同，**不可混成一层**：

| 层 | 实现 | 输入 | 输出 | 为什么是这个实现 |
|---|---|---|---|---|
| **指标层（monitor）** | **非 LLM、确定性、阈值可声明/可版本化** | 冻结记录：轨迹 events、defs/events 链、金丝雀滚动统计、预算账 | **证据**：漂移越界（默认 CUSUM，SPRT 不得并行）、失败模式聚类（**按全局 `RefusalCode` 的码 + `attributable_to` 维度聚类**，不是按契约分组——见下）、覆盖缺口、能力缺口、结晶候选、预算异常 | 门禁与升级触发的证据必须**可复算、可重放、零 LLM 噪声**——LLM 诊断不能充当证据 |
| **决策层（manager）** | **LLM（dev-only）** | 指标层证据 + 抽样轨迹 + 池现状 | **提案**：绑定变异 / 实例生长 / 契约扩展 / 结构结晶（**节点池增删全在此**） | "为什么失败、缺什么能力、该加什么节点"是语义归纳，正是 LLM 的长处；每回合一次，成本低 |

- **两层都不在图内**：不是节点、不进节点池、不占 per-task `B`、不写 `shared`/`slots`、执行期零干预。
  `can_delegate:true` 契约只用于图内 L2 委派，不得拿来实现监控或管理。
- **运行时机**：每个**回合结束后**（检查点回合另含 holdout 判分），读取**已冻结的只读记录**，
  **不读实时执行流**。决策层的 LLM 调用记外环预算，不占 per-task `B`。
- **manager 只是提案者，不是执行者**：它**不得直接写池 / 写账本**；节点添加一律走
  "证据 → 提案 → 门禁 → 双集门槛 → 采纳 → 可回滚"。
- **每条提案必须挂证据 id** + 预注册预期收益；**无证据提案直接拒**（禁时钟驱动生长）。manager 永不接触 holdout，
  提案文本过泄漏扫描。
- **两层分签**：指标层只产证据、manager 不能自造证据；manager 只产提案、指标层不能改提案——
  "自己诊断自己改"的自欺入口被结构性堵死。
- **理由**：① 运行时纯函数性不被观测者污染；② 外环成本不混进 per-task `cost_exec(G)`；
  ③ "做题者 ≠ 判卷者"在时间上分离——监控无法影响它正在评判的那一轮；④ 回放只需 events，不必重放观测者。

**触发条件（必须先有证据，禁时钟驱动生长）**

| 触发 | 证据 | 动作 |
|---|---|---|
| 能力缺口 | 某能力类在 ≥ N 个 dev 任务上失败，且图内重连无法修复 | 结构搜索（MCTS/EA）或新增节点 |
| 节点漂移 | 金丝雀集滚动统计超界（成功 / 延迟；**校准 ECE 仅对声明了 `confidence` 的契约**；检测默认 CUSUM **双侧**，SPRT 不得并行；`target` = 转正时的 pin 住基线，不用滚动均值） | **下降侧** ⇒ 隔离 / 重训 / 降级；**上升侧** ⇒ 强制重测金丝雀 + 重置基线（不隔离）。两者**必留痕** |
| 会话结晶 | 同一 `sub_sig` 子拓扑在 ≥ k 个 **dev 任务**上**任务级验收通过**（不是节点级 post 通过；`sub_sig` 定义见《契约与图》§二结构代际） | **结晶为单节点** |
| 覆盖缺口 | 课程某难度档的 `S_dev` 低于全档中位数减 `theta.cov_gap`，**且**该档失败任务的失败模式聚类集中在同一 `contract_id` 或"无合法契约可用"上 | 课程调度或节点合成 |

> **"覆盖缺口"必须可判（原表述"某难度档无可用节点"在闭集契约 + 兜底首节点不变量下永不成立）**：池不变量保证
> 任何任务都至少有一个合法首节点 ⇒ "无可用节点"是空条件。真实的覆盖缺口是**该难度档系统性做不出来**，
> 判据如上表；`theta.cov_gap` 住账本。这条与"能力缺口"的区别：能力缺口按**契约**定位（某能力类到处失败），
> 覆盖缺口按**难度档**定位（某档到处失败，可能是任务分布问题而非能力问题）——
> 故覆盖缺口的默认动作是**先调课程**，只有课程调整无效才升级为节点合成提案。

> **失败模式聚类必须跨契约可比（否则能力缺口证据没有来源）**：聚类维度 = `(RefusalCode, attributable_to)`，
> **不是 `contract_id`**。按契约分组只能回答"哪个契约差"，回答不了"缺什么能力"——
> 而后者才是契约扩展提案的依据。`attributable_to='graph'`（如 `capability_mismatch`）指向**编排选错了节点**，
> 应走"改提示词/改池统计"而非新增契约；只有 `attributable_to='node'` 且跨多个契约重复出现，才是**新能力**的证据。
> 这条区分决定提案方向，混用会把"编排问题"误诊成"能力缺失"并触发无谓的契约扩展。

**池生长 = 子图结晶**（**唯一使 `H` 下降**的生长方向；实例级生长只是不增 `H`）：把反复出现的稳定子拓扑提升为
单个节点，**外层**图复杂度同时下降 ⇒ 生长与 MDL 不冲突。
**注意 `H` 下降只在外层**：`composite` 内部照常执行、照常计费（见《契约与图》§一「结晶的收益边界」），
所以结晶换来的是**生成端**的简化（token 更短、搜索空间更小、`sig` 去重更强），不是执行端的省钱。
**结晶的净收益必须在软闸曲线上单独可见**：`fit` 的 `−μ·H` 项会因结晶下降而改善，
但若同期 `cost_exec` 与 `pass@1` 都没动，那只是**记账口径的改善**，报告须标注 `H_drop_only`，不得当能力提升宣传。

**世代与回合（缺这个，"跨世代曲线"无从测量）**

- **回合（round）** = 一段固定的 `dev` 批量（**每回合任务数为定数，住账本**）+ 一次采纳判定。
  **采纳判定要求 `new` 与 `incumbent` 在当轮同一 `dev` 批上共评**（配对检验的前提；代价是 dev 计算翻倍，
  但课程每回合换 dev 批，不共评则"同任务配对"不成立）。
  **dev 批的采样规则**：同一 `incumbent` 窗口内**按簇跨回合不重复**采样（窗口开始时确定性洗牌、按回合切不重叠批次），
  否则独立重采样下不同簇数增长太慢、累计 `n` 永远攒不够。
  **配对单位是独立簇**（任务池中"同一解法、仅标识符不同"的换名副本属同一簇），不是任务——
  同簇内的换名副本先聚合成簇级比例再配对；`n` 取簇数。簇的具体构成由 bench 生成规格定义。
  **`ROUND_B` 必须含共评的两份成本**（`Σ_i B_i` 是**当轮实际执行的任务次数**之和 = `new` 与 `incumbent` 各一遍），
  否则回合预算账系统性少一半。
- **采纳闸的累计窗口随 `incumbent` 重置（写死）**：配对非劣检验的样本量 `n` 是**跨回合累计**的，
  但每次采纳都会换掉 `incumbent` ⇒ 跨采纳累计等于把不同对比对象混进同一检验族。故：
  **窗口起点 = 当前 `incumbent` 生效的那一回合**；一旦写下 `add_ver`（采纳）或 `set_active`（回滚），
  **窗口清零、group-sequential 边界按新检验族重开**（新的最大回合数与 alpha-spending 计划重新登记）。
  推论：每回合 dev 批的簇数、`n` 下限、窗口长度上限**都是定数（住账本）** ⇒
  **同一 `incumbent` 下不可能首回合判定**，前若干回合一律记"未判定"（不采纳、不算失败）。
  这是刻意的节奏约束——绑定变异与权重变异**不受此限**
  （它们不写 `add_ver`、照常每回合迭代），只有会换 `incumbent` 的采纳判定受节奏约束。
  窗口长度上限 = **按族取最小** `min over 族(族簇数 / 每回合该族簇数)`（本注册 = `⌊160/25⌋ = 6` 回合，受 `dev-hard` 池约束）；用尽仍未判定 ⇒ 记"未判定并重开窗口"（换洗牌种子、重新登记边界），
  **不得**降 `n` 下限或抬 `δ` 强行判定——改 `δ` 只能走登记提案。
  报告必须标注每次判定的**窗口起止回合与累计 n**，否则读者无法判断该结论用了多少信息。
- **升级触发按"已判定回合"计**：连续**若干个已判定回合**无 pass@1_dev 严格提升才触发升级（个数住账本）；
  "未判定"回合不计入停滞计数（否则等待样本量本身会被读成停滞、白白触发升级）。
- **holdout 改为注册检查点制**：每**固定间隔**回合判分一次（间隔住账本）+ 结论回合判分（冻结模型前向），
  **不参与任何搜索 / 蒸馏**；所有检查点判定用 BH-FDR 校正，判分次数入账。非检查点回合只出 `S_dev`，
  不写 holdout 结论（防反复偷看同一测速仪）。
  **检查点与采纳判定可能不对齐**（检查点间隔与最快可判定回合数不同，两者取值住账本）：口径是
  **只有落在检查点回合的采纳判定才加 holdout 非降条款**；非检查点回合的采纳只过 dev 硬闸。
  代价（明写）：连续两次非检查点采纳之间，holdout 无监督 ⇒ 最多两代之后才发现 holdout 退步。
  补偿：检查点回合的 holdout 非降是**对当前 active 版本**判的，退步即触发 `set_active` 回滚到上一个
  **通过检查点**的 `ver`（不是回滚一代）；该"最近安全版本"指针 pin 进 manifest。
- **世代号 = 回合号**；每次采纳写一条 `add_ver`，回滚写一条 `set_active`（指回旧 `ver`）。
  **未采纳的回合不写 `add_ver` ⇒ 世代号会跳号**（回合 5、7 采纳则世代 = 5、7，无 6）。跳号是正常的，
  曲线横轴一律用**回合号**，不用"第几代"。
- 每回合预算 `ROUND_B`（= 当轮实际执行任务的 cap 之和 + `search_cost`；运行时控制层 decode 已含在各任务 `B` 内，
  **不重复计入**；holdout 判分成本单列 `holdout_cost`，不计入 `ROUND_B`）随结果入账；
  曲线 = `(回合, S_dev, 检查点 S_holdout, 成本)`。

**适应度与接受闸（口径）**

适应度 = `pass@1_dev` 减去成本惩罚与结构复杂度惩罚（`cost_exec` 只含图执行的确定性三维 `{calls, tokens, tool_calls}`、
已归一化，**不含 `walltime`**；结构复杂度以人工固定图臂的节点数为基准，`|V_seed|` pin 进 manifest）；
离线搜索成本是回合级 `search_cost`，进 `ROUND_B` 单列报告、**不进 `cost_exec`**。**搜索进运行时档**下，搜索成本按任务数
**等额** pro-rata 计入**对外四维 `used_ext`**（`search_cost_d / n_eval_tasks`，未评测任务不分摊；所有臂共用），仍不进 `cost_exec`。
具体公式与默认系数住账本。

**版本级 `fit` 的聚合口径（写死，否则"比较 fit"指代不明）**：单图 `fit(G)` 只对一次执行有意义；
**接受闸比较的是版本级 `fit`** = 当轮 dev 批上 `fit(G_i)` 的**任务等权均值**（`G_i` = 该版本在任务 `i` 上现场生成的图）。
`incomplete` 任务按 `pass@1=0` 与**实际消耗**的 `cost_exec` 计入（不按 cap 计满，否则提前停会被双重惩罚）；
`H` 取该任务实际产出图的 `H`，`incomplete` 且未产出闭合图者取该轮 dev 批 `H` 的中位数占位并标记
（记 `fit_H_imputed`，占比超过诊断线则该轮 `fit` 只作诊断不进软闸——插补占比过高时曲线已不可信）。

接受闸分硬/软（避免进化停滞在"降成本刷分"而非提能力）：

- **硬闸**（不满足即**不采纳**、本轮提案作废，不回滚已采纳历史）：dev 配对非劣检验成立——单侧 CI 下限 ≥ −δ，
  且对累计样本量与**实测 CI 半宽**另有前置约束（否则本回合只记"未判定"：不采纳、不算失败，防"CI 半宽过大时硬闸
  退化为'必须显著更好'"）；检查点回合另加 `S_holdout(new) ≥ S_holdout(incumbent) − ε`（holdout 点估计非降）。
  **重复检验控制**：采纳闸在**同一 `incumbent` 的窗口内**每回合判一次，属**重复检验**，必须用**预注册
  group-sequential**（alpha-spending，如 O'Brien-Fleming）控制整体 type-I；**该窗口的最大回合数、每轮名义 α、
  累计 n 计划在窗口开始时登记，窗口内禁事后改边界或偷看后延长**；窗口随 `incumbent` 变更而重置并重新登记。
- **软闸**（入曲线、不阻断采纳）：`fit` 改进超过 `margin` 才记入；cost / H 的改进**只记账**。
- **同回合多条提案的处置（写死，否则"采纳"指代不明）**：manager 一回合可产多条提案，但**采纳判定的单位是
  "候选版本 `new`"**，不是单条提案。口径：本回合通过生长额度执法的全部提案**打包成一个 `new`**，
  一起过硬闸、一起 `add_ver` 或一起作废。**不做逐提案的单独判定**——生长额度（契约级 + 实例级，取值住账本）
  限定了每回合的变更项数上限，逐项判定需要成倍的 dev 预算且引入多重比较；
  代价是"打包内某项有害、某项有益"时会被一起拒，此时 manager 下回合按 `evidence_id` 保留的证据**拆开重提**
  （提案被拒不销毁证据，这条已写死）。`accept` entry 必须列出**打包内的全部 `proposal_id`**。

> `H` 用 `(|V|+|E|)/|V_seed|` 而不是"度数分布熵"：它可执行、与 MDL 惩罚同源，且**子图结晶会使它下降**
> （子图折叠成 1 节点 ⇒ `|V|` 减少），正是"生长不增熵"要的方向。
> `pass@1_dev` 用全过口径；`test_pass_fraction` 只作诊断列，**不进接受闸**（防部分通过刷分）。
> **硬/软闸拆分的理由**：硬闸已保证 pass@1_dev **非劣（允许 ≤ δ 的统计噪声内下降）**；fit 的 cost/H 改进
> **只作软闸**——否则 pass@1_dev 持平时仅靠 cost 下降过 margin，进化偏向"越练越便宜"而非"越练越能"，且因仍"达标"
> 而不触发升级。故升级触发改挂 **pass@1_dev 严格提升**：连续若干回合无严格提升 ⇒ 上升一档（回合数阈值住账本），
> 不再以 fit 无提升为触发（防成本优化永久规避升级）。

**课程模型的可执行验收**：课程 = 按难度向量的采样分布策略。**默认 = 对冻结 dev 池均匀重采样**（每回合任务数住账本）；
非均匀调度只在有覆盖缺口证据时偏离均匀，并登记预期。难度是**向量**、无全序，故判据不是"单调"，
而是**分档趋势诊断**：按难度向量分桶（如难度范数分位）算各档 `S_dev` 与其 CI，用 Spearman / 单调回归检验
"档位升 → 成功率不升"的趋势；趋势异常记为**诊断项**（进报告、触发课程侧复查），**不作硬门禁**——
有限样本与真 LLM 方差下严格单调不可满足。

**"模型自治"的红线**：控制层**不得在运行时自改自身结构**——那只能走「提案 → 门禁 → 双集门槛 → 采纳 → 可回滚」。
运行时自改 = 没人记录 ⇒ 可回退当场失效。

**提案的 owner（角色分离）**：**指标层只产证据、不提案**；提案由**决策层 manager（LLM）**产出
（manager 不是图内执行体）。两层用 `evidence_id` 接口连接：manager 的每条提案必须引用指标层证据。
**提案四类，映射变异通道三分**：**绑定变异**（绑定通道，不占生长额度）；**实例生长**、**契约扩展**（生长通道的实例级 / 契约级，占额度）；
**结构结晶**（契约扩展的特例：契约扩展 + 新实例，且 `H` 下降，占额度）。**权重变异不是提案**（走蒸馏 / 微调）。
每回合生长额度**分契约级与实例级两个上限（取值住账本）**（超额拒、证据保留）；绑定变异不占额度。

## 二、账本与版本

```
Entry = { seq, prev, op, args, argsHash, by, ref?, at }     // 链式哈希；argsHash 进链
                                                            // entryHash = H({at, seq, prev, op, argsHash, by, ref})

// defs 链（版本声明；进 worldRev，除 audit）
op ∈ { declare, put, add_ver, set_active, quarantine, accept, snapshot, audit }

// events 轨迹（运行期；不进 worldRev、不进版本）
event_op ∈ { publish, memo, note }
```

**八个 defs op 的语义**：

| op | args | 说明 |
|---|---|---|
| `declare` | `{ kind, body }` | **append-only 声明的唯一入口**。`kind ∈ { capability, type, shared_ref, role, refusal_code, motif, node }`。同内容重复声明幂等（`dup`） |
| `put` | `{ slot, def_ref }` | **可版本化数据的唯一入口**。`slot ∈ { binding.prompt, binding.model, binding.decoding, binding.tools, binding.context_policy, binding.retry_policy, binding.weights, binding.subgraph, threshold }` |
| `add_ver` | `{ target, ver, payload }` | 世代追加（控制层权重世代、池版本）。必与 `accept` 成对 |
| `set_active` | `{ target, ver }` | 切 active 版本 = **唯一的回退机制**（不设 `rollback`） |
| `quarantine` | `{ node_id, reason, evidence_id }` | 实例隔离/降级；是池状态变更故在 defs 链、要进 `worldRev`、可 `set_active` 回退 |
| `accept` | `{ round, proposal_ids[], verdict, stats, evidence_ids[] }` | 回合级采纳判定（采纳与拒绝都写）。缺 `accept` 的 `add_ver` 非法 |
| `snapshot` | `{ world_rev }` | run 级 manifest 版本快照，供重放与只读冻结 |
| `audit` | `{ call_id, attempt_index, variant_index, port, method, request_bytes_ref, response_bytes_ref, used{} }` | 效果审计：每次实际发出的 `EffRequest` 一条，被写请求 `ref` 指向。**不进 `worldRev`**（另立 `auditRev`） |

**为什么从 19 个合并到 8 个**：原表里六个 `declare_*` 与三个 `put_*` 全是"追加一条带类型的声明 / 更新一个 pin"，
形状完全相同、只是 `kind`/`slot` 不同 ⇒ 九个 op 塌成两个，`kind`/`slot` 进 `args` 并**进索引**（报表按 kind 分组）。
收益不只是数量：① **加新声明类型不再需要加 op**（加 `refusal_code`、`motif` 这两类时原表就得改 op 枚举 —— 而 op 枚举
改动等于账本格式变更）；② 与内核迁移面 8 原语（内核 op 共 10 种，去掉 `batch`/`note` 两个非迁移面对手）的形状偏离大幅缩小，`op` 语义映射层从"19→8 多对一"变成"8→8 近一对一"，
迁内核的成本从重写降为改名；③ `argsHash` 口径统一（一份 `args` 一次规范化），不必逐 op 分别定义。
代价：账本可读性略降（需看 `args.kind`），用报表按 kind 分组展示补偿。

**三项原本缺失、现由 `declare`/`audit` 覆盖的机制**（补前它们无落点）：
`audit`（效果审计原无承载 op ⇒ "每次 EffRequest 配一条审计 def"落不下去）、
`declare{kind:'motif'}`（motif 进 `action_head` 动作空间 ⇒ 改 arch dims，必须版本化声明而非可重算缓存）、
`declare{kind:'role'}` 与 `declare{kind:'refusal_code'}`（原文称"进 append-only 表"却无声明入口）。

- **回退不是独立 op**：回滚 = `set_active` 指回旧 `ver`，不设 `rollback`，以免出现两套回退机制。
- `declare{kind:'capability'}` 只在**新增契约**时出现（契约 append-only）；已有契约不得再声明。
  `kind ∈ {type, shared_ref, role, refusal_code}` 同理：这四张表都是 append-only 枚举，加项即一条 `declare`。
- `declare{kind:'node'}` = 新 `NodeDecl` 实例声明（开集）；**绑定变异不走它**，走 `put(slot='binding.*')` +
  `set_active` 切 pin 的 def 版本（换 pin 不换 `node_id`，这正是"节点身份不变、绑定换代"的落点）。
- **`put(slot='binding.*')` 覆盖全部八个绑定槽**：`prompt` / `model` / `decoding` / `tools` /
  `context_policy` / `retry_policy` / `weights` / `subgraph`。原表只有 `put_prompt` 与 `put_policy`，
  **模型 / 解码 / 工具 / weights 无 op 可落** ⇒ "换模型""换 `temperature`"这类最常用的绑定变异无法入账。
  **`weights` 槽的两种归属（不可混）**：`trainable` **节点自身**权重走 `put(slot='binding.weights')`
  （绑定变异，不占生长额度）；**控制层三模型权重走 `add_ver` / `set_active`**（世代通道，不是绑定）。
- `put(slot='threshold')` = **阈值参数**以数据身份入库；**判定式结构不在此 op**——改判定式 =
  `declare{kind:'capability'}`（新 `contract_id`）。与"判据改动只影响下一轮"的回合锚配合。
- **结晶不设专用 op**：结晶 = `declare{kind:'capability'}` → `declare{kind:'node'}`（`composite` 实例）→
  `declare{kind:'motif'}` → `add_ver` + `accept`。**来源子图与 `sub_sig` 记在 `declare{kind:'node'}` 的
  `body.crystallized_from = { sub_sig, source_graph_sig, evidence_id }`**——这样"独立新增的契约"与
  "结晶产生的契约"依然可区分（`«结晶使 H 下降»` 仍可审计），但不需要第 19 个 op。
  回滚一次结晶 = 一条 `set_active` 指回 arch bump 前的 `ver`（契约与实例仍在链上，只是不再 active）。
- `quarantine` = 实例隔离/降级。**必须在 defs 链**：它是**池状态变更**，要进 `worldRev`、要能 `set_active`
  回退；放进 events 会导致降级不进版本、不可回滚。
- `accept` = **回合级采纳判定**（记两端分数、门禁结论、打包内全部 `proposal_id` 与 `evidence_id`；采纳与拒绝都写）；
  `add_ver` 只在实际采纳时追加版本。二者成对，缺 `accept` 的 `add_ver` 非法。
- `snapshot` = **run 级 manifest 版本快照**：把本轮 `world/manifest/fixture` 的规范哈希钉进账本，
  供事后重放与只读冻结。
- `audit` = 效果审计 def（详见下文「效果审计」）。**在 defs 链但不进 `worldRev`**（写死，否则每次 LLM 调用都改世界摘要）：
  它是**内容寻址的叶子**，被 `ref` 指向、不被 `pins` 遍历、不改任何 active 版本。
  `worldRev = H({defs 键集, ids 摘要})` 的 **`defs 键集` 排除 `audit` 产生的键**（另立 `auditRev` 摘要）。
  不排除的后果：`worldRev` 每次调用都变 ⇒ "同一池版本"不再可比、`snapshot` 锚不住、pin 全废。
- **events 轨迹三个 op**：`publish`（共享上下文的受控发布，必须记 `by`/`ref`，便于审计与撤销）、
  `memo`（幂等短路命中记录，让"未重复计费"可证）、`note`（留痕）。
  **《契约与图》§2.2 的一等事件**（`chosen_instance` / `edge_choice` / `wasted_step` / …）全部归 events 轨迹；
  `publish` / `memo` / `note` 三个**既是 op 也是事件类型**（同名不同层：op 是账本条目，事件是轨迹条目，以 `run_id` join）。
- **两条日志以 `run_id` join**：重放读 events，版本只读 defs，避免运行期事件污染版本链。
- **真源 = defs 链**；版本目录是派生。`worldRev` 同构 = `H({defs 键集（排除 audit）, ids 摘要})`，**摘要不含履历**。
- **pin 全员**：池版本、能力类表、图文法版本、控制层权重、提示词、阈值常量、bench 清单、scorer、
  **必读上下文量的基准（决定 `f_ctx` 难度维与"超窗"类任务是否成立 ⇒ 换模型必须重算）**、
  **搜索规模（每任务展开次数 / 每回合搜索任务数；决定 `search_cost`，改它们等于改预算口径）**、
  **运行时版本（进程代码 / 依赖锁文件 / 沙箱镜像）**、**回合锚**（本轮判据冻结：改判据只影响下一轮）。
- **回退**：`set_active` 指回旧世代 = 一条追加；**不删任何历史**。
- **效果审计**：**每次实际发出的 `EffRequest` 配对一条 `audit` def**（含 LLM 调用、`exec`、文件写；**重试的每次尝试各一条**），
  被写请求 `ref` 指向；带 `call_id`（逻辑调用）+ `attempt_index` + `variant_index`，多次尝试由 `call_id` join；
  **落盘字节按每次尝试保真**（禁语义往返重写）。`audit` 的键不进 `worldRev`（见上文）。
  **每条 `audit` 同时产出对应的成本事件**（《契约与图》§2.2 成本事件流）——`audit` 是成本事件的**唯一合法来源**，
  故"有花费但无审计"与"有审计但无花费"都是记账 bug，**预算账门禁逐条 join 校验**。
  **审计存储量必须封顶**：审计字节 ∝ 总尝试次数，真 LLM 下增长很快（按本实验约 100 万次调用估，正文字节达 TB 量级）。
  口径：`audit` 的 def 只存 **内容哈希 + 四维用量 + 元数据**，请求/响应字节落 `runs/<run_id>/audit/` 的 blob
  （内容寻址、随 run 冻结只读）；账本里**不内联** LLM 请求/响应正文。回灌重放读 blob，`verify` 校验哈希一致。
  **blob 保留策略（住账本）**：被写进结论的 run 永久保留；其余 run 的 blob 只保留最近若干回合
  （保留回合数住账本），过期只删 blob、**保留 `audit` def**（哈希与用量仍在链上，故成本账与漂移统计不受影响，
  只是这些 run 不再可逐字节回灌重放，记 `note`）。
- **可重放**：`(任务, 池版本, 权重, seed, runtime_pin)` + 审计回灌下逐字节等价；真 LLM 的不可复现由**回灌**表达，
  不由重跑表达。
- **回滚必须可验证**：回滚后重跑同一任务，**在回灌条件下**必须逐字节复现旧结果；
  回灌缺失时不得声称"回滚成功"，只能记"回滚未验证"。
