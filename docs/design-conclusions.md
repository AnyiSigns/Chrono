# 设计讨论结论（2026-09-16 长谈的收束）

> 本文记录一次设计长谈的最终共识，作为 kernel.md 之外的口径参考。带 [推测] 的是讨论中提出的方向（未入 kernel.md）；其余是对文档口径的澄清。

## 0. 纪律

- **内核只有一种东西：数据**。源码、动作、逻辑、配置——全是数据的不同格式。回退按对应格式/对应目录各自还原，逐条记录回退（git 式：一条记录 = 动作 + 对应版本）。区分"代码/内容/插件"是产品层的语义，内核无感。
- **不猜**：文档里写的才说；文档没写的，明确说"没有/未定义"，不替文档发挥。
- **名词/动词**：动词（装载/审核/训练/执行）不进内核；内核只记账。
- **内核承诺**：改坏了能退、非法进不来、历史改不掉。**不承诺"合理"**——"合理"永远是上层的事。

## 1. 世界与执行的分层

| 层 | 存什么 | 干什么 |
|---|---|---|
| 内核 | 记录（动作产物）+ 声明 + 逻辑数据+插件源码数据（快照，插件的源码以数据形式出入内核） | 重放、机械校验、快照、回滚。纯函数，无 IO |
| 宿主 | 运行时环境、构建产物缓存、持久化（文件/SQLite 皆可） | 读世界声明 → spawn 进程 → 按协议通信；提供端口实现 |
| 执行件（插件） | —（是进程，不"存"） | 独立进程，语言无关，走统一协议（如 JSON-RPC） |

- 内核 = 事件溯源：**进内核的只是一个记录**。重放记录得到状态，回退 = 指回旧记录。
- 内核不持久化；落盘是宿主的活（kernel.md:130）。
- **M2 定案：保留**（2026-09-16 实现验收后转正，原 [推测]）。降级的是逻辑的"一等插件资格"，不是"机器解释逻辑的资格"——要被内核机械执行的逻辑（判定标准等）必须写成 term；可派生的仍以宏住在数据里（kernel.md §12.1）。machine.ts 已实现并全绿，"砍到只剩记录+重放+校验+快照"的分支正式关闭。

## 2. 插件（执行件）的形态

- **插件 = 执行件（进程）**。逻辑不再是一等"插件"——要么内嵌进执行件，要么降级为动作记录。
- 一个插件 = 一个目录 = 一个身份，可含**多份执行件 + 多份逻辑数据**。内核视角：一个 `id`，每代 `payload` 是一份清单式 def，成员（执行件源码 def、term def）按哈希引用——装配由宿主读声明完成，内核只记账，不认识"组合"这个词。
- 代码怎么存：**世界存源码（文本，content-addressed），宿主按哈希构建成进程**。二进制不进世界（平台相关）。源码 def 与任何数据**完全同路**：`put` / `batch` 进 `defs`，键 = `H(Def)`；内核不感知哪个哈希是源码（清单里列的键在 body 内部，引用完整性归上层工具，kernel.md §11.2②）。
- 只有二进制的包：世界存**声明 + 哈希 + 平台**，本体归宿主存储/包注册表。
- 宿主挂载的是**协议**，不是语言。Rust/Node/Python 只要实现协议都能当执行件。

## 3. 能力与门

- 出世界必须走门（`eff` → 端口实现）。端口按**能力类**切（fs/model/net/exec…），不按功能切。
- **能力必可收回**（降权/卸载/下架）——收不回的授权叫后门；包括第一方（第一方无特权，可测：卸载全部第一方仍全绿）。
- 端口是"协议（数据）+ 实现（宿主代码）"；实现可换，调用方不改。

## 4. 变更与生效

- 改数据（参数/模板/配置）→ 热生效，不重启。
- 改代码 → 宿主重建 + 重启进程。
- 改协议（方法/caps）→ 更新声明（数据）+ 重启。
- **宿主代码永不因插件改动而动**：宿主只做读声明、spawn、通信三件事。
- **热装载归宿主**，按改动类型分两条路：改**数据**（term/参数/配置）→ 宿主感知链头推进、按新哈希重取 def、换缓存即热生效，进程不动（内核侧本就每次 `eval` 读当前 `defs`，无重装载概念）；改**代码** → 按哈希查构建缓存（命中免编译）→ spawn 新版本进程 → 旧进程排空（drain）退出。内核只记"当前生效是哪一代"（`add_gen` / `set_active`），从不过问进程——装载时机、排空策略、灰度比例都是宿主 manifest 参数（同 §10.7 快照节拍的口径）。

## 5. 命名收敛

- "内容插件 / 数据插件"不准确 → 叫**逻辑插件**（如果逻辑是数据），或直接降级为动作记录。
- "端口实现"不是插件种类，是**门 / 执行件**。
- "数据包"不当一等公民——只有"首次注入（bootstrap）"这个动作，不配一个目录。

## 6. 文档事实核对（长谈中确认过）

- `kernel.md` **不含** 训练器/搜索算法/遗传编程——那些是讨论中的推测，不是文档。
- 内核四机制：M1 value / M2 machine / M3 journal / M4 commit。审核（正当性）在上层。
- `kernel.md:1177`：非测试代码禁出现 criteria/approve/level/review/policy（内核不含审核概念）。
